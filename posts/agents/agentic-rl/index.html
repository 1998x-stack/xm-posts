Understanding Agentic Reinforcement Learning

从单轮回答优化到多轮环境交互：用 POMDP、轨迹级回报、信用分配与长程课程学习，理解语言模型如何学会持续行动。

01 / THE PROBLEM

为什么“会调用工具”不等于“会完成任务”？

一个智能体可能能正确生成 search()，也能读懂搜索结果，却仍然无法完成一个需要多次查询、比较、验证和修正的任务。真正困难的不是生成一次正确答案，而是在每次行动之后，根据环境反馈，决定下一步应该做什么。

设想任务：“查出项目 Orion 属于哪个团队，再找出该团队负责人，并提交姓名。”模型必须先搜索项目归属，再查询团队负责人，最后验证并提交答案。若第一次搜索结果不完整，策略还需要换关键词；若工具返回错误，则要恢复，而不是机械地重复调用。

核心问题发生了变化： 单轮 LLM-RL 主要问“这次回答是否好”；Agentic RL 则问“这一连串决策是否让智能体在真实或模拟环境中完成了目标，而且代价、风险和约束是否可接受”。

这并不意味着所有 Agent 都必须使用强化学习。Prompting、SFT、工具协议和工作流编排可以构建一个能运行的 Agent；Agentic RL 的区别在于：利用环境交互产生的经验和奖励，更新策略本身。它是一种训练范式，不是某一个固定算法或某个 Agent 框架。

02 / FORMALIZATION

从单步 MDP 到部分可观测的长程决策

许多 LLM 后训练任务可以被简化为一次条件生成：给定 prompt，模型采样 completion，再由奖励模型或验证器评分。为了分析这种设定，可以把它视为一个退化的单步决策过程。2026 年的 Agentic RL 综述把这一范式与时间跨度更长、环境状态部分可见的 POMDP 作了明确对比。Zhang et al., TMLR 2026。

单轮生成

输入 prompt，模型输出一段 completion，最后得到一个分数。环境通常不在中途改变下一步输入。

one promptone completionone reward

多轮交互

每个动作都会触发环境转移。工具结果、页面变化、代码执行结果或模拟器状态，都会成为下一步决策的条件。

historytool callsobservations

用 POMDP 的记号表示：环境具有真实状态 sₜ，但智能体只能收到观察 oₜ。策略依赖交互历史，而不是假设自己知道完整世界状态：

ht=(o0,a0,o1,…,ot) at∼πθ(·|ht) st+1∼P(·|st,at),ot+1∼O(·|st+1)
符号说明：P 是环境状态转移分布，O 是观察分布，πθ 是参数为 θ 的策略。真实环境状态可以包含网页 DOM、文件系统或游戏内部状态，而模型只看到被接口暴露的观察。

一条轨迹可以写成 τ = (o₀, a₀, o₁, a₁, …, oT)。若每步奖励为 rₜ，折扣因子为 γ，则总回报为：

R(τ)=∑t=0Tγtrt

常见的正则化目标还会约束新策略不要偏离参考策略太远：

J(θ)=𝔼x,τ∼πθ[R(τ)]−βDKL(πθ‖πref)
这是常见的正则化写法，不是所有 Agentic RL 系统都采用完全相同的目标。奖励可能是终局成功、逐步约束、人工偏好或它们的组合。

最关键的建模区别：工具调用是策略动作，工具返回是环境观察。 例如模型生成 search("Orion") 是动作；搜索引擎返回的网页摘要是观察。二者来源不同，训练时的 token mask、log-probability 和信用分配必须区分。

03 / CONCEPTUAL BOUNDARY

ReAct 不等于 Agentic RL：一个是交互结构，一个是学习范式

ReAct（Yao et al., 2023）把 Thought、Action、Observation 组织成交替序列。它回答的是“推理和行动如何交织”。原始工作主要通过提示冻结的语言模型，让模型生成思考、执行动作并读取环境反馈。

Agentic RL 则进一步问：如果我们把这些交互轨迹收集起来，根据任务成败计算奖励，并用策略梯度更新模型，模型能否逐渐学会更好的行动顺序、工具选择、恢复策略和长程规划？

维度ReActAgentic RL
核心问题如何交替思考、行动和观察？如何从交互经验中优化决策策略？
是否更新参数原始方法不要求更新模型参数通常通过 RL 更新策略参数
学习信号提示示例、上下文、工具反馈环境奖励、验证器、偏好或塑形信号
主要优化对象一条推理—行动轨迹的组织方式轨迹分布与长期任务回报
关系ReAct 可以作为 Agentic RL 的轨迹协议或行为模板，但有 ReAct 不代表已经进行了强化学习。
避免一个常见概念混淆： 一个系统即使使用了工具、Memory、Planner 和多 Agent，也不自动属于 Agentic RL。只有当环境交互经验进入学习目标，并对策略或其可训练组件产生更新，才进入 RL 训练范畴。
04 / SYSTEM ARCHITECTURE

一个完整的 Agentic RL 训练系统由什么组成？

不要先从 PPO 或 GRPO 开始。先把系统拆成三个边界清晰的模块：Agent 负责生成动作，Environment 负责执行并返回观察，Trainer 负责从轨迹计算学习信号并更新策略。AgentGym-RL 的核心设计正是模块化、解耦的 Agent / Environment / Training 架构。AgentGym-RL, ICLR 2026。

Agent / Policy

  • 将历史组织成上下文
  • 生成自然语言或结构化动作
  • 管理工具调用与失败恢复
  • 控制结束条件和预算

Environment

  • 提供任务状态和工具接口
  • 执行动作并返回观察
  • 维护权限、约束和终止条件
  • 计算可验证的任务结果

Trajectory Collector

  • 记录状态、动作、观察、奖励
  • 记录策略版本与 token mask
  • 处理超时、异常和部分轨迹
  • 管理 rollout 数据新鲜度

Trainer / Learner

  • 估计回报与优势
  • 应用 PPO / GRPO 等目标
  • 限制策略更新幅度
  • 评估并决定下一轮课程

真实系统还需要任务分布管理、模型推理服务、日志追踪、环境隔离、超时控制、数据版本、评估器和安全策略。Agentic RL 不只是“把一个 GRPO loss 接到 Agent 上”；它首先是一个跨模型、环境和训练基础设施的闭环系统。

05 / CREDIT ASSIGNMENT

为什么 Agentic RL 的难点是信用分配？

假设一个 Agent 用三步完成任务：搜索项目、查询负责人、提交答案。最终结果正确时，环境可能只给整条轨迹一个 +1；但到底是哪一步做对了？第一步搜索到了关键实体，第二步选对查询方式，还是第三步没有把名字抄错？如果结果失败，究竟应该惩罚哪一个决策？

策略梯度的核心思想是：增加那些带来更高回报的动作概率。用优势估计 Âₜ 衡量动作相对于基线的好坏，可以写成：

∇θJ≈𝔼τ[∑t=0TA^t∇θlogπθ(at|ht)]

如果奖励只在最后一步出现，最朴素的 Monte Carlo 回报会把这个结果向前传播：

Gt=∑k=tTγk−trk

在价值函数可用时，GAE 会对多个时间尺度的 TD 残差做指数加权：

A^t=∑l=0T−t−1(γλ)lδt+l

但在 LLM Agent 中，轨迹里同时存在模型生成的推理 token、工具调用 token 和环境返回 token。不能把它们一概当成策略动作：环境返回不是当前策略采样出来的 action。训练实现必须正确记录哪些 token 参与 log-probability 和 policy loss，哪些只是上下文或环境观察。

研究前沿：观察本身也可能携带监督。 ACL 2026 的 SOAR 研究指出，标准 Agentic RL 通常把环境观察 token 排除在策略优化之外；SOAR 则提出一种与前序动作不确定性关联的 observation-aligned advantage，试图让模型更好地学习动作后果。这是特定方法的扩展，不是所有 Agentic RL 的默认做法。SOAR, ACL 2026, §3。
06 / ALGORITHM DESIGN

PPO、GRPO、REINFORCE++：算法没有消失，但任务结构变了

Agentic RL 不是一个取代 PPO / GRPO 的新优化器。它把这些算法放进更复杂的多轮轨迹、环境奖励和异步数据管线中。不同算法解决的是学习更新问题；框架解决的是环境连接、轨迹收集和训练调度问题。

方法核心机制在 Agentic RL 中的作用主要注意点
PPOClipped policy objective + value baseline限制策略更新幅度，支持价值估计长轨迹的价值估计、样本成本和 token mask
GRPO同一任务采样多个候选轨迹，用组内奖励相对值构造优势适合可比较的任务级奖励，不一定需要独立 critic奖励方差、组内全成功/全失败、轨迹长度偏差
REINFORCE++基于回报的策略梯度与归一化作为简化的 on-policy 更新基线高方差与信用分配粒度
Hierarchical RL把复杂任务拆成多个决策单元，分配局部信用处理多次 LLM 调用、子任务与多 Agent 工作流分解规则可能引入偏差

例如 GRPO 的组内相对优势可用下式表达：

A^i=Ri−R¯σR+ε
这里的 Rᵢ 是同一任务下第 i 条 rollout 的回报；不同实现对长度归一化、token mask、KL 和优势计算细节可能不同。

Agent Lightning 提供一个有代表性的系统设计：把 Agent 执行与 RL 训练解耦，并用层次化信用分配模块将多步轨迹拆成可训练的 transition，再接入 PPO、GRPO 等算法。它的重点是“让已有 Agent 更容易接入训练”，而不是声称一种全新的通用奖励函数。Agent Lightning, 2025。

区分三层： Agentic RL 是训练问题设定；PPO / GRPO 是优化算法；AgentGym-RL / Tunix / Agent Lightning 是环境与训练系统。把三者混为一谈，会让架构设计和实验对比失去意义。
07 / LONG-HORIZON LEARNING

为什么不能一开始就训练 30 步甚至 100 步的 Agent？

长程交互会放大早期错误：一个错误的工具选择可能改变后续可见状态；错误观察又会影响下一轮计划；最终奖励距离最初动作很远，信用分配和探索都变得更难。AgentGym-RL 的 ScalingInter-RL 采用渐进式 horizon scaling：先训练较短交互，再逐步增加允许的交互轮数。

AgentGym-RL 在 ICLR 2026 论文中展示了跨 BabyAI、TextCraft、SciWorld、WebArena 和 Deep Search 等环境的结果，并报告其 7B 模型在所测 27 项任务中具有竞争力。论文还比较了不同最大交互轮数下的训练动态，指出固定长 horizon 可能出现训练不稳定或性能退化。AgentGym-RL, Figure 4–8, §4–6。

这里有一个容易忽略的工程事实：交互轮数不是越多越好。增加 horizon 会增加模型调用、工具等待、上下文长度、错误累积和样本成本。训练目标应是“学会在需要时进行足够多的交互”，而不是无条件地把每个任务拉长。

08 / ONLINE CURRICULUM

让训练任务也能随失败而进化

长程 Agent 不仅需要学会解题，还需要持续获得合适难度的任务。若训练数据只是一组固定 prompt，策略可能很快记住狭窄的解决模式；若环境过难，奖励又可能长期为零，学习信号不足。

WebRL（ICLR 2025）采用 self-evolving online curriculum：从失败尝试中生成新任务，结合 outcome-supervised reward model 和在线 RL 策略，缓解任务稀缺、奖励稀疏和策略分布漂移。论文报告 Llama-3.1-8B 在 WebArena-Lite 上从 4.8% 提升到 42.4% success rate；这是论文特定 benchmark 和训练设置下的结果，不应被理解为所有网页 Agent 的通用提升幅度。

2026 年的 Long-Horizon Tool-Using Agents 研究（Findings of EMNLP 2026）进一步从 reward shaping、model scaling、data composition、algorithm selection 和 environmental stability 五个维度研究训练配方，并指出数据难度混合与环境稳定性会显著影响训练表现。

课程设计的闭环： 任务采样 → Agent 尝试 → 识别失败类型 → 生成或选择下一批任务 → 再训练。关键不是让任务越来越难，而是让数据分布持续提供“模型能探索、又能区分好坏策略”的学习信号。
09 / TRAINING SYSTEMS

为什么 Agentic RL 会让 GPU / TPU 等待工具？

普通语言模型训练时，主要成本是张量计算；Agentic RL 的 rollout 还要等待浏览器、搜索 API、数据库、代码执行器或模拟器。模型可能生成几百个 token 后暂停数秒等待工具返回。如果训练架构是同步批处理，一个慢轨迹就可能拖住整批 worker。

Google Developers 在 2026 年 7 月的 Tunix 工程文章中介绍了异步 rollout orchestrator、解耦式 producer-consumer pipeline 和动态轨迹组批：一个 Agent 等待工具时，推理引擎可以继续处理其他轨迹。Scaling Agentic RL with Tunix, 2026-07-21。

2026 年 11 月的 Gemma 4 + Tunix 示例把完整链路拆成四个部分：Task Environment、Tool / Chat Template Parser、Conversation Agent、Trajectory Collector + Agentic GRPO Learner。一个 6×6 Plane Strike 小游戏中，Gemma 4 E2B 的 held-out board win rate 从初始 9.4% 提升到 100 个训练 step 后的 95%，平均游戏步数也从约 22.44 降到约 16。这个结果来自特定小型游戏、模型、硬件和训练配置，不能外推为通用 Agent benchmark。Google Developers, 2026-11-19。

工程上至少要监控六类指标

  1. Rollout latency：单条轨迹和每轮工具调用耗时。
  2. Environment wait：等待工具 / 环境的时间占比。
  3. Queue depth：待训练轨迹数量与分布。
  4. Policy lag：轨迹采样时策略版本与当前 learner 版本差距。
  5. Token accounting：prompt、生成、观察和工具返回 token 数。
  6. Task efficiency：成功率之外的调用次数、总耗时、成本和无效重复率。

因此，本知识库把 Agentic RL 放在 Agents 下的独立专题，并通过阅读路径连接 GAE、PPO、GRPO、ReAct 和 SWE-agent。它既保留强化学习算法的先修关系，也不把工具交互问题压扁成单一的训练算法问题。

12 / EXECUTABLE TOY ENVIRONMENT

用最小 Python 环境把状态转移写出来

玩具环境的目的不是复现某个 Agentic RL 框架，而是把一个容易被 prompt 掩盖的事实写清楚：每个工具调用都会改变可见状态；动作是否合法、是否重复、任务何时结束，都由环境定义。

from mini_agentic_rl import DirectoryEnv, discounted_returns

env = DirectoryEnv()
env.reset()

rewards = []
for action in ["search_project", "lookup_lead", "answer:Mina"]:
    observation, reward, done = env.step(action)
    rewards.append(reward)
    print(action, observation, reward)
    if done:
        break

print(discounted_returns(rewards, gamma=0.9))
# [0.81, 0.9, 1.0]

这个例子把“工具返回”保留为 observation，把“模型选择的工具”保留为 action；如果跳过第一步直接查询负责人，环境会返回错误反馈。测试文件验证状态转移、终止行为和折扣回报。它没有训练语言模型，也没有声称复现 AgentGym、WebRL 或 Tunix 的性能。

13 / FAILURE MODES

Agentic RL 的失败模式与边界

失败类型表现诊断与缓解
Reward hacking学会绕过验证器或利用环境漏洞对抗性测试、独立 verifier、约束奖励与人工审计
Sparse credit最终失败，但无法定位哪次动作导致失败回报分解、GAE、层次化 credit assignment、过程信号
Tool loops重复搜索、重复点击、无效调用重复检测、调用预算、状态机约束和失败恢复
Horizon collapse交互轮数增加后训练不稳定或策略退化渐进式 horizon、任务难度混合、梯度与轨迹监控
Environment drift网页、API 或模拟器变化导致训练分布漂移版本化环境、确定性回放、数据新鲜度监控
Policy lag异步 rollout 用旧策略采样，训练时分布不匹配记录 policy version、限制 lag、重要性采样校正
Unsafe exploration智能体在真实系统中执行破坏性动作沙箱、最小权限、审批门、不可逆操作保护

最重要的工程原则：训练环境应当先可控、可回放、可审计，再逐步接近真实世界。不要把真实数据库、真实付款、真实部署权限直接交给尚未经过评测的探索策略。

14 / SYNTHESIS

最后：如何建立正确的 Agentic RL 心智模型？

Agentic RL = Policy + Environment + Trajectory + Reward + Learning Loop。 策略负责行动，环境提供真实反馈，轨迹保存因果上下文，奖励定义任务成功，学习算法把结果转化为策略更新。
  1. 先学 MDP / POMDP：理解状态、观察、动作、转移和回报。
  2. 再学 Policy Gradient / GAE / PPO：理解如何把回报转化为策略梯度。
  3. 接着学 GRPO：理解同一任务下多条 rollout 的相对比较。
  4. 再学 ReAct 与 Tool Calling：理解 LLM 如何把生成内容转化成外部动作。
  5. 最后进入 Agentic RL：把策略更新、环境交互、信用分配、任务课程和异步系统连成一个完整闭环。
