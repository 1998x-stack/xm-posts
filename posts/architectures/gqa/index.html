Understanding GQA

如果生成下一个 token 时，只计算很少的 Query，为什么还要反复从显存读取整段历史的 Key 和 Value？

Ainslie et al. · EMNLP 2023注意力头共享 / KV 带宽 / Uptraining约 34 分钟
核心直觉：Query Head 继续保持多样性，让几个 Query Head 共用一套 Key/Value 参数与缓存。压缩的是历史读写所需的 KV 通道，不是把 Query 直接合并。

01 · 一次 Decode，为什么会变成内存读取问题？

想象输入已经经过 Prefill，模型现在要生成第 4097 个 token。新的 Q 只来自当前 token，但它要同之前 4096 个位置的 K 做相似度，再按权重读取 V。

在因果解码器中，过去 token 的 K/V 可复用，因此我们将它们存成 KV Cache；然而每一步生成都需要按需读取已有历史。序列越长、并发越高，缓存占用和内存带宽压力就越显著。计算量并非唯一的速度瓶颈。

这正是 Shazeer（2019）提出 Multi-Query Attention（MQA）的背景：既然 Query 仍可有多个头，K 和 V 是否必须也有同样多的头？[Shazeer 2019]

02 · MHA、MQA、GQA：谁共享了什么？

记 Query Head 数为 H、KV Head 数为 G。标准 MHA 为每个 Query Head 分配单独的 Key/Value；MQA 将所有 Query Head 接到同一组 K/V；GQA 则允许中间的组数。

G = HMHA：每个 Query Head 有自己的 K/V。
1 < G < HGQA：多个 Query Head 共享一对 K/V。
G = 1MQA：全部 Query Head 共享一对 K/V。

GQA 是广义形式：GQA-1 等价于 MQA，GQA-H 等价于 MHA。论文的 GQA-8 表示 8 组 KV Head，不是每组有 8 个 Q。[论文 §2.2]

03 · 关键公式：Query 保持 H 个，KV 只有 G 个

先取一组可明确计算的约定：H 可以被 G 整除，相邻的 r=H/G 个 Query Head 分为同组。对第 i 个 Query Head，索引从 0 开始：

r=HG,g(i)=⌊ir⌋
(1)

若单个 Head 的维度为 d，当前批的 Q 张量形状是 [B, Tq, H, d]，而 K/V 为 [B, Tk, G, d]。对单个 Query Head i，其输出为：

Oi=softmax(QiKg(i)⊤d+M)Vg(i)
(2)

其中 Qᵢ 是第 i 个 Query Head，K_{g(i)} 与 V_{g(i)} 是它所属组的共享键和值；M 是注意力 Mask（因果注意力禁止访问未来位置）。注意力先沿键位置维做 Softmax，再与 Value 相乘；不同 Q Head 仍产生不同 Attention 分布与输出。

容易误读的地方：组共享不等于将 Query 求平均，也不等于对各个 Head 的 Attention 输出求平均。压缩的是 K/V 投影参数和由它们产生的状态；各 Q 的 Softmax 独立计算。

04 · KV Cache 显存为什么几乎正比于 G？

假设 L 个层都使用相同的全量 KV Cache，批大小 B、历史长度 T、KV Head 数 G、每个 Head 维度 d、每元素 s 字节，并且 Key 与 Value 具有相同形状，那么原始 KV 张量负载是：

MKV=2·L·B·T·G·d·s
(3)
MGQAMMHA=GH
(4)

比如 L=32、B=1、T=4096、H=32、d=128、BF16（s=2 字节），MHA 的缓存为 2 GiB；GQA-8 是 512 MiB；MQA 是 64 MiB。这里比较的是相同维度假设下的原始 KV 张量，不含页表、对齐、碎片、量化元数据或其他工作区。

论文也指出：标准张量并行会在多个分区间复制仅有的一组 MQA K/V，导致分片效率受限；GQA 的多个 KV 组给分片留下更灵活的配置空间。最终表现仍由并行度、通信、算子实现及请求长度共同决定。

05 · 直接换成共享 KV，旧 Checkpoint 怎么办？

训练一个新模型很昂贵。论文提出先转换、再继续训练的路径：保留原来的 Query/输出投影，对原 MHA 的 Key 与 Value 投影矩阵按组进行均值池化。这不是把推理时 KV Cache 简单重排。

WgK=1r∑j=gr(g+1)r−1WjK,K→V 同理
(5)

这是一个合理的初始化，因为它保留了旧 Head 的部分统计信息。但 Softmax 是非线性的，新的共享 K/V 不能使原 Attention 输出逐项保持相等。参数转换 ≠ 功能无损等价，因此要继续训练以补偿能力损失。

06 · 5% Uptraining 到底指什么？

论文将预训练完成的 T5.1.1 MHA Checkpoint 转成 GQA/MQA 结构后，复用原预训练目标、数据与训练方案，额外训练原预训练步数的一小部分 α。主实验选择 α=0.05。

在 T5-XXL 的主实验中，α=0.05 的额外训练约需 600 TPUv3 chip-days，这是论文报告的资源投入；对其他模型规模和训练配方不能直接照搬这个数。[论文 §3.1]

实验同时表明：均值池化优于只取第一个旧 Head，后者又优于随机初始化；增加训练比例总体改善性能，但从 5% 到 10% 的收益呈递减趋势。消融曲线的绝对分数依赖特定任务子集，不应与 Table 1 的全任务 Average 混用。

07 · 动手：改变组数，看看缓存如何变化

固定 32 个 Query Head。调整 KV Head 数 G，观察组内共享比例和理论缓存大小。这个演示只做确定性尺寸推算，不是 GPU 速度测试。

多少个 KV Head 才够？

固定 L=32、B=1、T=4096、H=32、d=128、BF16；按 G 选择。

G=8：每 4 个 Query Head 共享一组 KV；原始 KV Cache 为 512 MiB（MHA 的 25%，理论容量节约 75%）。

选择 G=32 回到 MHA，选择 G=1 变成 MQA。组数越小，K/V 的表征自由度也越少；缓存减少不保证任务质量不变，也不保证延迟按相同比例缩短。

08 · 一个能验证索引与权重合并的最小实现

实现 GQA 不必将 K/V 物理重复 H/G 次。对 Head i，使用分组索引 i // (H // G) 访问对应 K/V 即可。实际 GPU Kernel 可能采用广播、分块或特殊的加载调度。

def group_index(query_head, n_query_heads, n_kv_heads):
    assert n_query_heads % n_kv_heads == 0
    return query_head // (n_query_heads // n_kv_heads)

# H = 8, G = 2
assert [group_index(i, 8, 2) for i in range(8)] == [0,0,0,0,1,1,1,1]

独立的 mini_gqa.py 使用 Python 标准库实现缩放点积、按组共享 K/V、矩阵均值池化以及 KV 字节数计算；test_gqa.py 检查 MHA/MQA 端点等价、分组索引、投影均值和缓存尺寸。这是数学/形状一致性测试，不是 T5-XXL 复现，也不测真实 GPU 延迟。

09 · 原论文证据：质量接近 MHA，时间接近 MQA

主实验使用 T5.1.1 Large 与 XXL。MQA、GQA 仅修改 Decoder Self-Attention 和 Cross-Attention，没有修改 Encoder Self-Attention。论文用 TPUv4、greedy decoding 测量每样本推理时间，且为各模型分别优化并行方式。[§3.1–3.2，Table 1]

模型时间/样本 (s)Average*方法
MHA-Large0.3746.0原模型
MHA-XXL1.5147.2原模型
MQA-XXL0.2446.65% Uptraining
GQA-8-XXL0.2847.15% Uptraining

* Average 是论文跨 CNN/Daily Mail、arXiv、PubMed、MediaSum、MultiNews（ROUGE-1）、WMT（BLEU）和 TriviaQA（F1）得到的汇总指标。不同任务量纲与评估方式不同；它不是某个数据集的单一准确率。

相对于 MHA-XXL，GQA-8 的时间比值 1.51/0.28≈5.39，Average 从 47.2 到 47.1；MQA-XXL 更快（0.24s）但 Average 更低（46.6）。不能将 MHA-Large 与 XXL 的质量、参数规模混作同一控制变量。

权重初始化：平均真的比随机好？

额外训练：0%、5%、10% 有什么区别？

Figure 5 显示转换后的 GQA 立即具备一定质量，MQA 对继续训练更敏感；两者在 5% 后继续增加训练的边际收益变小。这也是转换和训练两阶段都不可省略的证据。

组数：越接近 MHA，延迟一定线性增长？

Figure 6 在输入 2048、输出 512 的条件下，1→8 个组造成的时间增加相对温和，向 64 组移动则开销明显加大。这个关系受到硬件带宽、模型分片及具体任务共同影响，并非对 G 的普适线性函数。

11 · 进入 LLM Infra：GQA 的收益在哪里，边界又在哪里？

  • KV Cache：Head 数越少，历史状态越小；对长上下文与高并发的 Decode 尤其关键，但 B、T、layer 配置和 Cache Policy 不变时才可直接按 G/H 比较。
  • Tensor Parallel：单 KV Head MQA 可能在多个分片间重复；GQA 的可分组 K/V 允许更灵活的映射，但实际是否更快取决于 TP 配置、通信和实现。
  • Prefill 与 Decode：Prefill 偏矩阵计算，Decode 经常受访存影响；“减少 KV 加载量”不能自动推出全请求端到端延迟或吞吐线性改善。
  • FlashAttention / PagedAttention：前者侧重 Attention IO 路径，后者侧重 KV 分配与访问管理；它们与 GQA 是不同优化维度，不应视作论文提出的同一方法。
  • 模型适配：非整除 Head Group、RoPE 应用位置、跨层共享 KV、Sliding Window、KV Quantization 都属于具体架构或实现选择；此文公式仅覆盖标准均匀分组情形。

继续阅读本站 Transformer、KV Cache、PagedAttention 和 FlashAttention，可把架构、缓存与 Kernel 的优化边界串起来。

12 · 论文没有证明什么？

原作者明确指出：评估主要覆盖 encoder-decoder T5，未在同等资源下系统比较从头训练 XXL GQA；ROUGE 对长序列质量的刻画有限；MQA 在部分长输入任务出现不稳定。论文对 decoder-only 模型的更大收益属于推断，不是当时论文中的 decoder-only 大规模实验证明。[Limitations 与 Appendix A]

同时要区分：理论 KV 字节公式是张量维度推导；Table 1 的时间是具体 T5/TPU 系统测量；当前 Serving 机制可能加入缓存分页、量化、RoPE、滑窗、张量并行等复杂条件。这三层证据互不能替代。
