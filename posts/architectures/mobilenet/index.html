Understanding MobileNet

不是把大型 CNN 简单缩小，而是重新组织一次卷积：先让每条通道看见空间，再让通道彼此交流。

MobileNet V1 · Howard et al., 2017 · 机制、成本推导与后续架构演进

核心问题：如果手机只能承担有限计算与内存，怎样用尽量少的乘加运算换来足够强的视觉特征？

01为什么大模型不能直接装进手机？

ImageNet 时代的 CNN 经常通过更多层与更多通道换取精度。然而实际运行需要同时考虑权重体积、峰值激活内存、运算量、算子实现以及真实设备的延迟。减小文件大小不等于降低延迟；减少理论计算也不保证提升每一种硬件的速度。

MobileNet V1 的关键设计决定是让卷积结构本身更便宜，并让用户沿两条独立方向调节模型：通道宽度与图像分辨率。这一架构面向移动和嵌入式视觉，而不是 2017 年所有视觉任务的绝对精度冠军。[1, §1–3]

02普通卷积为什么昂贵？

设输入张量为 H×W×M，卷积核边长为 k，输出通道数为 N，输出空间面积为 S=H′×W′。一个标准卷积核同时查看附近的 k×k 空间区域以及 M 条输入通道；要生成 N 条输出通道，就重复 N 组这样的学习。

Cfull=k2MNS
(1)

这里统计的是 multiply-adds（乘加次数，MACs / Mult-Adds），忽略 bias、BN、激活函数和内存访问；不要直接把它等同于不同口径下的 FLOPs 或设备毫秒延迟。

03逐通道滤波，再跨通道融合

Step A — Depthwise 卷积

给每一个输入通道单独应用一个 k×k 空间滤波器。若步幅与填充保持目标输出空间尺寸，这一步的中间特征维度是 H′×W′×M。它善于提取每个通道的局部模式，却不能把红色通道的信息直接混入绿色通道。[1, §3.1]

Step B — Pointwise 卷积

接着用 1×1×M×N 卷积核，在每个空间坐标上组合 M 个通道，生成 N 个新通道。空间滤波与跨通道投影由两组参数分别承担；V1 原论文在两层卷积后均使用 BatchNorm 和 ReLU。[1, §3.1–3.2]

04为什么 3×3 可以节约约 8–9 倍计算？

Depthwise 只需 k²·M·S 次乘加，Pointwise 只需 M·N·S 次；相加便得到可分离卷积的总成本。

CDS=k2MS+MNS
(2)
CDSCfull=1N+1k2
(3)

分母中出现的是输出通道 N，不是输入通道 M。若 k=3 且 N 足够大，比例逐渐接近 1/9；所以常听见的「约 9 倍」是渐近直觉，不是对任何层都精确成立的常数。

Depthwise + Pointwise：7,325,696 MACs；约为标准卷积的 12.7%（减少 87.3%）。

与固定同一输出形状的标准卷积相比，可分离卷积有结构约束：一个输出通道的空间核由共享的逐通道空间模板及 1×1 系数组成，未必能表示任意标准卷积核。它是一种归纳偏置与效率权衡，而不是免费且完全等价的代换。

05MobileNet V1 全网络如何搭建？

原论文 Table 1：以普通 3×3 stride 2 卷积为起点，再重复 13 组 Depthwise/Pointwise 对。下采样在首层或指定的 Depthwise 层通过 stride 2 完成；随后是全局平均池化、全连接分类器和 Softmax。逐层计数：1 个首层卷积 + 13×2 个 DW/PW 卷积 = 27 个卷积层；再加 1 个 FC，构成论文所称的 28 个可学习层，Softmax 不作为可学习层。[1, §3.2]

计数提示：业界对「多少层」的口径会把最终 FC 纳入可学习层。常见的 28 层说法是：1 个起始卷积 + 13×(DW+PW)=27 个卷积 + 1 个 FC = 28 个可学习层；不要把它误写成 28 个卷积层。

原论文 Table 2 还告诉我们：节省了昂贵的 k×k 混合后，绝大多数乘加转移到了高度优化的 1×1 卷积：占 94.86%；Depthwise 仅占 3.06%。优化后端时，Pointwise GEMM 的吞吐往往是关键。[1, Table 2]

06更小的模型：α 与 ρ 是两把不同的旋钮

Width Multiplier α

宽度乘子把每一层输入和输出通道从 M、N 缩成约 αM、αN。Pointwise 的成本因此约随 α² 缩小，但 Depthwise 项只随 α 缩小；所以「所有计算都严格按 α² 变化」是不准确的。实际模型需要对通道数做整数取整。[1, §3.3]

Resolution Multiplier ρ

分辨率乘子作用于输入图像及内部空间尺寸，理想化面积随 ρ² 变化。卷积核参数并不因为输入变小而自动减少；但空间边界、步幅和实际 shape 都可能使近似值出现偏差。[1, §3.4]

Cscaled=ρ2S(k2αM+α2MN)
(4)

08V2、V3、V4 改变了什么？

MobileNetV2：逆残差与线性瓶颈（2018）

与传统 ResNet 在宽通道表示上建立 shortcut 不同，V2 的 bottleneck 通道较少，中间先用 1×1 扩张得到更宽的通道，再做 Depthwise，最后通过无激活的线性 1×1 投影压回窄通道。仅在 stride=1、输入输出通道吻合时采用恒等 shortcut；不是所有块都有残差。[2, §3]

y=Plinear(DReLU6(EReLU6(x)))+x (same shape, stride 1)
(5)

线性瓶颈旨在避免对低维表征过早施加 ReLU 造成的信息损失。它并不意味着整个 V2 都不用非线性：扩张和 Depthwise 阶段仍采用 ReLU6。[2, §3.2]

MobileNetV3：把设备真实延迟放入设计目标（2019）

V3 结合硬件感知 NAS 与 NetAdapt，再引入 Squeeze-and-Excitation 通道注意力、h-swish 非线性以及面向不同资源范围的 Large/Small 版本。其目标是特定设备上的效果，不是仅让论文上的 MACs 最小。[3, §3–5]

MobileNetV4：跨加速器更普适（2024）

V4 引入 Universal Inverted Bottleneck（UIB），统一多种轻量级卷积块的搜索空间；并在部分模型中使用 Mobile Multi-Query Attention（Mobile MQA）。关注 CPU、GPU、DSP、神经网络加速器之间的硬件差异。[4, §3]

09数值验证：计数与结构等价不是一回事

最小纯 Python 示例放在 mini_mobilenet.py。它计算标准卷积与 Depthwise+Pointwise 的 MACs，并对人为构造的可分离核验证两步实现与对应的标准卷积等价。这不代表任意标准卷积核都能无损分解成一次 DW 和一次 PW。

from mini_mobilenet import cost, check_factorized_equivalence

full, separable = cost(k=3, m=32, n=64, h=56, w=56)
assert full == 57_802_752
assert separable == 7_325_696
assert check_factorized_equivalence()
print(round(full / separable, 2))  # 7.89

测试不加载训练权重、不复制论文精度、不测真实设备延迟；对照实验与生产部署需要完整模型、推理引擎、量化方案和目标设备基准。

10工程应用最容易混淆的五件事

  1. MACs ≠ latency：Depthwise 在部分推理后端可能受到访存或算子调度限制；请实测端到端延迟。
  2. 参数数目 ≠ 峰值内存：中间激活、临时缓冲区与量化元数据也要计入。
  3. α 与 ρ 不是推理时的免费开关：切换宽度通常需要一组匹配的结构和训练权重；不能直接裁剪已训练权重而假定达到原论文的结果。
  4. BN 融合应区分训练与部署：推理时可在符合条件的 Conv/BN 组合做折叠，但并不改变 V1 与 V2 的结构定义。
  5. 版本差异影响性能解释：V1 使用 DW/PW + ReLU；V2 线性瓶颈；V3 加硬件感知搜索和 SE；V4 则扩展为更广泛的可搜索轻量模块。
定量报告应同时提供：模型版本、宽度/输入分辨率、参数量、MAC 计数约定、实际设备与推理框架、预热/批量设置、延迟分位数、准确率数据集与评测流程。

11检查自己是否真正理解

为什么 Depthwise 不能直接取代 Pointwise？

Depthwise 对每个输入通道独立滤波，不进行跨通道组合；Pointwise 才能学到新的通道特征。

为什么把分辨率减半不会把参数量降成 1/4？

卷积核的参数只由核大小、输入/输出通道决定；分辨率减小的是被卷积的空间位置个数，主要降低 MACs 与激活开销。

为什么 V2 的「linear」不等于全网线性？

线性只描述瓶颈末端投影不再加 ReLU；扩张及 Depthwise 位置仍有非线性，块之间也有可选的残差路径。

一句话：MobileNet 最值得学习的不是某一个 ImageNet 数字，而是如何把 CNN 的计算拆成可分配、可量化、可沿硬件约束重新设计的部分。
