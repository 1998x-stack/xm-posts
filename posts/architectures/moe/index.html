PAPER STUDY / CONDITIONAL COMPUTATION / ICLR 2017

Understanding Mixture of Experts

为什么只执行少数专家，模型却能拥有巨大的参数容量？从门控数学和一枚 token 的路径理解 MoE 的计算优势，以及真实系统必须支付的代价。

Shazeer et al. · ICLR 2017MoE / Top-K / Load Balancing / Expert Parallelism约 35 分钟
核心观点：每次只执行少量 Expert，使模型总参数量与单 token 专家计算不再同步增长；但 Router、负载均衡、专家权重存储、分布式通信与容量仍决定实际效率。

01 · 为什么需要条件计算

在普通 Dense FFN 中，每枚 token 都走完整的同一组权重。模型扩容时，执行成本随之增加。能否拥有许多备用子网络，却只调用少量相关子网络？

这是稀疏 Mixture of Experts (MoE) 的核心。假设 N 名专家各自拥有权重，Router 对每枚 token 选择 k 名，k 远小于 N。权重总容量可以随 N 增加，而单次专家计算更接近 k 的规模。节省的是本次不执行的专家算术，不是凭空消失的模型权重内存或通信。

02 · 一枚 token 穿过 MoE

一条信息路径包含：隐藏状态 x → Router 打分 → Top-K 选专家 → Dispatch → Expert 前向 → 按权重聚合，再回到主干。不同 token、不同层可以选不同专家。专家的专业化要由实验检查，而不是靠给专家起名字。

专家的输入输出维度要能满足后续层的张量接口。若主干隐藏宽度是 d，每位专家可拥有不同权重，但输出仍是 d 维；这样才能参与按分数加权求和。

03 · 原论文并非 Transformer MoE

Shazeer 等人在 ICLR 2017 将稀疏门控 MoE 置于堆叠 LSTM 层之间，应用于语言建模和机器翻译。它不是后来 Transformer block 的 Dense FFN 替换设计。

混合专家思想本身更早出现在 Jacobs 等人 1991 年的工作中；2017 的关键创新是让稀疏条件计算在大量专家和分布式 GPU 上实用。之后的 GShard、Switch、Mixtral 与 DeepSeekMoE 有不同的路由规则和系统策略。

读后续论文时，必须记录它采用 Top-1 还是 Top-2、何处插入 MoE、是否共享专家、是否容量限制、何种平衡损失和哪些通信原语。

04 · 核心前向方程与稀疏门控

在原论文 §2，记 Eᵢ(x) 为第 i 个专家输出，Gᵢ(x) 为其非负门控系数，且 N 维门控仅有少数非零项：

y=∑i=1NGi(x)Ei(x)
(1)

这并不是要实际算出 N 个专家输出再相加。对 Gᵢ(x)=0 的项，可以直接跳过 Eᵢ 的计算。Softmax 如果施加到全部 N 个普通 logit，会得到稠密门控；要实现稀疏执行，必须先选择支持集合。

G(x)=softmax(KeepTopK(H(x),k))
(2)

KeepTopK 保留前 k 个得分，把其他位置设为负无穷，再 Softmax 得到只有 k 项非零的概率。本文实现采用并列分数选较小专家索引的确定性规则，这是教学实现细节。

05 · 为什么原论文要有 Noisy Top-K

纯粹贪心选择会产生“富者愈富”：较早被偏爱的专家先得到更多样本并更快更新，从而持续胜出。2017 §2.1 在 Router 的线性得分上加入标准正态随机变量和可学习的 Softplus 噪声尺度，训练时让更多路由路径被探索。

Hi(x)=(xWg)i+εi·softplus((xWnoise)i)
(3)

εᵢ 是标准正态噪声，Wg 和 Wnoise 是两组可学习参数。这是Shazeer 2017 的 Noisy Top-K 训练定义，不能写成所有 MoE 的共同公式。实际测试时的路由是否去噪由模型实现决定。k>1 时已选中 gate 对 Router 权重存在局部梯度，Top-K 的选择边界则不连续；不应声称整个离散路由处处可微。

06 · 张量形状与专家计算预算

以现代 token-wise MoE 的简化教学实现为例：输入 X 的形状为 [T,d]；Router 权重 [d,N]；路由 logits [T,N]；Top-K 产生 [T,k] 的索引和权重。按专家分组后的 Expert 输入是 [tᵢ,d]，经 FFN 再 scatter-combine 复原 [T,d]。

routes/expert≈TkN
(4)

T 是本批次 token 总数；均匀路由时一位专家平均约接收 Tk/N 次调用。N 增加而 T 不变时，每位专家获得的微批缩小，可能使 GPU GEMM 利用率下降。原论文 §3.1 正是从 shrinking batch problem 出发设计混合数据并行和模型并行。

Ptotal≈Pshared+NPexpertPactive≈Pshared+kPexpert
(8)

模型所有专家权重需要有存储或可加载位置。活跃参数少，不等于显存只储存活跃权重；另有 KV Cache、buffer 和通信成本。

07 · Importance、Load 与专家塌缩

2017 §4 分别定义 Importance 与 Load：Importance 是一个批次内分配给某专家的 gate 权重总和；Load 衡量专家实际被挑选的样本数量。二者不能互换，因为少量大权重和大量小权重可能拥有相似 Importance。

Limportance=wimportanceCV(Importance(X))2
(5)

CV 是变异系数（标准差除均值），其平方在专家重要性均匀时更小。论文还在 Appendix A 定义通过概率估算的 Load loss，与简单整数计数不同。不能把这两种正则项写成 Switch 的 Laux。

08 · 容量约束与溢出路由

GShard / Switch 等具体实现需要让 dispatch buffer 的形状可管理，于是给 Expert 设置 Capacity。某一专家已满后，被选择的 token 可能失去该路由、被保留在残差路径、或由实现采用其他策略处理。Drop Token 不是所有 MoE 的必然行为。

C=⌈cTkN⌉
(6)

这是一条通用教学用的容量账本：c 是 capacity factor，T 是 token 数，k 是选中专家数，N 是专家数。各论文的 capacity 定义与 Top-1/Top-2 处理不同，本式不能冒充 GShard / Switch 的原论文等式。容量越低，可能减少 padding 却导致更多 overflow；容量越高，缓冲和计算分配成本也可能升高。

09 · Switch、Mixtral、DeepSeekMoE 分清版本

Switch Transformer 的 Top-1

Fedus、Zoph、Shazeer 的 Switch Transformer（JMLR 2022）简化为每 token 选择一位专家，并在其论文的训练目标中加入基于专家分配频率 fᵢ与平均路由概率 Pᵢ的辅助损失：

Laux=N∑i=1NfiPi
(7)

这里 N 为专家总数。它与 Shazeer 2017 Importance CV² 和 Load loss 是不同定义。Switch 的 bfloat16 训练技术和实验特定的预训练加速数字，也不能推成所有 GPU 推理加速保证。[Fedus et al. §2.2]

Mixtral 的 Top-2 与 DeepSeekMoE 的共享专家

Mixtral 8×7B 的每层包含 8 个 FFN expert，每个 token 经过 Router 选择其中 2 个；论文以约 47B 总参数、约 13B 活跃参数说明参数口径差异。DeepSeekMoE（ACL 2024）引入 fine-grained expert segmentation 与 shared expert isolation，让常用知识由共享专家承载，路由专家专注更细分的路径。

GShard 面向多语言翻译，把稀疏条件计算与自动分片结合。三者在路由、共享结构和系统目标上都与 2017 的 LSTM+MoE 有区别。

10 · Expert Parallelism 与真实系统成本

专家多到跨设备时，先根据 Router 选择目标专家，再把 token 重新排序、跨设备 dispatch、运行 expert GEMM、发送结果并聚合。这个通信常涉及 All-to-All。2017 原论文 §3 的重点之一，就是避免每个专家收到太小的局部批次，并使网络传输与专家计算比例可接受。

因此分布式 MoE 需要同时看 MFU、专家微批、Top-K 分布、尾部专家负载、All-to-All 传输、组批效率和内存调度。理论 FLOPs 省了，实际延迟仍可能因为通信与不均衡而上升。对 Decoder，Prefill 与 Decode 的 token 数不同，专家负载特性也不同。

12 · 能运行的最小 Router 参考实现

文内采用纯 Python 标准库构建可验证的教学模块：moe_toy.py 包含 Top-K 稳定 Softmax、标量 Expert 加权组合、容量 dispatch、Importance 与 CV²；tests/test_moe.py 使用确定性不变量验证逻辑。不包含 Autograd、优化 GPU kernel、训练数据或真实 expert-parallel all-to-all。

from moe_toy import route_topk, combine_scalar
gate = route_topk([2.0, 1.5, 0.1, -0.4], 2)
assert sum(w > 0 for w in gate) == 2
assert abs(sum(gate)-1) < 1e-12
value = combine_scalar(3.0, gate,
    [(1.0, 0.0), (0.5, 1.0), (2.0, 0.0), (-1.0, 0.0)])

在真实张量模型中，还应补充精度、训练梯度、不同 Shape、分布式 dispatch/merge、负载和吞吐测试。这个例子只能证明公式实现的内部一致性。

13 · 论文证据与适用范围

原始来源能够支持的结论边界
Shazeer et al. 2017可训练的稀疏门控和大规模条件计算；论文展示最高约 137B 参数的 LSTM+MoE 方案。不是 Decoder-only Transformer 的量化结果。
GShard 2020/2021多语言机器翻译中自动分片 + 条件计算，研究规模超过 600B 参数。不同硬件和通信拓扑不可直接类推。
Switch 2022Top-1 路由与辅助损失；论文报告特定 T5 预训练基线的加速和 trillion-scale 模型。加速倍数并非无条件的实际推理时延结论。
Mixtral 2024八专家中每 token 激活两位，论文报告约 47B total / 13B active。活跃参数不是完整 GPU 显存占用。
DeepSeekMoE 2024细粒度专家切分、隔离共享专家以改善专门化。并非原始 Shazeer MoE 的基本组成。

阅读论文结果应保留对照模型、数据集、比较预算和推理/训练设置。本文手工 logits、示例专家调用数和容量实验全部是可重复的独立教学数字，不将其误作论文报告的消融结果。

14 · 局限与进一步阅读

MoE 不自动保证语义可解释的“专家分工”，也不保证训练稳定或在线低延迟。路由塌缩、Expert 负载尾部、权重驻留、KV Cache、带宽和 token dispatch 的复杂度，仍须随任务与硬件单独测试。

  1. Shazeer et al., ICLR 2017, Outrageously Large Neural Networks: The Sparsely-Gated Mixture-of-Experts Layer，重点 §2–4、Appendix A。
  2. Lepikhin et al., ICLR 2021, GShard: Scaling Giant Models with Conditional Computation and Automatic Sharding。
  3. Fedus, Zoph & Shazeer, JMLR 2022, Switch Transformers。
  4. Jiang et al., 2024, Mixtral of Experts。
  5. Dai et al., ACL 2024, DeepSeekMoE。
