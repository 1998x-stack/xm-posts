Understanding Multi-Head Attention

如果一个 Attention 已经能从整段序列挑选信息，为什么还要拆成多个 Head，分别计算，再重新拼接？

Vaswani et al. · NeurIPS 2017Q / K / V · Head · Mask · Softmax约 28 分钟
核心直觉：多头不是把同一张注意力图复制 h 次，而是学习 h 组不同的线性投影，使不同头可以在不同特征子空间和不同 token 之间分配注意力，再整合其输出。多头首先是一种表达能力设计，不是自动获得 h 倍速度的技巧。

01 · 一个权重分布，为什么可能不够？

一个词可能同时需要找到“谁做的动作”和“动作作用于什么”。一次注意力得到的是一组归一化权重，再把 Value 加权成一个向量。

单个 Head 并非完全不能表达多种关系，但一次输出依赖同一组权重。多头把 Q、K、V 送进不同的可训练投影，容许每个 Head 学到不同的比较空间与关注模式。原论文 §3.2.2 明确将这点作为动机，而不是声称每个 Head 必然学会指定的语法角色。[Vaswani et al., 2017]

“不同头可学习不同模式”和“Head 的注意力权重就是忠实的因果解释”是两个命题；后者需要额外验证。这里首先只讨论可计算的机制。

02 · 先理解一个 Scaled Dot-Product Attention

令 Query 矩阵 Q 的维度为 Lq × dk，Key 矩阵 K 为 Lk × dk，Value 矩阵 V 为 Lk × dv。Q 乘 K 的转置得到 Lq × Lk 个匹配分数。对每一行按 Key 位置归一化，再乘 V，输出为 Lq × dv。

Attention(Q,K,V)=softmax(QK⊤dk+M)V
(1)

这里 M 是为了明确掩码场景而加入的扩展写法：合法 Key 的 M 为 0，不可见 Key 的 M 为负无穷。Softmax 必须沿 Key 轴进行，确保每个 Query 行的概率和为 1。原始论文公式 (1) 无显式 M，但论文 §3.2.3 描述了 Decoder 的 masked attention。

三个位置得分若为 2、1、0，Softmax 将其变成一组总和为 1 的概率。K 影响读取概率，V 是真正被聚合的内容：这能避免把 Q/K/V 三者误画成相同功能。

03 · 多头的关键：独立投影，而非重复计算

第 i 个 Head 使用自己的 WᵢQ、WᵢK、WᵢV，先得到 Qᵢ、Kᵢ、Vᵢ，然后执行独立的缩放点积注意力。它们独立归一化；注意力权重不会先在 Head 之间相加。

headi=Attention(Qi,Ki,Vi)
(2)

各头输出沿特征维拼接，然后乘输出投影 Wᴼ：

MultiHead=Concat(head1,…,headh)WO
(3)

投影矩阵形状是 WᵢQ, WᵢK ∈ R[dmodel × dk]、WᵢV ∈ R[dmodel × dv] 和 Wᴼ ∈ R[(h·dv) × dmodel]。最后一步将拼接的表示重新映射回模型宽度，供残差连接和后续网络使用。

关键误区：多头不是让多个 Head 共用同一组 Q/K/V 权重，也不是“多个 Softmax 结果求平均”。Query/K/V 的独立投影、独立归一化、Concat 与 Wᴼ 的顺序共同定义了标准 MHA。

04 · 具体形状：8 个 Head，为什么总宽度还是 512？

原论文 Transformer-base 采用 dmodel=512、h=8、dk=dv=64；每个 Head 处理 64 维的 Q/K/V，8 个输出在特征轴拼接后是 512 维，并不是把输出宽度膨胀为 4096。[§3.2.2，Table 3]

dk=dv=dmodelh=5128=64
(4)
计算阶段张量形状（省略 batch）为什么
输入 XL × 512每个 token 的特征
单头 Qᵢ/Kᵢ/VᵢL × 64各自线性投影
单头权重L × L每个 Query 对所有 Key 的分布
Head 输出拼接L × 5128 × 64，沿特征轴连接
Wᴼ 之后L × 512回到模型主通道宽度

若 Q/K/V 总投影宽度均固定为 dmodel，忽略偏置，三组输入投影加一组输出投影共 4 × dmodel² 个权重；在 512 维时是 1,048,576。这不是整个 Transformer Layer 的参数数，也不能据此推断 h 变化时的 GPU 延迟不变。

05 · 为什么点积要除以 √dk？

假定 q 和 k 的分量独立、均值为 0、方差为 1，则点积是 dk 个乘积的和，方差为 dk。dk 增大时，Logit 的典型量级也变大，Softmax 更容易饱和、产生很小的梯度。除以平方根可以在此简化假设下把方差恢复到 1 的量级。[§3.2.1，脚注 4]

Var(q·k)=dk
(5)

这里的方差结论依赖独立和单位方差假设，不是所有网络激活都精确满足的经验定律。实际计算还需要对每个 Query 行减去最大 Logit，再做指数与求和，以保证数值稳定。

06 · 自注意力、交叉注意力与因果 Mask

原始 2017 Encoder–Decoder Transformer 在三个场景使用 MHA。机制相同，但是 Q、K、V 的来源及可见范围不同。

使用位置Query 来自Key/Value 来自可读取位置
Encoder self-attentionEncoder 当前层输入同一层输入全部非 padding 位置
Decoder masked self-attentionDecoder 当前层输入同一层输入当前位置与历史位置
Encoder–decoder cross-attentionDecoder 中间表示Encoder 最终输出全部可用源位置

训练时可以同时计算所有 Query 行，并用 Mask 防止未来信息泄漏；增量推理时可以只算当前步的 Query，重用历史 K/V。两种执行方式遵循同样的因果语义，但内存与调度行为不同。

09 · 复杂度与历史 KV Cache：为什么有 MQA/GQA？

全序列标准 Self-Attention 在每头构造 L×L 打分；当各头的合计宽度固定为 dmodel 时，打分和加权值的主导计算量通常写作 O(L² · dmodel)。如果显式存储每头完整得分/概率矩阵，则中间张量占用随 hL² 增加；现代 IO-aware Kernel 可以通过分块与重计算改变中间访存策略，但不改变本文的数学定义。

增量 Decode 需要历史 Key/Value。若 L 是层数、B 是批大小、T 是历史长度、G 是 KV Head 数、d 是每头 K/V 维度、b 是每元素字节数，则原始张量体积在等宽假设下为：

CKV=2·L·B·T·G·d·b
(6)

MHA 通常让 G=h；Shazeer 2019 的 MQA 让 G=1；Ainslie et al. 2023 的 GQA 允许 1<G<h。减少 KV Head 能减小原始缓存体积与潜在读取量，不等于端到端解码延迟必然按同比例改善。

延伸阅读：Understanding GQA、Understanding KV Cache。MQA/GQA 是后续推理架构的演化，不要倒灌进 2017 年 Transformer 的原始实现。

10 · 最小可运行代码：形状、Softmax 与 Mask

仓库的 mini_mha.py 使用 Python 标准库实现每头切片、稳定 Softmax、因果遮罩、加权 Value、Concat 和输出投影。tests/test_mha.py 对可见性、形状和概率归一化做确定性断言。

from mini_mha import self_attention, identity

x = [[1.0, 0.0], [0.0, 1.0]]
w = identity(2)
out, attn = self_attention(x, w, w, w, w, heads=1, causal=True)
assert attn[0][0][1] == 0.0  # 第一个 token 不能看未来
assert len(out) == 2 and len(out[0]) == 2

运行 python posts/architectures/multi-head-attention/mini_mha.py 即可执行内置自检，也可用 python -m pytest -q tests/test_mha.py 检查边界。该实现没有 batch、位置编码、偏置、dropout、反向传播或 GPU Kernel；这是数值核示例，不是对论文翻译实验的复现。

11 · 工程与解释上的五个边界

  • 多头不保证自动分工：不同 Head 可能冗余或学习到难以简单命名的关系。
  • 多头不保证更快：实际速度依赖矩阵形状、GPU Kernel、内存布局、负载与 KV Cache。
  • MHA 本身不编码顺序：原论文通过将 Positional Encoding 加入输入表示提供位置信息。
  • Mask 必须先于 Softmax：事后清零概率且不重新归一化，会改变注意力输出语义。
  • Head 数不是自由增加容量的旋钮：固定总投影宽度时，更多头意味着每头维度更窄。

建议的研究路径是 Transformer 总览 → 本篇 MHA 的算子级定义 → GQA 的 KV Head 共享 → KV Cache / FlashAttention 的 Serving 细节。
