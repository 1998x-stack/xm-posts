PAPER STUDY / TRANSFORMER ARCHITECTURE

Understanding RoPE

Attention 只是在比较向量。怎样让它知道两个 token 相距多远，同时保留连续空间中优雅的相对位置结构？

Su et al. · RoFormer（2021 初稿，2023 修订版）核心主题 · 位置编码 / Attention约 30 分钟
一个核心发现：先按 token 的绝对位置旋转 Q、K，再做内积。旋转的组合规律会让内积中的位置部分只依赖两者的相对位移。

01 · 如果 Attention 只看内容，顺序在哪里？

把「猫 追」换成「追 猫」，词向量还是那些词向量，但语义关系已经发生变化。没有位置项的全连接 Self-Attention 在对输入位置作同一置换时，其输出也会相同地置换：它本身不拥有固定的 token 序号。

原始 Transformer 在 token 表示上相加 正弦位置编码。这是一种向表示注入位置信息的方法。RoPE 换了入口：不必先把“位置信号”加进残差流，而可以直接修改计算注意力分数的向量。

02 · 想要的不只是位置编号，而是相对关系

考虑同一句话位于上下文的第 2–5 个 token，与位于第 8–11 个 token。内容关系没变，位置整体右移了 6。理想的某些位置机制应当让与距离有关的项保持一致，而不必为每个绝对位置重新学习一套规则。

记查询所在位置为 m，键所在位置为 n。我们希望查询键的交互满足 f(q, k, n − m) 形式：绝对位置各自进入变换，组合之后却呈现相对位移。这里的“不变”要求 q 和 k 内容相同、采用相同旋转频率。

03 · 从一个二维向量开始旋转

将一对相邻通道看成平面向量 u = (u₀,u₁)。位置 m 的编码不是增加一组坐标，而是令它沿平面旋转 mθ 弧度。旋转矩阵保持长度与同角度下的向量夹角。

R(α)=[cosα−sinαsinαcosα]
对于 u ∈ ℝ²，RoPE(u,m) = R(mθ)u，且 ‖R(mθ)u‖₂ = ‖u‖₂。

二维单元也可以写成复数乘法：(u₀ + i u₁) · eimθ。两种写法等价；工程实现通常使用成对通道上的 sin/cos 运算。

04 · 为什么会自动出现相对距离？

关键恒等式是旋转矩阵的转置等于其逆矩阵，以及旋转角度可以相加。对未旋转的 q、k ∈ ℝ²，有：

⟨R(mθ)q,R(nθ)k⟩=qᵀR((n−m)θ)k
推导： (R(mθ)q)ᵀ(R(nθ)k) = qᵀ R(−mθ)R(nθ)k。
Step 1

在位置 m 上，q 转过 mθ；在位置 n 上，k 转过 nθ。

Step 2

点积把左侧旋转矩阵转置，等价于转过 −mθ。

Step 3

剩余的角度是 (n−m)θ，因此绝对位置对分数的影响合并为相对位移。

精确边界：这里证明的是单个 Q·K 分数的旋转部分对共同平移不变，前提是 q、k 内容固定，并且旋转频率一致。完整 Attention 的分布还取决于内容、Mask、缩放与其他网络层；不能据此宣称模型具备完美的长度泛化。

05 · 从一对通道推广到多频率 RoPE

一个 attention head 往往有 d 个通道（以下假设旋转维度 d 为偶数）。将其划分成 d/2 对，每一对使用不同的频率：

θi=B−2id，i=0,…,d2−1
B 为频率基数（常见默认值为 10000，但应读取具体模型配置）；每一对使用 R(mθᵢ)。

高频通道在相邻 token 上变化更明显；低频通道随距离缓慢旋转。把这些旋转放到对角块里，可写成 RΘ,m = diag(R(mθ₀), …, R(mθd/2−1))。整组内积就是每一对的相对旋转贡献之和。

交错配对 / interleaved

(x₀,x₁)、(x₂,x₃)……每对分别旋转。

半维配对 / half-split

(x₀,xd/2)、(x₁,xd/2+1)……只是张量布局不同；必须与 checkpoint 定义匹配。

实现里的 rotary_dim 可能小于 head_dim，剩余通道不参与旋转。不能仅从模型名字判断所有通道都使用了 RoPE。

06 · 究竟把旋转放在 Attention 的哪里？

设输入 X ∈ ℝB×L×D，Q/K ∈ ℝB×H×L×dₖ，V ∈ ℝB×Hv×L×dᵥ。对每个 Q 和 K 按其 token 的绝对位置旋转，随后才计算 QKᵀ / √dₖ、Mask、softmax 和加权 V。GQA/MQA 的 K/V 头数可以小于 Q 头数，逻辑仍相同。

“旋转 Q/K，而不旋转 V”很重要：RoPE 的目标是改变 谁关注谁 的匹配分数，不是让被加权汇聚的 Value 特征随着绝对位置一起转动。

07 · 两维、三个位置：手算一个最小例子

取 q=(1,0)、k=(1,0)，令频率 θ=π/4。若 m=1、n=3，那么两个向量旋转后相差 2θ=π/2，故它们内积等于 0；若同时右移 5 个位置（m=6、n=8），相对位置仍是 2，内积仍然是 0。

qᵀR((n−m)θ)k=cos((n−m)θ)=cos(π2)=0
这是教学用的单位向量与人工 θ；并非任何模型的真实 attention score，更不是论文实验结果。

当 q 与 k 不完全相同，结果仍只随差值出现，但会变成包含 sin 与 cos 的线性组合；每个维度对最终分数的影响还受内容向量大小与方向控制。

08 · 交互实验：同时平移 Q 与 K 会怎样？

固定 q=(1,0)、k=(1,0)、θ=π/4。按钮仅改变位置，不改变内容。比较“同间距平移”与“改变间距”。

m=1, n=3, Δ=2。旋转后点积 cos(π/2) = 0.000000。

前两组分数相同，第三组的相对位移改变，分数将变成 cos(3π/4) ≈ −0.707107。这个小实验检查的是 旋转代数，不是长文本检索或模型质量。

09 · 可复核的最小实现（纯 Python）

下面使用交错通道配对，不依赖第三方包；仓库中完整实现位于 posts/architectures/rope/mini_rope.py，测试位于 tests/test_rope.py。它验证范数保持、共同平移不变性，以及奇数维输入的防护。

def rope_pair(x, y, angle):
    import math
    c, s = math.cos(angle), math.sin(angle)
    return (c*x - s*y, s*x + c*y)

# 对 d 维向量的第 i 对使用：
# angle = position * base ** (-2 * i / d)
# attention score = dot(rope(q, m), rope(k, n))
# 只在 Q / K 上调用，不修改 V。

教学代码采用 float64 语义的 Python 浮点数和交错配对布局，不能直接替代模型的 fused kernel；实际工程还需要对齐模型权重布局、dtype、位置索引、cache 与推理后端。

10 · RoFormer 论文究竟证明了什么？

Su 等人的 RoFormer 从“能在内积中出现相对位置依赖”的目标出发构造 RoPE。论文第 3 节推导旋转表示及其性质，并通过长文本分类等任务分析其有效性。这里不引用未经核对的绝对分数，也不把当代 LLM 的效果归因于原论文中的某一次实验。

同一篇论文，不同任务上的结果并不一致

为了避免把“RoPE 有相对位置性质”直接跳跃成“所有模型性能都会更好”，先看 原论文第 4 节的具体表格：

论文位置 / 数据集基线RoFormer指标与解释
Table 1 · WMT14 En→De / TestTransformer-base：27.327.5BLEU，越高越好。论文中 RoFormer 高 0.2 BLEU，但不是跨所有任务的增益保证。
Table 2 · GLUE MRPC / ValidationBERT：88.989.5F1，越高越好；该任务 RoFormer 较高。
Table 2 · GLUE SST-2 / ValidationBERT：93.590.7Accuracy，越高越好；该任务 RoFormer 反而较低。
Table 5 · CAIL2019-SCM / TestRoFormer-512：68.29%RoFormer-1024：69.79%Accuracy，越高越好；这里同时改变了输入截断长度，不能把 1.50 个百分点的差异全部归因于位置编码。

原论文在 GLUE 多项任务上同时存在收益和退化。上述数字均来自论文自身设置，没有独立复现实验；不同架构、截断长度或预训练语料之间的对比不构成严格的单因素消融。

数学层面

旋转表示让每个 QK 内积对位置的依赖写成 n−m；这是可以直接重算的代数结论。

经验层面

原论文报告 RoFormer 在所评估长文本分类任务上的效果；具体收益依赖数据集、基线与训练条件，不能推出对所有模型都有效。

11 · 长上下文：RoPE 不是扩窗的终点

若模型只在有限的位置范围内训练，直接将位置索引扩大可能带来未见过的旋转相位、注意力分数分布和实际任务质量问题。后续工作围绕“频率与位置该如何缩放”提出不同方法：

方法主要思路不能误读成
原始 RoPE按 mθᵢ 旋转 Q/K上下文窗口无限增长
Position Interpolation（PI）将扩展位置映射回较短的索引范围，例如 m → m/s完全不需训练就无损扩窗
YaRN按旋转维度组合插值策略，并调整注意力尺度只改 max_position_embeddings
LongRoPE对维度和位置采用非均匀插值与渐进式扩展任意 checkpoint 都可获得论文中的长窗口

现代 Transformers 的 RoPE 参数文档还涵盖 default、linear、dynamic、yarn、longrope、llama3 等实现选项；这是软件配置与后续工程体系，不应回溯为 2021 年 RoFormer 的原始算法。

12 · 工程边界：当它进入推理服务

KV Cache

缓存已在正确绝对位置旋转的 K（及未旋转的 V）；新 token 的 Q 用其真实 position_id 旋转。重新使用或偏移 cache 时必须核对索引约定。

布局与精度

交错配对、半维配对不能混用；计算 sin/cos 的 dtype、频率表更新与位置偏移也应与 checkpoint、kernel 对齐。

长上下文

改频率不消除全量 Attention prefill 的二次计算，也不自动减少随序列长度增长的 KV Cache 内存。

评价

在目标长度上比较长文检索、困惑度、短文退化、吞吐/时延，报告模型、缩放参数、训练与推理配置。

最后记住：RoPE 的本体是 Q/K 的多频率二维旋转；相对位移来源于 R(m)ᵀR(n)=R(n−m)；长上下文扩展与推理效率是需要分别评估的后续工程问题。
