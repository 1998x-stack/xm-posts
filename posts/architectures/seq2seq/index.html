PAPER STUDY / ENCODER–DECODER

Understanding Seq2Seq

如果一句英文有 3 个词，却需要 4 个法文词才能表达，神经网络应该如何决定：先读什么、记住什么、何时停止写？

Sutskever, Vinyals & Le · NeurIPS 2014架构脉络 · RNN / LSTM / Attention约 32 分钟
核心思想：把「读完一个变长序列」与「逐步生成另一个变长序列」拆成两个可联合训练的过程。原始 LSTM Seq2Seq 用固定维度上下文向量连接两者；Attention 是后来为改善这条信息通路提出的扩展。

01 · 输入和输出，为什么不必等长？

文本分类会把一整句话映射成一个标签；序列标注通常给每个输入位置一个标签。但机器翻译、摘要与对话要求的是一个新的序列，长度和对齐方式都可能变化。

设输入 x=(x₁,…,x_T)，目标 y=(y₁,…,y_U)，模型学的是整个条件分布 P(y∣x)，而不是预测每个 x 的局部标签。EOS（结束符）让生成长度由模型决定；BOS（起始符）提供解码的第一步输入。

02 · 2014 年的两条重要研究线索

Cho et al.（EMNLP 2014）提出 RNN Encoder–Decoder，将短语编码为固定维向量、再以另一个 RNN 解码，并将其条件概率作为传统短语式 SMT 的特征。这个工作并不等于完整的端到端翻译系统。Sutskever et al.（NeurIPS 2014）则展示深层 LSTM 编码整句并独立生成译文的端到端训练与解码。它们共享 Encoder–Decoder 思路，但具体模型、训练目标在系统中的角色并不完全相同。

Cho et al., 2014

重点：RNN Encoder–Decoder 与短语条件概率，辅助传统 SMT 的重排序/评分管线。

Sutskever et al., 2014

重点：深层 LSTM 从源句映射到译句，独立自回归生成；本篇的主要计算示范以此为基础。

03 · 两个 LSTM，中间一段固定维度信息

Encoder 依次消费源 token 并更新内部状态；读完后产生一个固定大小的句子表示（及相关 LSTM 状态）。Decoder 以此为条件，从 BOS 开始逐步选择目标 token，直到输出 EOS。两者通过整段目标的负对数似然共同训练。

固定维度并不等于固定输入长度。它意味着无论输入 T 是 5 还是 50，编码完成之后的接口尺寸都相同。将两种语言置于不同的时间步循环，模型便不依赖人工对齐的 token 位置。

04 · 生成整句话，其实是一连串条件预测

所谓「给定 x 预测 y」，可以用概率链式法则展开：先决定第一个目标 token，再在已经给出的前缀下预测第二个，依此类推。这里 y<t 表示前 t−1 个目标 token；EOS 也要建模。

EQ 01序列级条件概率的自回归分解
P(y∣x)=∏t=1U+1P(yt∣y<t,c)

U 是目标正文 token 数，另一个时间步用于 EOS；x 与 y 的长度无需相等。

这个分解不要求 Encoder 必须是 LSTM，也不要求固定向量。它定义了很多自回归 seq2seq 模型共有的预测接口：前缀 → 下一个 token 分布。

EQ 04解码步骤的预测分布
pt=softmax(Wst+b)

输出维度为词表大小 V；softmax 对整个目标词表的 logits 归一化。

如果解码状态 sₜ 的维度是 d，输出矩阵 W 可看作 V×d，因而 pₜ 是 V 维分布；具体模型也可能在输出层加入额外投影和权重共享。

05 · LSTM 究竟把什么传到下一步？

普通 RNN 用一个隐藏状态承载历史摘要；LSTM 将记忆细分为 cell state 和 hidden state，并通过门控更新。这里可以先把二者合称「状态」，重点看时间依赖：第 t 步依赖第 t−1 步，不能像全并行的自注意力层一样在时间维上同时完成全部状态更新。

EQ 03编码器与解码器状态的抽象递推
st=fdec(st−1,E(yt−1),c)

这是讲解用的抽象接口，不声称与原论文逐门 LSTM 更新公式逐字相同；c 可通过初始化状态或其他条件注入方式使用。

Encoder 与 Decoder 采用不同参数；Decoder 的输入除了此前的 token embedding，还受到源句表示 c 的条件影响。图中的 f_dec 是抽象接口，实际 LSTM 的输入拼接、初始状态和输出层按具体实现而异。

06 · Teacher Forcing：训练时为什么知道正确的上一个词？

训练样本已提供完整参考译文。因此在计算 P(yₜ∣y<t,x) 时，前缀使用参考答案（ground truth），而不是等待模型自己采样出完整句子。这被称为 Teacher Forcing。实践中可把目标序列右移一位：Decoder 输入为 BOS、y₁、…，训练标签为 y₁、…、EOS。

EQ 02条件对数似然与 Teacher Forcing
L(θ)=−∑t=1U+1logPθ(yt∣y<t,x)

每个训练时间步的条件前缀来自参考译文；Padding 不应计入 token loss。

若 batch 里目标长度不同，训练会在目标维添加 Padding。损失应只聚合实际 token（包括 EOS 的有效位置），否则 Padding 数量会错误地改变样本贡献。

不要混淆：Teacher Forcing 是计算监督条件似然的一种输入方式，不意味着推理时有参考译文；训练/推理前缀分布不匹配会引出 exposure bias 等问题，但不意味着模型一定无法解码。

07 · 推理：贪心与 Beam Search 如何找一整句？

推理先提供 BOS；每一步从词表分布选择下一个 token，再把这一预测作为下一步输入。贪心解码每步只取当下最大概率，未必得到全局概率最高的完整序列。Beam Search 保留 B 条累计得分较高的部分序列，直到 EOS 或长度上限。

EQ 07Beam Search 的累计对数分数
S(y1:t)=∑k=1tlogP(yk∣y<k,x)

这是最朴素的未归一化累计分数；真实搜索系统可能另外采用长度归一化与约束。

未归一化对数概率容易偏爱较短序列（每新增一步通常贡献非正 log 概率）。因此工程实现可能引入长度惩罚、最小长度、EOS 处理及批量化搜索。Beam Search 是推理算法，不是另一种 Encoder–Decoder 架构。

08 · 2014 年一个不直观但有效的技巧：反转源词序

Sutskever 等人发现，仅将源句按词序反转（目标句顺序不变），能显著改善优化。一个直觉解释是：某些原本距离很远的源/目标依赖，在时间展开图中变得更近，梯度需要跨越的递归步数减少。注意不是把自然语言语义本身反转，也不是目标倒序生成。[Sutskever et al., 2014]

这一技巧与后来的双向 Encoder、Attention、Transformer 使用的内容连接方式不同；它不能被推广成「所有现代 seq2seq 都应该反转输入」。

09 · 一条固定维度的接口，真的够吗？

固定向量 c 不是数学上绝对不能表达长句，而是给训练、优化与信息保留带来潜在压力。特别是输入增长、结构更复杂时，Decoder 每一步都从同一个压缩摘要中恢复细节。Bahdanau et al. 明确指出这个固定长度向量可能成为瓶颈，并将该观察发展为可学习的软对齐。

需要同时保留的事实：原始 Sutskever 模型报告在其测试设置下对长句也有可用表现，不能将「存在潜在瓶颈」写成「固定向量 LSTM 一定无法处理长句」。Bahdanau 的对比与结论建立在其模型、数据和长度切片实验上。

10 · Attention：让每个解码步骤拥有自己的上下文

后续模型改为保存 Encoder 的位置级表示 h₁…h_T。解码第 t 个词时，用当前解码状态与每个 hᵢ 打分，沿源位置 softmax 得到 αₜᵢ，再形成加权上下文 cₜ。于是 c 不再是唯一的静态读取接口。

EQ 05Attention 权重在源位置上归一化
αti=exp(eti)∑j=1Texp(etj)

eₜᵢ 是第 t 个 decoder 步与第 i 个源位置之间的可训练匹配分数；αₜᵢ 的 i 维总和为 1。

EQ 06按解码时间步变化的上下文向量
ct=∑i=1Tαtihi

每个 encoder annotation hᵢ∈ℝᵈ，因而 cₜ∈ℝᵈ；解码器不再只能依赖单个静态句向量。

Bahdanau et al.（2014 预印本 / ICLR 2015）引入联合对齐与翻译；Luong et al.（EMNLP 2015）系统讨论 global 和 local Attention。二者与原始 2014 固定向量 LSTM 在时间顺序上需要清楚区分；Attention 不等于 Transformer，后者进一步用自注意力处理序列内部的 token 交互。

12 · 最小实现应该验证哪些计算不变量？

仓库配套 mini_seq2seq.py 是不依赖框架的数值教学示例，而不是 NeurIPS 2014 的大规模 LSTM 复现。它验证：条件概率乘积等于 log 概率之和、Teacher Forcing 的输入/标签正确错位、Padding mask 不计损失、Beam Search 可以与贪心不同。

from mini_seq2seq import shifted_targets, masked_nll
decoder_in, labels = shifted_targets(["je", "suis"], bos="BOS", eos="EOS")
assert decoder_in == ["BOS", "je", "suis"]
assert labels == ["je", "suis", "EOS"]
# 真实多层 LSTM 的 hidden/cell state、嵌入与梯度优化，
# 不属于这个纯标准库数学算例的复现范围。

若用 PyTorch 写一个真正可训练的 Seq2Seq，建议逐一验证 shape：输入 [B,T]、Encoder 状态（含层数、方向）[L,B,H]、Decoder logits [B,U,V]、目标 mask [B,U]，并用固定 seed 的 tiny overfit 测试检查模型能否记住两三对小样本。Attention 版本还要确认源 padding mask 在 softmax 的源位置轴上生效。

13 · 五个最容易混淆的边界

  1. Seq2Seq 不等于 LSTM。它描述序列到序列的条件映射任务与一类 Encoder–Decoder 组织方式，CNN、RNN、Transformer 都能实现。
  2. 原始 Seq2Seq 不自带 Attention。两者是相关但不同的历史阶段；Bahdanau 与 Luong 扩展是后续工作。
  3. Teacher Forcing 不是测试时输入。训练用真实历史前缀；推理递归消费预测前缀。
  4. Beam Search 不保证找到全局最佳序列。有限宽度会剪枝，分数还可能受长度偏置影响。
  5. BLEU 不是无上下文的真理数字。同名指标仍受数据切片、分词、OOV 和系统组合方式影响。

从 LLM Infra 的角度，最重要的延伸是：编码源数据、条件生成以及解码策略是可分离的系统组件。后来的 Transformer 换掉了编码/解码内部的信息通路；在线推理则继续在解码循环上研究 KV Cache、批处理和吞吐优化。
