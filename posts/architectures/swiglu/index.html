Understanding SwiGLU

为什么在 Transformer 的前馈网络里，多画一条分支、做一次逐元素相乘，就可能比单独换一个激活函数更有效？

Noam Shazeer · 2020论文：GLU Variants Improve Transformer约 30 分钟阅读

阅读主线：普通 FFN 只变换一条信号；SwiGLU 让一条信号产生按输入变化的门控因子，逐通道调制另一条信号。 但这不是稀疏 MoE 路由，更不是一个只能输出 0 到 1 的开关。

01 · 为什么要改 FFN，而不是 Attention？

Attention 负责让位置之间交换信息。每个位置拿到混合后的表示后，还需要一个在通道维度上重新组合特征的计算模块——position-wise feed-forward network（FFN）。

2017 年 Transformer 中的经典 FFN，是两次线性变换夹着一次 ReLU。它对每个 token 使用相同的参数，但不同 token 的输入不同，因此输出也不同。2020 年的论文提问：如果让 FFN 的中间特征被另一条、同样由当前输入计算出来的路径调制，会怎样？

这里的“门”不是前序 token 的记忆，也不负责注意力打分；它作用在同一 token 的中间通道上。理解这点，就能避免把 SwiGLU 混同于 LSTM 的时间门控或 MoE 的专家选择。

02 · 先读懂原论文的 ReLU 基线

设输入单个 token 的向量为 x ∈ ℝᵈ，传统 T5 无偏置 FFN 使用 W₁ ∈ ℝᵈˣᵐ 把它展开到宽度 m，经 ReLU 后由 W₂ ∈ ℝᵐˣᵈ 投影回来。ReLU 对负数输出 0，正数保持原值。

换 GELU 或 Swish，只是在同一条中间路径上替换激活函数；GLU 类结构改变的则是计算图本身。论文 §1 的式 (2) 明确采用无偏置基线，这样不同变体的比较口径更清楚。[Shazeer 2020，§1]

03 · 分开计算“提供什么”和“放大什么”

对每个 token，先算两组投影：up/value 分支产生被调制的候选特征 b；gate 分支产生 a，经过 SiLU 后得到可正可负的门控因子。两者逐元素相乘得到隐藏特征 h，然后再次投影。

试着只看一个通道。假设 b = 2，而 gate 的预激活 a = 2，那么 SiLU(2) ≈ 1.762，乘积约 3.523；当 a = -1 时，SiLU(-1) ≈ -0.269，乘积为负。可见它并不是将候选特征简单归一化到 [0,1]。

04 · 论文公式与张量形状逐项对齐

论文中的 Swish 定义为 Swishβ(z) = z·σ(βz)。Transformer FFN 使用 β = 1，这与现代框架常称的 SiLU 是同一个标量函数。

SiLU(z) = z1+e−z
(1)

设批量为 B、序列长 T、模型宽 d、门控隐藏宽 m_g；Wg 和 Wu 都是 d × m_g，Wd 是 m_g × d。那么 SwiGLU-FFN 的无偏置形式就是：

y=(SiLU(xWg)⊙(xWu))Wd
(2)
x∈ℝB×T×d,h∈ℝB×T×mg,y∈ℝB×T×d
(4)

这里的 ⊙ 是逐元素乘，不是矩阵乘；该层对每个位置独立操作，所以不需要像 Attention 那样额外构建因果 Mask。它本身并没有引入跨 token 依赖。论文式 (5) 含可选偏置与 β，式 (6) 的 FFN 实验形式则去掉偏置并使用 Swish₁。[§2，Eqs. 5–6]

05 · 第三组矩阵会不会让模型变胖？

直觉上，两个矩阵变三个矩阵，参数应该增加约一半。论文不直接采用同样的中间宽度，而是压缩门控层的隐藏宽度，以实现匹配的理论参数量与主要矩阵乘计算量。

2dm=3dmg⇒mg=2m3
(3)

以论文 T5 配置 d=768 为例：传统 m=3072，门控 m_g=2048。前者 2×768×3072 = 4,718,592，后者 3×768×2048 = 4,718,592，每个 FFN 的矩阵权重数完全一致。但实际运行速度、显存峰值仍依赖算子融合、activation 保存、batch 和设备，等 FLOPs 不等于任何机器上都等延迟。

06 · GLU、ReGLU、GEGLU、SwiGLU 的共同骨架

所有 GLU 变体都保留“φ(xWg) 与 xWu 相乘，然后 Wd 投影”的骨架。区别在于门控路径的函数 φ：原始 GLU 使用 sigmoid，ReGLU 使用 ReLU，GEGLU 使用 GELU，SwiGLU 使用 Swish₁/SiLU；Bilinear 则不使用额外非线性。

一个容易误解的术语是“门”。sigmoid 门确实在 0 到 1 之间，但 SiLU 的输出既可能为负，也可大于 1。因此 SwiGLU 提供的是由输入决定的乘性调制，并不保证稀疏选择，更没有显式路由或硬件跳过通道的机制。

括号内是四次较短训练的运行间波动；完整训练的右列没有相同的重复试验标准差，不能把短训练的括号套到长训练结果上。它们是 held-out log-perplexity，不是准确率、普通 perplexity 或推理吞吐。下游 GLUE、SuperGLUE、SQuAD 的 dev 表格有任务差异，论文也指出结果存在噪声。[Table 1–4，§3.3]

谨慎解释：这个结果证明的是特定 T5 训练协议下，门控 FFN 是很有竞争力的替换，不是“任何 LLM、任何规模、任何硬件下 SwiGLU 必定最好”的普遍定理。

单个隐藏通道

注意：虽然 SiLU(a) 对大正数近似 a，但它在负半轴并不等于纯粹的 0，也不像 sigmoid 那样总为正。这个乘法让梯度同时依赖 gate/value 两条分支。

09 · 门控带来的反向传播是什么样？

对于一个通道，写 h(a,b)=SiLU(a)b。对 a 求导是 b [σ(a)+aσ(a)(1−σ(a))]，对 b 求导是 SiLU(a)。也就是说，更新 gate 投影参数时会受到另一条 value 分支影响，反过来也一样。

这不是在宣称 SwiGLU 的梯度处处更大或永不消失：SiLU 在负区间的导数可能为负，极小负值区域也会趋近于 0。乘性结构增加了表达方式，也改变了梯度耦合与中间激活分布；稳定性仍然依赖初始化、归一化、优化器和训练数据。

下面的 mini_swiglu.py 用中心差分验证 SiLU 导数，并逐通道检查前向投影。数值微例只能验证公式实现，不能替代大规模语言模型实验。

10 · 用最小代码复现核心计算

在 PyTorch 中通常用三个 bias-free Linear：两个升维投影和一个降维投影；门分支的激活选 torch.nn.functional.silu。如下伪代码与论文式 (6) 在不考虑浮点舍入时等价：

gate = F.silu(w_gate(x))          # [B, T, m_g]
value = w_up(x)                 # [B, T, m_g]
hidden = gate * value           # elementwise product
output = w_down(hidden)         # [B, T, d]

可直接阅读并运行本站的 标准库最小验证代码（无需 GPU）：它还检查 768/3072/2048 的参数匹配、负门控，以及数值梯度。实际训练时还要考虑混合精度、融合算子、模型并行和激活重计算。

11 · 从 2020 年 T5 到现代 LLM

后续 PaLM 明确使用 SwiGLU 作为 MLP 中间激活；LLaMA（2023）也在 decoder-only 架构中采用 SwiGLU，并将中间维度选为约 (2/3)×4d。LLaMA 同时使用 RMSNorm 与 RoPE，不能把一个完整模型与其他模型的质量差异都归因于 SwiGLU。[PaLM] [LLaMA §2.2]

SwiGLU 与 Attention、RoPE、GQA 不承担同一种功能：Attention 混合不同位置的信息；RoPE 给注意力引入相对位置信号；GQA 共享 K/V head；SwiGLU 则在每个位置内部进行按输入变化的通道级调制。想系统连接这些机制，可以继续阅读 Transformer、GQA、Pre-LN vs Post-LN 与 MoE。

12 · 三个最值得纠正的误解

  1. “SwiGLU 就是把 ReLU 换成 Swish”——不对。 它额外加入一条并行线性投影，并在隐藏维度逐元素相乘；仅把 ReLU 换成 Swish 对应论文中的 FFN_Swish，不是 FFN_SwiGLU。
  2. “门控一定输出 0 到 1”——不对。 那是 sigmoid 门的常见属性；SiLU 可负、可大于一，SwiGLU 并不自动产生硬稀疏性。
  3. “参数量匹配就意味着训练/推理完全等成本”——不对。 三路矩阵乘和逐元素运算、张量存储、融合 Kernel 与设备利用率都可能改变实际成本。原论文匹配的是主要参数与计算量。

有些实现把 gate/up 合并为一次大矩阵乘，输出再拆分；只要权重布局和激活乘法顺序一致，这属于实现上的等价优化。也有模型对投影添加偏置或改用其他门控激活，应在模型定义里说明，不能默认与原论文设置完全相同。
