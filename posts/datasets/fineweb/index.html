DATASETS & CURATION / NeurIPS 2024

Understanding FineWeb

为什么拥有更多网页还不够？为什么“删除所有重复”反而可能保留更差的文本？从网页提取、MinHash、启发式筛选到 FineWeb-Edu 的教育质量蒸馏，重走一条可检验的数据工程路线。

Penedo et al. · NeurIPS 2024 Datasets & BenchmarksData Curation / Pretraining约 32 分钟阅读原始论文 PDF ↗

01 · 从一个反直觉问题开始

同样训练 350B tokens，为什么一份更干净、更少重复的网页语料，得到的模型却可能更弱？

在一类经典思路中，我们会先尽可能抓取整个网页，再删除模板、重复和垃圾内容。听起来“全局去重越彻底越好”。FineWeb 的关键实验恰好挑战了这一点：作者把 96 个 Common Crawl 快照做跨快照全局 MinHash 去重，语料缩到约 4T tokens，但在其控制实验中，性能仍明显落后于 RefinedWeb；换成每个快照内部独立去重，得到约 20T tokens，性能反而改善。[1, §3.4, Figs. 3–5]

这不是“重复有益”的笼统口号。决定结果的还有哪份副本被留下、跨时间采样会怎样改变内容分布、训练预算是否足够暴露重复，以及过滤规则究竟删除了什么。

整篇文章只围绕一个问题：如何把网页清洗的经验法则，变成有对照组、可解释、可复查的训练数据决策？

02 · 如何把“好数据”变成可检验的假设

论文使用固定训练配置进行数据消融：保持模型结构、训练 token 预算与评测任务不变，替换单个清洗步骤；主要在早期验证中使用约 1.7B–1.8B 参数量级模型，约 28B tokens 的短程消融，重要配置再延长至 350B tokens。这里的“数据质量”是特定预算、特定评测组上的模型性能代理，不是不依赖任务的绝对标签。[1, §3.1]

  1. Observation某种清洗流程留下的数据比例与实际下游表现并不一致。
  2. Hypothesis跨快照强去重改变保留文档的内容分布；启发式过滤可针对剩余噪声。
  3. Control使用相同模型与相同 sampled training tokens，仅改变一个数据处理环节。
  4. Evidence对照 RefinedWeb、C4 与自建版本；检查训练曲线、原文图注和模型能力边界。

注意：以模型表现筛选数据，会产生“对选定 benchmark 最有效”的偏好；多任务平均分的提升不等于所有领域都提升。

03 · 从 96 次网页抓取到 15T tokens

FineWeb 的原始来源是论文当时的 96 个 Common Crawl 快照，不是单一网页快照。作者从 WARC 抽取正文、执行基础语言与质量过滤、逐快照 MinHash 去重、选择性使用 C4 规则，最后加入自建的三条启发式规则。公开发布版本额外对邮箱地址与公开 IP 作匿名化。[1, §§3.2–3.7]

这三组数量回答不同问题：覆盖范围、可训练语料规模、目标内容取向。只比较最终 token 数，会掩盖作者验证过的质量选择。

04 · 为什么重新提取 HTML 正文

Common Crawl 的 WARC 包含原始网页内容与抓取元数据，WET 提供已提取的文本。作者发现 WET 更易保留导航、页脚和模板碎片，因此改用 trafilatura 对 WARC 提取正文。在 CC-MAIN-2019-18 对照中，WET 文本约 254B tokens，WARC+trafilatura 约 200B tokens，但在固定其他处理的实验下，后者训练结果更好。[1, §3.2, Fig.1]

关键区分：254B vs 200B 是两个提取方案所得的候选数据量，并非模型“学习 token 越少越好”的因果结论；作者也明确指出更高质量正文提取有显著 CPU 成本。

实际工程的第一原则应是保留处理日志：每个快照的输入文档数、抽取失败数、保留 token 数、提取器版本，以及随机抽样质检。否则后续性能差异难以归因。

05 · MinHash：如何近似发现重复文本

先把每个文档分解为词的 5-gram 集合，再通过 MinHash 近似比较两个集合的 Jaccard 相似度。在两份文档的 shingles 集合分别为 A 与 B 时：

EQ 01
J(A,B)=|A∩B||A∪B|

作者采用112 个哈希函数，分为 14 个 band，每个 band 含 8 个值。两文档只要有一个 band 完全匹配，就进入同一近重复候选关系；再通过传递聚类，每簇随机保留一篇。该配置目标是近似检测 75% 相似度附近的文本，不是逐对计算精确 Jaccard 后按 0.75 硬阈值裁剪。[1, §3.4]

EQ 02
Phit(J)=1−(1−Jr)b,r=8,b=14

式 02 是 MinHash/LSH 理想独立性假设下的教学推导；它不等同于 FineWeb 对任意一对文档的实际去重概率，实际实现还受到 tokenization、簇闭包与哈希设计影响。

06 · 为什么全局去重反而可能更差

全局策略从较新快照向较旧快照扫描：如果旧页面与较新快照的页面落入同一簇，旧页面可能被剔除。结果是老快照的保留集分布被扭曲：正常、常被再次收录的页面被删掉，少见的垃圾模板却更容易幸存。作者对 2013-48 快照做了单独调查：原本“保留”的约 31B tokens，其训练效果低于从“移除部分”再做快照内去重得到的约 171B tokens。[1, §3.4, Fig.4]

论文并未证实“一定要保留跨快照重复”。它提出更窄的假设：清除巨大重复簇很有帮助；继续消灭所有低频跨期重复，可能破坏质量/多样性的平衡。最终选择逐快照去重得到约 20T tokens，并对该策略加入后续质量过滤。[1, §3.4, Fig.5]

工程上更重要的问题：你的采样单位是文档、URL、快照还是 token？去重不仅减少记录数，也隐含改变了训练时各类内容出现的概率。

07 · 过滤器不是越严格越好

FineWeb 尝试 C4 规则时发现，强制终止标点的原版过滤虽然能提分，却约删掉三成 token，代价过高。作者保留 C4 的其他部分规则，并利用高低质量语料分布差异设计新启发式，筛出最有效的三条：[1, §§3.5–3.6, Figs.6–8]

判断一条规则是否有价值，不应只问它清掉多少数据，而要问在相同训练预算和模型配置下是否给目标任务带来收益。比如程序代码、诗歌、表格与低资源语言可能天然含有短行或缺少句号；把英文网页指标无差别套到所有语料会产生系统性删除偏差。

EQ 03
Rretain=TafterTbefore

过滤率和模型分数是不同维度；这只是计量恒等式，不是 FineWeb 提供的优化目标函数。

08 · FineWeb-Edu：把大模型判断蒸馏为筛选器

FineWeb-Edu 不只是“更严格的 FineWeb”。作者为约 460,000 篇网页请求 Llama-3-70B-Instruct 依据 0–5 评分标准生成教育价值标签，用其中 410k 训练、50k 验证；冻结 Snowflake-arctic-embed-m 的 embedding/encoder，仅训练线性回归输出头，再把模型得分四舍五入，以 ≥3 选择教育文本。论文报告对教师标签的验证 F1 约为 82%；应用分类器筛选 15T 数据约用 6,000 H100 GPU hours。[1, §4, Appendix F]

最值得注意的是评分 rubric：作者刻意偏向小学至初中知识的解释性内容，而不是仅给最技术化的网页最高分。作者也发行了阈值 ≥2 的更大变体（约 5.4T tokens）。阈值提高可能有利于某些知识/推理指标，却不保证 HellaSwag、PIQA 等任务同步改善。[1, §4] [2]

09 · 到底有哪些实验证据

在论文 §4 的约 1.71B 参数模型、350B training tokens 控制设置中，FineWeb-Edu 相比 FineWeb 在 MMLU 从约 33% 提升至 37%，ARC 从约 46% 提升至 57%。它们分别是 +4 和 +11 个百分点；不能把后者直接称为“+11% 相对增益”。[1, §4, Figs.10–11]

观察控制或证据不可推出的结论
逐快照去重优于全球强去重§3.4，Figs.3–5；对比不同去重粒度与 2013-48 抽样所有数据集都应保留一切跨期副本
FineWeb 过滤链逐步提分§3.2–3.7，Figs.1–9；逐步消融单个阈值跨语种与任务均最优
Edu 增强知识与推理基准§4，Figs.10–11；350B tokens 对齐比较所有下游任务、所有模型尺寸都增益
Edu 改变主题分布§4.1–4.2，Fig.12，Appendix F；Paloma domain perplexity教育数据全面优于广义网页数据

原论文 §4.2 的 Paloma 分析还显示：FineWeb 在较广的网页域更适配，FineWeb-Edu 对 Wikipedia、学术和编程域更适配。高质量没有脱离目标分布的唯一标量。

11 · 如何在自己的语料管道中实现

一个可靠的生产流程至少需要可追踪的输入快照、分阶段过滤日志、固定版本 tokenizer、可重复的抽样/训练消融、隐私与版权风险管理。FineWeb 的生产实现见 DataTrove；下面的纯 Python 片段只演示概率公式与阈值行为，不能替代分布式 MinHash / WARC 提取，更不声称复现了论文训练结果。

def band_hit_probability(jaccard: float, bands=14, rows=8):
    assert 0.0 <= jaccard <= 1.0
    return 1 - (1 - jaccard ** rows) ** bands

teacher_scores = [0, 2, 3, 4, 5, 1, 3, 2]
def select_threshold(scores, minimum):
    return [score for score in scores if score >= minimum]

assert len(select_threshold(teacher_scores, 3)) == 4
assert band_hit_probability(0) == 0.0
assert band_hit_probability(1) == 1.0

仓库含 完整教学测试文件，并在 CI 中执行数值断言。真正大规模应用还应记录 data lineage、URL 去重语义、快照时间权重、近似去重误判率、跨语言偏差与被删除样本审计。

复现实验协议：先选一个公开 crawl，固定两份去重策略与同等 token 预算；保持 tokenizer、model seed、batch、训练步数与评测集一致；输出每步 token retention、sample audit、逐任务曲线与显著性/方差。不要把这个 mini 函数当成 15T 数据处理器。

12 · 局限：训练基准、偏差与治理

评测外推

核心消融主要在小规模模型和有限基准上开展；对更大模型、长训练、后训练交互的外推需要新的控制实验。

选择偏差

评测驱动的过滤容易偏向被优化的一组任务；Edu 的教育性评分偏好不等于所有领域的偏好。

语种与格式

原版以英文网页为中心，英语检测阈值与短行规则不能直接套用中文、代码、表格和少数语言。

重复与记忆

逐快照去重不代表下游训练 token 采样时没有重复；训练数据泄漏与基准污染需要额外验证。

法律与隐私

公开抓取不等同于可无条件使用。论文描述了邮箱和公开 IP 的匿名化，但这不保证消除所有敏感文本或权利问题。

社会与代表性

教育评分会改变政治、文化、商业等主题比例；原论文 §5 还讨论语料中存在的偏见与词关联风险。

截至论文发表时的 15T / 1.3T 是本文研究版本的规模。数据集页面可能随更新增长，不能把更新后统计与 2024 论文结果混为同一次实验。

13 · 把关键机制串起来

  1. 先测抽取正文提取质量比最大化初始 token 数更重要。
  2. 再定粒度MinHash 把表面近重复变成候选簇；跨快照清洗改变时间与内容分布。
  3. 后做过滤对启发式逐项消融，量化保留率与固定预算下的模型效果。
  4. 按任务选集FineWeb 保留广泛网页覆盖；Edu 则以教育知识与解释性为目标做取舍。
  5. 全程留证据指标必须绑定论文版本、token 预算、模型、benchmark 与表/图号。
判断是否读懂 FineWeb 的三个问题：为什么 global dedup 会改变旧快照的数据质量？为什么 0.75 不是一个精确 Jaccard 切刀？为什么 Edu 提高 MMLU 不意味着它比 FineWeb 更适合所有 domain？
