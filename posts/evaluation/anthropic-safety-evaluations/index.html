ANTHROPIC ENGINEERING / EVALUATION SCIENCE

Building Strong Safety Evaluations

从“模型拒绝了多少次”走向“模型在真实风险情境中是否做对了事”：把安全评测拆成构念、场景、评分器、统计与复现五个可审查环节。

官方工程文章 · 2026-11-13主分类：Evaluation / Safety Evaluations约 26 分钟状态：研究草稿

01 · 安全评测究竟要测什么？

能力评测问“模型能不能完成任务”；安全评测问“给定具体情境，模型的回应是否让伤害更可能发生、是否正确地帮助用户，以及潜在伤害有多严重”。这两类评测不能混成一个总分。

Anthropic 的文章从一个常见误区切入：把拒绝率当作安全性的替代指标。拒绝诈骗、钓鱼或恶意操作通常是正确的；但在用户处于危机、寻求求助或提出正当双用途问题时，简单拒绝可能反而是不合适的行为。安全评测必须定义风险领域里的“适当回应”，而不是默认所有敏感主题都应该拒绝。

先定义构念，再设计题目：构念效度（construct validity）关心评分是否真的测量了你声称要测量的行为。一个拒绝率很高的模型，可能只是更容易拒绝，而不一定更安全。

官方文章建议同时测量两类方向：对有害请求的适当处理，以及对良性请求的过度拒绝。两者共同定义了有用且安全的行为边界。

02 · 设计评测：观察性问题与因果问题不能混用

2.1 先说清楚你要回答的问题

“模型在某类请求上表现如何？”是观察性问题；“某个 system prompt 改动是否让模型更安全？”是因果问题。前者可以比较模型行为，后者需要控制设计，例如在同一模型、同一组题目上只改变一个干预变量。否则分数变化无法归因。

2.2 用多轮模拟捕捉渐进式风险

单轮题容易构造，也容易饱和；真实用户可能逐步改变措辞、补充背景、重新包装意图。Anthropic 描述的多轮方案包含：领域专家编写场景规格；固定第一条用户消息；由另一个模型根据被测模型的回答继续扮演用户；被测模型产生 assistant turns；评分器按领域量表审阅整段轨迹。每次运行可从人物、语气、目标和策略的选项中采样，形成不同对话路径。

2.3 量表要覆盖风险，也要覆盖合理帮助

对双用途领域，适当回应往往不是“全部拒绝”：它可以解释合法、低风险的背景知识，同时不提供会显著提升恶意行动能力的操作细节。不同领域需要不同 rubric；领域专家要参与定义边界案例，方法专家则负责抽样、评分和统计设计。

03 · 运行评测：场景、评分器和环境本身都可能失效

3.1 内部效度与难度校准

题目如果已经出现在训练数据中，测到的可能是记忆而不是行为；环境如果泄露答案，模型可能走捷径；评分器如果把格式或关键词当作正确性，模型可能学会迎合评分器。过易的题目会饱和，过难或描述不完整的题目又会把正确答案误判为失败。应先用试运行检查任务难度、数据污染、提示泄漏和 reward hacking 路径。

3.2 评分器必须接受独立校准

把长对话交给 LLM grader 是可扩展的做法，但评分器也会偏向长答案、第一选项或某种措辞；它还可能在解析失败时静默地产生分数。Anthropic 建议把标准拆成原子化的 yes/no 条件，写明什么不算通过，抽样由专家盲标，再比较专家与 grader 的一致程度。对高不确定性样本进行人工复核，并让评分器故障显式失败，而不是静默记分。

3.3 在安全环境里运行

为了测量模型在缺少常规护栏时的基线行为，安全评测有时需要关闭某些默认 safeguards。Anthropic 特别强调：可能触及网络或真实系统的评测，应放在无互联网的沙箱里运行，并进行实时监控，以便在模型偏离预期时立即停止。不能为了“真实感”而让评测环境本身成为新的伤害入口。

04 · 报告结果：分数必须带着不确定性和配置一起出现

预注册（preregistration）要求在看到结果之前写下主要指标、比较对象、数据切片、改善/回归阈值和统计分析计划。Anthropic 在文章中给出的经验性样本量下限是：复杂多轮评测至少约 100 个项目，简单单轮评测至少约 1,000 个项目；模型输出有随机性，因此每个案例还应重复运行并报告分布。这是 Anthropic 的实践建议，不是适用于所有领域的普遍统计定律。

Rappropriate=Nall-turns-passNconversations

这里的分子按“整段对话是否始终适当”计数；只要一个关键轮次出现严重违规，整段轨迹就可能判为失败。

如果要比较两个模型，尽量使用相同项目的 paired comparison，并报告差值的置信区间。还应拆分风险领域、严重程度和对话长度，记录模型版本、system prompt、采样参数、grader 版本、运行日期与偏离预注册的地方。一个汇总百分比不能替代可复现的实验记录。

05 · 交互实验：拒绝不等于适当回应

下面是一个简化的教学场景，用来区分“危险请求”“良性请求”和“多轮语境”。它不是模型安全分类器，也不代表 Anthropic 的内部评分器。

示例判读：帮助用户完成合法的防御性任务，同时不提供规避防护的操作步骤。简单拒绝会造成过度拒绝。

交互结果只是人工写定的教学示例，不调用模型、不输出真实风险建议，也不能用于部署决策。

06 · 最小实现：整段轨迹的通过率

下面的代码只演示“每轮都通过才算整段通过”的聚合逻辑。真实 grader 需要领域量表、人工校准、抽样与版本记录；这个函数本身不能判断自然语言是否安全。

def appropriate_response_rate(transcripts):
    if not transcripts:
        raise ValueError("need at least one transcript")
    passed = 0
    for turns in transcripts:
        if turns and all(t.get("appropriate") is True for t in turns):
            passed += 1
    return passed / len(transcripts)

可以把每轮人工标注后的布尔值送入函数，得到轨迹级通过率。不要把这个数称作“真实安全概率”；它只是在给定样本和 rubric 下的经验比例。

07 · 适用边界与常见误读

  • 安全评测不是能力 benchmark；二者的目标变量不同。
  • 拒绝率只能描述一种行为，不能单独代表安全性。
  • 多轮模拟比单轮更贴近某些真实风险，但仍不能覆盖所有用户行为、语言、产品表面和工具环境。
  • LLM grader 的一致性需要实测；不能因为它输出了分数，就认为分数可信。
  • Anthropic 给出的样本量与报告建议应结合风险严重性、效应大小和统计功效重新评估。
核心原则：先定义“正确行为”，再构造能区分正确与错误的情境；先验证评分器，再相信分数；报告不确定性，而不是只报告漂亮的平均值。
