Understanding BPE

从字符合并到 Token：语言模型如何构建子词词表？

当模型遇到 unhappiness 这样不常见的词时，是把它当成完全陌生的符号，还是能够读出“熟悉的片段”？BPE 的关键不在于猜词义，而在于用数据频次学会一套可复用、可逆的局部合并规则。

01 / THE PROBLEM

机器为什么会被“罕见词”卡住？

传统固定词表的神经机器翻译系统，每个词有一个离散 ID。高频词很好学，但专有名词、复合词与未见过的词会落到词表外；如果统一变成 <unk>，模型丢失了词的内部拼写。Sennrich 等人的问题是：能否保留词的组成信息，而不把每一个可能的完整单词都塞进词表？[S1]

完整词粒度使序列短，却难以覆盖开放词汇；字符粒度覆盖广，却会让序列变长。子词是两者之间的数据驱动折中。

02 / HISTORY & SCOPE

三个 BPE，不是同一份编码表

Gage（1994）提出用于压缩的 Byte Pair Encoding：寻找重复字节对，并替换为当前数据中未使用的字节码；它是压缩方案。Sennrich 等（2016）改造为从词汇表和词频学习子词合并规则，用于开放词汇机器翻译。GPT-2（2019）使用字节作为基础符号，并结合预分词与其它约定构造语言模型 tokenizer。[S1–S4]

这里讲解的 主要是 2016 子词 BPE。页面中的字符级 toy 例子不等同于 GPT-2 生产 tokenizer；更不能把 1994 年的字节替换压缩器称作 GPT-2 tokenizer。

03 / VOCABULARY

为什么最常见的片段值得一个 Token？

如果 est 在训练语料中反复出现在 newest、widest 等词里，把字母 e、s、t 合并成更大单元，可在相关词上减少 token 数。其过程不认识词根：合并的只是统计上的相邻关系，未必恰好等于语言学词素。

新词若仍可拆成基础符号与已学子词，可以不用单一 OOV ID 表示；但字符级 BPE 对训练中从未出现的字符仍可能无法编码。字节级 BPE 的 256 个基础字节解决了这个覆盖问题，代价是某些字符要占多个字节。

04 / LEARNING MERGES

一次训练轮次，到底发生了什么？

把每个训练词展开为字符序列，并附上词尾标记 </w>；用词频加权统计所有相邻符号对。每轮取频率最高者，将它在每个词中的非重叠匹配合并。合并后的字符串成为新的候选子词；重复直到合并预算达到或无法继续。词尾标记避免词内部、词末单位被不加区分地混用。[S1, S2]

  1. **初始化**：每个词是一串基础符号 + 词尾边界。
  2. **统计**：相邻对出现次数乘对应词的语料频率。
  3. **选择**：贪心选出最高频 pair，记录合并顺序。
  4. **替换**：逐词做非重叠合并，并重新统计下一轮。

当频次相同，实际实现需要确定性的 tie-break 约定；本页统一用字典序，和某些生产库的 tie-break、预分词与归一化约定不同。

05 / THE EQUATIONS

从直觉到数学，贪心选择到底最大化什么？

令 V 是本轮去重后的词集合、f(w) 为词频、ca,b(w) 为当前分段中 pair (a,b) 的相邻出现次数（包括尚未处理的重叠候选）。合并规则学习可写成：

01 · 加权相邻对频率
F(a,b)=∑w∈Vf(w)·ca,b(w)
02 · 贪心合并准则
p★=argmaxp∈PF(p)

其中 P 是当前训练分段中所有相邻 pair 的集合；规则 p★ 由最大频次决定。这是局部贪心，不等于直接最大化语言模型似然，也不是全局最优压缩率的证明。

03 · 词表上界（示意）
|VK|≤|V0|+K

初始词表大小为 |V₀|，进行了 K 轮有效合并，每轮最多引入一种新符号。由于特殊 token、词尾标记处理、合并产物与已有字符串可能有重合，数学上用上界比盲目写等号严谨。

04 · 平均 token 数（评估指标）
T=∑w∈Vf(w)·len(encode(w))∑w∈Vf(w)

T 是按原始词频加权的平均输出 token 数（评估度量，非学习目标）；这里 len(encode(w)) 不把仅为教学分界使用的词尾记号作为实际文本 token。词表预算增加往往让平均序列变短，但不保证下游效果线性改善。

06 / TRAIN VS INFER

训练时“数频次”，推理时还要数吗？

训练：输入带词频的语料，输出合并规则列表。编码：对新词先按相同的基础字符和边界预处理，再按照学到的规则优先级合并。解码：把符号表面内容重新拼接，并恢复/删除明确定义的边界标记。若 token ID、标准化或特殊 token 约定不一致，简单拼字符串不一定够用。

“用当前新句子里最频繁的 pair 再训练一遍”是错误的推理流程。每个 checkpoint 的 tokenizer 词表、merge 顺序、归一化与特殊 token 约定，必须与模型训练时匹配。

08 / GPT-2 VARIANT

Byte-level BPE 为什么能覆盖任意 UTF-8 文本？

字符级子词算法若仅见过部分字母或符号，遇到新 Unicode 字符可能仍会 OOV。GPT-2 将 UTF-8 文本表示为字节序列（每个字节 0–255），基础字母表有 256 种可能值；然后对字节映射后的符号学习 BPE merges，并配合正则预分词和特殊 token 规则。因而它不依赖收齐所有 Unicode 字符作为初始词表。[S3, S4]

一个 UTF-8 字符可能跨多个基础 byte，而一个学到的 token 又可能包含多个字节；字符数、字节数、token 数不能互相替代。计算 API 输入预算和模型上下文长度，应使用目标模型的实际 tokenizer。

09 / COMPARISONS

与 WordPiece、Unigram、SentencePiece 的差异

方法主要学习选择边界提醒
BPE反复合并高频相邻符号对经典子词 BPE 与 byte-level 版本不同
WordPiece按词表概率/似然相关评分选择候选不是直接用原始 pair count 排序
Unigram LM从较大候选词表迭代删减，计算分段概率可能存在多种合法分段
SentencePiece一种 tokenizer 工具与训练框架可实现 BPE 或 Unigram，不是第四种合并目标

不同实现还可以对空格、词边界、大小写、Unicode 规范化和特殊 token 采取不同约定。横向比较 tokenizer 质量时，必须同时报告词表、训练语料、模型任务和评估指标，不能只比较切出来的片段看起来是否“像词根”。[S4]

10 / PRIMARY EVIDENCE

原始论文实际验证了什么？

Sennrich, Haddow & Birch（ACL 2016） 研究神经机器翻译中的罕见词与开放词汇问题，并将基于 BPE 的子词方法用于 WMT 2015 英德和英俄翻译。论文摘要报告：与回退词典基线相比，两个任务的 BLEU 提升分别最高可达 1.1 和 1.3（按原文提及的英德、英俄顺序）。它是特定翻译系统与评估设置下的结果，**并非** BPE 对任意语言模型的普遍性能保证。[S1]

重要的逻辑区别：论文显示子词处理有助于当时的罕见词翻译；并未证明当前任何 GPT tokenizer 的 token 效率、生成质量、推理成本都优于其它方案。本文所有词频演示和长短权衡图均是独立教学示例，不冒充 WMT 测量结果。

11 / CODE YOU CAN VERIFY

小到可以亲自验证的 Python 实现

下列标准库实现与交互面板使用同一玩具语料、同一词尾边界、同一字典序 tie-break。它验证合并顺序与简单 round-trip；没有包含批量加速、正则预分词、特殊 token、Unicode 规范化、词表 ID，也不能替代 subword-nmt 或 GPT-2 tokenizer。

from collections import Counter

CORPUS = {"low": 5, "lower": 2, "newest": 6, "widest": 3}

def merge_pair(symbols, pair):
    out, i = [], 0
    while i < len(symbols):
        if i + 1 < len(symbols) and tuple(symbols[i:i+2]) == pair:
            out.append(symbols[i] + symbols[i+1])
            i += 2
        else:
            out.append(symbols[i])
            i += 1
    return out

def train(corpus, steps=12):
    states = {w: list(w) + ["</w>"] for w in corpus}
    rules = []
    for _ in range(steps):
        counts = Counter()
        for word, symbols in states.items():
            counts.update({})  # weighted adjacent occurrences follow
            for pair in zip(symbols, symbols[1:]):
                counts[pair] += corpus[word]
        if not counts:
            break
        pair = sorted(counts, key=lambda x: (-counts[x], x))[0]
        states = {w: merge_pair(s, pair) for w, s in states.items()}
        rules.append(pair)
    return rules

def encode(word, rules):
    symbols = list(word) + ["</w>"]
    for rule in rules:
        symbols = merge_pair(symbols, rule)
    return symbols

if __name__ == "__main__":
    rules = train(CORPUS)
    assert rules[:3] == [("e", "s"), ("es", "t"), ("est", "</w>")]
    assert "".join(encode("lowest", rules)).replace("</w>", "") == "lowest"
    print("BPE toy checks passed")

12 / LIMITS

实际工程中最容易忽略的细节

  • 预分词改变 pair 统计空间。 不同的空格、标点、中文切分和 emoji 预处理会生成不同 merge 表。
  • Unicode 不是 byte。 UTF-8 汉字往往由多字节组成；不能从字符级 toy 图推断真实模型 token ID。
  • 分段不是词义理解。 高频片段可能只是拼写共现，未必等于有意义的语素。
  • 训练与编码必须同规约。 同一规则列表在归一化、标记、特殊 token 处理不一致时也不兼容。
  • 词表规模是工程超参。 大词表可降低部分文本 token 数，却增加 embedding/output 的参数与稀疏统计负担；多语言分配也可能不公平。
  • 边界标记是格式的一部分。 教学 </w> 和 GPT-2 的 byte mapping 不可互换；对照结果必须写明具体 tokenizer 版本。

记住一句话：BPE 学的是“什么片段值得成为一个符号”，不是“哪些片段有词义”；正确 token 化依赖完整且冻结的预处理 + merge 规则。
