Understanding SentencePiece

从原始 Unicode 文本直接学习子词，而不必先为每种语言编写分词器：用可逆空格、两种算法、动态规划与真实论文证据建立完整理解。

Kudo & Richardson · EMNLP 2018 System Demonstrations2026-11-2024 分钟阅读
01 / SENTENCEPIECE

一个分词器为什么要读懂空格？

神经网络消化的是整数 ID；输入却可能是英语、日语、中文或代码。把原始文字变成 ID 的步骤，为什么不应该预先假设每种语言都用空格分词？

传统 NMT 流水线往往先调用外部 word tokenizer，再学习子词；但许多语言根本不通过空格标记词界。更微妙的是：如果先切成 ["Hello","world","."]，就可能丢失标点前后是否原本有空格的信息。

Kudo 与 Richardson（EMNLP 2018） 提出的是一套不要求外部语言特定预分词的系统：直接从原始句子训练子词模型，并把编码、解码与 ID 管理统一起来。[SP01] 这并不意味着“只要叫 SentencePiece，内部一定是 BPE”。

02 / SENTENCEPIECE

从 Normalizer 到 Decoder，四段系统如何衔接？

论文 Section 2 将系统拆为 Normalizer、Trainer、Encoder、Decoder。训练阶段对句子进行一致的规范化、拟合词表；推理阶段沿用同一规范化规则，把文本转成子词 ID，再从 ID 解码到可读文字。[SP02]

词表大小用目标 vocab_size 指定，而不是把“BPE 合并多少次”这一算法专属概念暴露成整个系统的统一参数。特殊符号 <unk>、<s>、</s> 等也拥有需要在训练前约定的 ID。[SP03]

03 / SENTENCEPIECE

空格 ▁ 怎样保存可逆边界？

SentencePiece 把空格转义为可见的 U+2581 字符 ▁，使它参与 piece 分割。解码时，拼接子词片段、恢复空格即可重建归一化后的文本。[SP04]

Equation 01 · 编码再解码可得到归一化后的文本
Decode(Encode(N(x)))=N(x)

这里 N 是 normalization。公式右侧不是未经处理的原始字节：NFKC 归一化、空格整理等规则本身可能改变输入。论文“lossless”的精确定义，是在既定归一化语义下可以还原文本；不要把它写成“任何字节百分百无损恢复”。[SP04][SP10]

工程边界： 词表模型中的 normalize 规则、dummy prefix、特殊 ID、未知字符机制都属于接口契约，不能只存一份 vocab.txt 就假设可还原性一致。
04 / SENTENCEPIECE

BPE 是如何通过重复合并学习片段的？

BPE 逐步将经常共同出现的相邻符号合并成更长片段。它解决的是“如何从基础单位获得子词词表”，SentencePiece 则为 BPE 添加了从原始句子直接学习和统一编码/解码的基础设施。[SP01][SP05]

合并顺序来自训练数据，不是根据每个新句子现场重新估计概率。论文 Section 3.2 描述通过优先队列管理候选合并，将它所考虑的分割算法从朴素反复扫描的 O(N²) 改善为 O(N log N)；这不能直接外推为任何场景下训练总耗时的复杂度。[SP05]

相反，Unigram 不保存同样形式的 merge 规则，而是给各 piece 分配概率，并在可能的分割路径中选择最优者。

05 / SENTENCEPIECE

Unigram：为什么一段文字会有多种切法？

先建立候选子词词表，再为每个候选 piece 估计概率。固定输入 aba，如果词表里包含 a, b, ab, ba，那么 ab | a、a | ba、a | b | a 都是完整分割。[SP06]

Equation 02 · 一条切分路径的分数是各个片段概率的乘积
P(z)=∏i=1kp(zi)

令 z 为切分路径、k 为其片段数、p(zᵢ) 为该 piece 在 Unigram 词表中的概率，则路径分数为概率乘积。三条候选路径分数依次为 0.1134、0.0462、0.03528，最优分割为 ab | a。

训练算法要估计候选 piece 概率并逐步修剪词表。这比把高频单字串直接排成列表复杂得多。原始 SentencePiece 2018 论文把详细 Unigram 机制指向 Kudo 2018 Subword Regularization。[SP06]

06 / SENTENCEPIECE

全局最佳分割为何能用动态规划求出？

令 D(i) 是覆盖前 i 个字符的最高对数路径分数。对于每个以 i 结尾的合法 piece x[j:i]，接在位置 j 的最优前缀后面；对所有合法 j 取最大值即可。[SP06]

Equation 03 · Viterbi 动态规划递推
D(i)=max0≤j<i[D(j)+logp(xj:i)]

初始条件为 D(0)=0；不可达状态取负无穷。对数把概率连乘变成相加，前驱指针可回溯最优路径。这个过程体现了 Viterbi 思想，但本页的 Python 教学核只支持小词表、没有实现原论文的 EM 学习、词表剪枝与 C++ 优化。

07 / SENTENCEPIECE

Subword Regularization 为什么不总用唯一的最佳切法？

在模型训练时，同一个句子的不同子词分段可成为数据扰动。Unigram LM 提供路径分数，让训练可以从合理的候选分割中抽样，而不是只使用一次确定性 Viterbi 输出。[SP07]

Equation 04 · 基于候选路径进行 alpha 指数重加权
Pα(z|x)=P(z)α∑u∈S(x)P(u)α

交互实验：改动路径权重指数 α

同一个 aba，保留相同的三个分段候选，仅改变路径分数指数。这里是可手算的教学模型，不是 SentencePiece 的实际 nbest 搜索实现。

ab | a
58.19%
a | ba
23.71%
a | b | a
18.10%

α 增大，最优路径的质量更集中；α 接近零，已列出的候选更接近等权。

子词采样属于训练时正则化；日常服务中的确定性 Tokenizer 并不要求每次都随机切分。此外，BPE-Dropout 是后续研究，不能倒写成这篇 2018 系统论文的原始机制。[SP11]

08 / SENTENCEPIECE

Unigram 训练只是在数频率吗？

并非如此。典型 Unigram 过程从过完备的候选集合出发，交替估计参数并删去对整体语料建模贡献有限的片段，直至满足词表规模预算；BPE 则主要积累合并规则。两者目标与优化过程不同。[SP06][SP08]

BPE 与 Unigram 的关键区分
方面BPEUnigram LM
核心对象相邻合并与顺序子词概率分布
编码思路按学到的合并规则在候选路径上求最优
随机分段后续 BPE-Dropout 等路径采样 / subword regularization
共有约束归一化、特殊符号、覆盖率、词表预算

官方实现允许选择 model_type、character_coverage 等参数。可选的 byte_fallback 属于实现选项，不能未经检查就宣称论文中的每种模型天然覆盖所有 Unicode 或原始字节。[SP08]

怎样把 SentencePiece 接入生产训练？

稳定的 Tokenizer 不只是一张 piece-ID 表，还包括 Normalizer、模型类型、特殊 ID、字符覆盖和归一化版本。把某版本 Tokenizer 的 ID 与另一版本的 Embedding 权重拼接使用，会改变 ID 语义；这属于需要版本化检查的模型契约。

import sentencepiece as spm
# data.txt: UTF-8，逐行一条文本；以下为 API 使用示意
spm.SentencePieceTrainer.train(
    input="data.txt", model_prefix="toy",
    model_type="unigram", vocab_size=800,
    character_coverage=0.9995
)
sp = spm.SentencePieceProcessor(model_file="toy.model")
ids = sp.encode("Hello 世界", out_type=int)
pieces = sp.encode("Hello 世界", out_type=str)
assert isinstance(ids, list) and isinstance(pieces, list)
print(sp.decode(ids))

不同规模和语言的语料不保证上述词表设置都能成功训练；示意代码不是本文现场复现结果。工程中还应测试 Normalization 的空格、罕见字符、Unicode 兼容字符和 byte fallback 行为，以及跨训练/在线环境的一致性。[SP08][SP10]

关于 SentencePiece 的五个常见误解

  1. SentencePiece = BPE：错误。它还支持 Unigram LM。
  2. 不需要预分词 = 不需要预处理：错误。Normalizer 是系统的一部分。
  3. 无损 = 任意原始字节完整还原：错误。论文讨论的是归一化之后的文本。
  4. 固定词表 = 没有未知字符：错误。还受字符覆盖与可选回退机制约束。
  5. 训练时采样 = 推理时必须随机：错误。正则化与稳定编码是不同选择。

对于 LLM Infra，这些差异会进一步影响 context token 数、Embedding 维度预算、缓存命中与数据处理一致性。但这类工程推论不是 EMNLP 2018 对现代 LLM Serving 的实证指标。

12 / SENTENCEPIECE

一份最小 Python 算例，究竟验证了什么？

仓库中的 mini_unigram_dp.py 以标准库实现玩具词表上的 Viterbi 分段，并用穷举作参考：aba 的最优路径应为 ab | a，权重 0.1134。还验证不同 α 下抽样概率总和为 1、不可达字符返回负无穷。

该代码刻意不声称包含实际 SentencePiece 的 EM 学习、优化数据结构、Unicode 规范化，也不是 KFTT 实验复现。将教学代数与复现实验明确分开，是理解论文和实现的必要步骤。
