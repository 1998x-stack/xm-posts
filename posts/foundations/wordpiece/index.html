RESEARCH NOTE / SCHUSTER & NAKAJIMA 2012 · GNMT 2016 · BERT 2018

Understanding WordPiece

从子词词表到最长匹配：BERT 如何把文本变成 Token？

当一个不常见的单词没有出现在模型词表中时，是否只能交出一个 [UNK]？WordPiece 的思想是让常见片段成为可复用的词表单元；但最容易混淆的是：训练词表时如何选择片段与给新文本编码时如何寻找片段，根本不是同一项操作。

01 / THE QUESTION

一个罕见词，为什么会令整词词表失效？

固定整词词表往往只能保留最常见的若干词。遇到新派生词、姓名或罕见拼写，系统可能将整词映射为一个未知 ID，丢掉可用的字符结构。字符级则能覆盖更多形式，却使 token 序列变长。WordPiece 将单词分解为词表中可重用的子词单元，在词表规模和序列长度之间作工程折中。[1–3]

请注意：un、##aff、##able 是离散符号，而不是三个从外部语义字典查到的“词根”。子词切分可能与词素边界一致，但算法没有形态学正确性的保证。

02 / PROVENANCE

WordPiece 不能只从 BERT 开始讲

Schuster 与 Nakajima（ICASSP 2012）讨论日语和韩语语音搜索中的词片段建模，后续 Google 研究将 WordPiece 用于开放词汇的机器翻译。Wu 等（2016）GNMT 用有限的共同子词集合替代纯整词，缓解稀有词问题。Devlin 等（2018，NAACL 2019）BERT 使用 30,000 大小的 WordPiece 词表来构造模型输入。[1–4]

这篇文章的“主论文”是 2012 年 WordPiece 研究脉络，实际编码代码以公开 BERT tokenizer 为准；训练机制使用明确标注的教学重建，不把未公开的 Google C++ trainer 当作已复现成果。

03 / POSITIONAL VOCAB

## 到底代表什么？

在 BERT 风格的 WordPiece 词表中，hug 是允许出现在预切分单词开头的片段，##s 是只能继续接在单词内部的片段。## 是词表符号约定，不是原始文本中的两个井号。编码一个新词时，首片段用原样查表，后续片段用 ## 加前缀再查。

这种边界只在 BasicTokenizer 已经完成预切分后的单个词内部生效；不同 tokenizer 的空格、标点、大小写和 Unicode 处理不一致，得到的片段也会不同。不能直接把 BERT 的 WordPiece 词表与 GPT-2 byte-level BPE 的词表混用。

04 / WHAT IS KNOWN

训练词表的原始代码，实际公开了吗？

BERT 官方仓库明确指出：当年用于学习新 WordPiece 词表的程序依赖 Google 内部 C++ 库，未作为 BERT 开源代码的一部分提供。官方公开的 WordpieceTokenizer 是编码器，不是词表训练器。Google 相关研究以语言模型似然/词表质量为动机描述 WordPiece 的训练思想，但工程实现细节不能凭空补齐。[2, 5]

因此以下“pair score”展示的是 Hugging Face 教学教程的近似重建：它很适合解释为什么 WordPiece 与“只选最高频 pair”的 BPE 有区别，但不能用它声称完全复原 Google 的训练目标、打分平滑、停止条件、tie-break 或真实 BERT vocabulary。

05 / TEACHING SURROGATE

为什么最高频的 pair，未必先合并？

取一个加权词频 toy corpus：hug:10、pug:5、pun:12、bun:4、hugs:5。初始化字符分段时，首字符不带前缀，后续字符标为 ##u、##g 等。统计符号与相邻对出现频率，再按下式排序：

01 · Hugging Face 教学重建的 pair score
S(a,b)=c(a,b)c(a)·c(b)

c(a,b) 表示在整个加权分段语料中相邻对出现的次数，c(a)、c(b) 表示两个符号各自在当前位置出现的加权次数。它偏好“两个部分各自未必很常出现，却稳定结合”的 pair。该式是教学代理评分，而不是公开可验证的 Google WordPiece trainer 损失函数。[6]

02 · 教学模拟每轮选择最高评分 pair
p★=argmaxp∈PS(p)
04 · 教学示例中的两组实际评分
S(##u,##g)=2036×20=136<120=S(##g,##s)

当把 ##g + ##s 合并为 ##gs 时，需要去掉后半符号的 ##，且新符号仍是词内部片段；语料分段随之更新。选定 pair 后下一轮要重新统计，因为单元频率和邻接关系已经改变。合并时已入词表的旧符号通常仍需保留，和仅在当前训练分段使用的符号集合不同。

06 / INFERENCE ALGORITHM

真正编码时：最长前缀匹配（MaxMatch）

对预切分单词，BERT 的 WordpieceTokenizer 从当前位置向后尝试最长候选；当前不是单词开头时，在候选字符串前加 ##。找到第一个属于词表的最长候选后推进游标，直到全部消耗。这个过程无需重新计算 pair 分数，也不需要历史合并列表。[5, 7]

03 · MaxMatch：选择当前剩余串的最长可用前缀
ti=argmaxt∈Vi,t⊑si|t|

其中 sᵢ 是尚未编码的后缀，Vᵢ 是在当前位置允许使用的词表子集（首片段不带 ##，后续片段需带 ##），符号 ⊑ 表示“是前缀”。

Longest-match-first 是一项局部贪心规则，不等价于全局最少 token 的动态规划。这也是它与使用合并历史回放的传统 BPE 编码逻辑的关键差别。

07 / OOV BEHAVIOR

中途失败为什么整个单词都会变成 [UNK]？

原始 BERT 实现如果在单个预切分单词中途找不到合法子词，会废弃已经找到的局部片段，对整词只返回一个 [UNK]。它也有长度保护：原始 Google 实现默认单词长度超过 200 个字符就回退未知标记。具体阈值可能随实现不同而变化。[5]

WordPiece 不天然保证任意 Unicode 文本可逆；需要有覆盖所需字符的基础词表或显式回退策略。不要将 BERT 的 [UNK] 语义误认为 GPT-2 byte-level BPE 的全字节覆盖。

09 / BERT INTEGRATION

WordPiece 在 BERT 模型里扮演哪一环？

BasicTokenizer 负责清理、按配置折叠大小写和去音调、标点切分及 CJK 边界等；WordpieceTokenizer 逐个处理预分词结果；编码器再把子词映射到词表 ID，并按任务增加 [CLS]、[SEP] 等标记。BERT 论文描述使用约 30,000 大小的 WordPiece 词表。在 Masked LM 训练中，它随机选择 15% 的 WordPiece token 位置作为候选预测位置。[4, 5]

这两个数字属于 BERT 论文设置，不是 WordPiece 算法的数学常量；它们也不意味着每个完整词都有一个独立表示。BERT 的模型参数包括 token embedding、position embedding 与 Transformer 结构，WordPiece 只负责把输入变成可索引的离散序列。

10 / ALGORITHM BOUNDARIES

WordPiece、BPE、Unigram 到底差在哪？

方法训练阶段编码阶段易混淆处
BPE经典形式选择最高频相邻符号对按已学习的合并排名合并频率不是 WordPiece 的教学归一化分数
WordPiece原始目标与实现未完整开源；教学版用相邻对归一化评分只用冻结词表做 MaxMatch编码不回放合并排名
Unigram LM基于概率候选词表做删减与优化选择概率较高分段，可容许多种分段它不是逐对贪心合并
SentencePiece分词工具与训练框架，可训练 BPE / Unigram取决于所选模型与规范化不是 WordPiece 的同义词

公平比较还必须控制训练语料、预分词、Unicode 归一化、特殊标记、词表大小和评价语种。仅凭一个词切出的片段“看起来更像词根”，不能断言语言模型质量更高。[6, 8]

11 / SYSTEMS ANGLE

算法一样，编码速度还能有数量级差别吗？

朴素 MaxMatch 在每一个起点尝试许多候选前缀，复杂度可能随长度呈平方增长。Song 等（EMNLP 2021）Fast WordPiece Tokenization 基于 Trie 与类似 Aho–Corasick 的失败链接，把单词编码算法做到 O(n)，并优化文本的预切分处理。其论文摘要报告，指定测试设置下对 HuggingFace Tokenizers 和 TensorFlow Text 的平均提速分别为 8.2× 与 5.1×。这些数字来自 2021 年论文的系统比较，而不是本文测量结果。[7]

这种加速是在维持 WordPiece tokenization 语义的前提下改进执行路径，并不意味着改了 BERT 的词表训练规则或语言模型架构。

12 / TESTABLE CODE

从 Python 参考核验每一个假设

配套 mini_wordpiece.py 提供两部分：分数导向的可复现实验 trainer（教学重建），以及仿照 BERT 公开实现的最长匹配 encoder（针对已经预切分的单词）。标准库 Fraction 保持示例打分精确；测试覆盖第一轮合并、词表保留、整词 [UNK]、200 字符长度保护及可解码的 toy 输入。

"""WordPiece teaching model: score-based vocabulary growth + exact-style MaxMatch.

Training below is a transparent, deterministic *approximation* from Hugging
Face's educational explanation, NOT the unpublished Google WordPiece trainer.
Encoding follows the greedy longest-match BERT tokenizer logic on one
pre-tokenized word; it is not a replacement for BasicTokenizer.
"""
from __future__ import annotations
from collections import Counter
from fractions import Fraction

CORPUS = {"hug": 10, "pug": 5, "pun": 12, "bun": 4, "hugs": 5}
PREFIX = "##"
UNK = "[UNK]"

def initial(word: str) -> list[str]:
    if not word:
        raise ValueError("word must be nonempty")
    return [word[0]] + [PREFIX + char for char in word[1:]]

def adjacent_counts(states: dict[str, list[str]], frequencies: dict[str, int]):
    symbols: Counter[str] = Counter()
    pairs: Counter[tuple[str, str]] = Counter()
    for word, units in states.items():
        weight = frequencies[word]
        symbols.update({unit: units.count(unit) * weight for unit in set(units)})
        for pair in zip(units, units[1:]):
            pairs[pair] += weight
    return symbols, pairs

def scores(states, frequencies):
    symbols, pairs = adjacent_counts(states, frequencies)
    return {p: Fraction(count, symbols[p[0]] * symbols[p[1]])
            for p, count in pairs.items()}

def combined(a: str, b: str):
    return a + (b[len(PREFIX):] if b.startswith(PREFIX) else b)

def merge(symbols: list[str], pair: tuple[str, str]) -> list[str]:
    result = []
    i = 0
    while i < len(symbols):
        if i + 1 < len(symbols) and (symbols[i], symbols[i+1]) == pair:
            result.append(combined(*pair))
            i += 2
        else:
            result.append(symbols[i])
            i += 1
    return result

def learn_demo(corpus=CORPUS, steps: int = 8):
    if not corpus or steps < 0 or any(not w or n <= 0 for w, n in corpus.items()):
        raise ValueError("nonempty words and positive frequencies are required")
    states = {w: initial(w) for w in corpus}
    vocabulary = {UNK} | {x for units in states.values() for x in units}
    rules = []
    for _ in range(steps):
        score_table = scores(states, corpus)
        if not score_table:
            break
        pair = min(score_table, key=lambda p: (-score_table[p], p))
        rules.append((pair, score_table[pair]))
        vocabulary.add(combined(*pair))
        states = {w: merge(units, pair) for w, units in states.items()}
    return vocabulary, rules, states

DEMO_VOCAB = {
    "[UNK]", "un", "##aff", "##able", "hug", "##s",
    "b", "##u", "##gs", "m",
}

def encode_word(word: str, vocab=DEMO_VOCAB, max_chars: int = 200):
    """BERT-style greedy longest-match-first; failed word -> single [UNK]."""
    if not word or len(word) > max_chars:
        return [UNK]
    output = []
    start = 0
    while start < len(word):
        found = None
        found_end = start
        for end in range(len(word), start, -1):
            part = (PREFIX if start > 0 else "") + word[start:end]
            if part in vocab:
                found = part
                found_end = end
                break
        if found is None:
            return [UNK]
        output.append(found)
        start = found_end
    return output

def detokenize_word(tokens: list[str]):
    if tokens == [UNK]:
        raise ValueError("UNK loses the original surface form")
    return "".join(x.removeprefix(PREFIX) for x in tokens)

if __name__ == "__main__":
    print(encode_word("unaffable"))
    print(encode_word("mug"))

13 / EVIDENCE AND LIMITS

论文证据该如何读，而不误以为“模型能力来自 tokenizer”？

2016 GNMT 在一个完整翻译系统内使用 WordPiece，论文还包含深 LSTM、Attention、Residual、低精度推理和 Beam Search 等不同组成；因此无法把整套系统的翻译提升直接全部归功于 WordPiece。BERT 采用 WordPiece 词表，也不意味着 Masked LM 的成效由 tokenizer 单独引起。[2–4]

本文真正可以核验的事实分为：论文与源码事实（2012 来源、GNMT/BERT 使用、BERT MaxMatch、UNK 行为）、独立推导（教学分数比较和局部贪心选择）、后续系统研究（Fast WordPiece）。对未公开部分保留明确的不确定性，比构造一个看似完整但失实的“原始 WordPiece 复现”更有价值。

最重要的三句话：训练阶段研究词表候选；编码阶段用冻结的 vocabulary 做 longest-match-first；词表外失败和 BasicTokenizer 的行为都必须与目标模型版本对齐。
