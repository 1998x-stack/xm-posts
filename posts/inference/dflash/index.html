Understanding DFlash

单步块扩散、逐层 KV 注入与推测验证

1. 为什么草稿也会成为瓶颈？

假设一个模型正在补全程序的下一行。大模型每输出一个 token 就要经过全部层；经典推测解码把多次目标前向变成一次批量验证，但若小模型仍串行起草，延迟会转移到草稿。低批量 decode 往往受权重读取和 kernel launch 限制，重复调用不一定比一次更宽的调用便宜。

DFlash 的问题不是怎样用扩散模型替代整个 LLM，而是怎样把扩散模型变成一个廉价且准确的预测器。质量由原目标模型负责。

2. 单步块扩散与 anchor

令块长 B=5。目标模型先生成已知 anchor a；草稿输入 [a,M,M,M,M]，一次前向给出四个新候选。块内双向注意力允许 mask 槽交换中间表示，但看不到真实未来 token。原目标模型仍使用因果注意力。原版 DFlash 的块长包括 anchor，因此候选预算 g=B−1，而不是 B。B=16 对应 15 个候选。

这一设计将 g 次串行 draft forward 变为一次 block forward。注意总 FLOPs、KV 读写和验证开销仍随块长变化，不能把一次前向等同于常数时间。

3. 隐藏特征融合与逐层 KV 注入

假设已缓存因果历史长度 N，目标宽度 dₜ，抽取 r 层，每层 H 形状 N×dₜ。沿特征轴拼接并投影到草稿宽度 d，得到 F∈R^{N×d}；当前官方代码还执行归一化。论文通常选取五层目标特征，草稿通常五层，Coder 例外为八层（§5）。

F=Norm(Concat(H1,…,Hr)Wf)

以一个注意力头为例，X∈R^{B×d} 是块表示。Q 只来自 X，K/V 由历史 F 和 X 分别投影再沿序列轴拼接。Q 的形状 B×dₕ；K,V 为 (N+B)×dₕ。每层使用自己的参数，实际多头/GQA 还保留头维，应用位置编码与归一化。

Q=XWQ,K=[F;X]WK
O=softmax(QKTdh+M)V

V 与 K 来源相同，softmax 沿 key 轴，M 在不可见位置为负无穷。每层都可以直接检索融合历史，而不是在第一层融合后等待逐层传播；被缓存的是草稿自己的历史 K/V，不是直接复用目标模型 K/V。

5. 早期 token 的损失为什么更重？

如果第一个候选错误，后面即使都碰巧正确也不能提交。设 k=1 表示第一个 mask 位置，论文 Eq.4 的权重随位置指数衰减（此处用 λ 表示原文 γ，避免与预算符号混淆）。

wk=e−k−1λ

教学实现可用有效位置加权交叉熵之和除以有效权重之和；anchor、padding、越界位置不参与。目标模型和共享 embedding、LM head 冻结，只训练草稿内部。Appendix A.1 对 B=16 采用 λ=7；每序列随机采样 512 个 anchor。可在线抽特征，也可离线预存；后者降低在线目标计算成本却增加存储流量。

6. 验证、bonus 与无损性

以 greedy 为例，target 一次验证 [a,A,B,X,D]，预测依次为 A,B,C,…。第一、二候选匹配，第三失败。提交 A,B 和目标修正 C，把 C 留作下轮 anchor；D 的条件已改变，不能跳过错误继续接受。全部匹配时则追加 target bonus。

非 greedy 时不能简单比较 token 相等。设实际条件提议为 q，目标为 p，提议 x 的接受概率为：

a(x)=min(1,p(x)q(x))

拒绝时从归一化正部 max(0,p−q) 采样。接受质量 min(p,q) 加上残差质量，恰好恢复 p。并行独立采样时 q 是对应槽提议分布；若后续算法引入联合采样或候选选择，必须重新核对真实条件提议。无损指目标分布保持，而非任意随机种子、浮点 kernel 都产生完全相同文本。详见 Speculative Decoding。

7. 接受长度与速度

A 是连续接受的候选数，g 是候选预算。忽略 EOS 与长度截断，τ=E[A+1] 包括新增 target bonus，但不重复计入本轮 anchor。由尾和公式：

τ=∑k=0gP(A≥k)

若每个位置在此前全接受的条件下都有相同接受概率 α，则 P(A≥k)=α 的 k 次幂（不要求无条件独立）。

L=Tdraft+Tverifyτ,η=LtargetL

9. 工程实现与缓存边界

状态机：target prefill → draft forward → target verify → commit/crop → 更新目标特征。对照官方 dflash/model.py 中 dflash_generate 和 attention forward：target cache 仅保留已提交历史，draft cache 裁掉临时块并由新接受的 target features 补充，bonus 尚需在下一轮作为输入。候选未通过时不能保留其临时历史。

性能测试需分别记录 draft/verify 时间、接受长度直方图、TTFT、TPOT、吞吐、峰值显存、EOS 截断与排队等待。大 batch 下验证成本更可能成为瓶颈；长上下文需要考虑历史投影缓存和带宽。当前官方实现还含 DFlash2 等后续变种，不要将它们当成 v1。Speculators 文档也明确区分 DFlash 和 DSpark 的 anchor sampling。

10. 可执行练习

toy_dflash.py 用标准库验证首错边界、可见性、期望提交数和采样残差质量。它不是神经网络或 GPU benchmark。

python posts/inference/dflash/toy_dflash.py
python -m pytest -q tests/test_dflash_toy.py
