Inference & Serving / Speculative Decoding

Understanding DSpark

从并行草稿到半自回归生成，再到置信度驱动的验证预算。

DeepSeek-AI / Peking University · arXiv:2607.05147v1 · 2026-07-06

为什么猜得更多不一定更快？

假设在线服务有 100 条正在生成的请求，每条猜 7 个未来 token，就会产生 700 个候选验证位置。若某些请求在第二个位置被拒绝，后面的计算无法使用。高并发下，这些行还会占据其他请求的计算资源。

草稿模型本身也有两难：逐 token 生成可利用真实前词，但须反复执行网络；一次并行生成节约串行时间，却难以处理块内已经抽样的 token。DSpark 将两个瓶颈分离：以轻量顺序模块提高草稿质量，再按收益分配目标验证预算。[E01]

令 Td 为草稿耗时、Tv 为验证耗时、τ 为每轮平均输出数（包含目标修正或 bonus token），则简化的平均单 token 延迟为：

L=Td+Tvτ

(1)

只提高 τ 不足以证明端到端加速。前置阅读：Understanding Speculative Decoding。

无损推测解码：目标分布如何恢复？

令 q 为 draft 的条件分布，p 为目标条件分布。候选 x 从 q 抽样，以如下概率接受。首次拒绝就丢弃剩余草稿，改从归一化正残差抽样。全部接受则从目标下一位置分布产生 bonus。

α(x)=min(1,p(x)q(x))

(2)

pres(v)=max(0,p(v)−q(v))∑umax(0,p(u)−q(u))

(3)

直接接受的概率质量是 min(p,q)，拒绝总质量是 1−Σmin(p,q)，乘残差分布恰好补齐 max(0,p−q)。因此输出质量逐词等于 p。若 p=q，拒绝分支概率为零，不需要归一化零残差。例 p=(.7,.3)、q=(.5,.5)：直接接受质量 (.5,.3)，剩余 .2 补给 A，恢复 (.7,.3)。无损指精确目标采样分布，不指同一随机种子得到同样文本。[E02]

并行主干：从 DFlash 到 DSpark

令历史上下文长度 N，target 隐藏宽度 dt，抽取 m 层特征，沿特征轴拼接为 [N,m·dt]，投影至草稿隐藏宽度 d 并 RMSNorm。每个草稿层把投影后的上下文 K/V 与草稿块 K/V 沿序列轴拼接。Query 来自 γ 个草稿位置；忽略头维后，注意力分数形状为 [γ,N+γ]。块内可双向访问 mask 表示，但不能读取真实未来目标 token；target 验证仍采用因果注意力。

DSpark 把 anchor 自身也作为预测位置，γ 个输入（anchor 加 γ−1 个 mask）得到 H:[γ,d] 与 U:[γ,V]，V 为词表大小。与 DFlash 一样共享冻结的 target embedding 和 LM head。一次主干调用并不代表 FLOPs 与 γ 无关，而是大网络无需为每次采样重新执行。[E03]

教学例：两个合理续写 of course 与 no problem 各占一半概率。两位置的边缘分布均为均匀，但独立抽样后四个组合各占 .25，其中一半跨模式。需要补充的是对上一实际采样词的依赖，而非仅仅增加独立位置的容量。

半自回归：重主干与轻量顺序头

主干生成 Uk 后，每个位置在基础 logits 上加入依赖前缀的偏置 Bk，再沿词表维归一化。令 x0 为 anchor，x1:k−1 为本轮已采样草稿。

Q(X|x0)=∏k=1γqk(xk|x<k,x0)

(4)

qk=softmax(Uk+Bk)

(5)

B(xk−1,·)=W1[xk−1]W2

(6)

W₁:[V,r]，W₂:[r,V]，论文默认 r=256。完整转移矩阵 V² 参数变成 2Vr；教学词表 V=100000 时由 100 亿降为 5120 万，约 195 倍压缩（只针对转移矩阵）。每步仍有 O(rV) 投影与 O(V) softmax。顺序头只依赖上一个 token，而主干仍提供全部历史信息。[E04]

动手：前一个词改变了什么？

教学设定：基础 logits 为零；匹配词加 +2，另一词加 −2。

course 98.2% · problem 1.8%

RNN 变体

Markov 的块内修正只读上一 token；RNN 将状态 sk−1、上一词嵌入和 hk 拼接成 zk:[2r+d]，以门控更新 r 维状态：g=σ(Wgz)，sk=g⊙sk−1+(1−g)⊙tanh(Wcz)。状态起始为零，输出 W₂ᵀtanh(Woz) 给出 V 维偏置（列向量约定）。它能保留更长块内历史，但串行计算较重；论文默认和生产部署均为 Markov 变体。

置信度：从条件接受率到前缀生存率

我们需要预测 draft 能否被 target 接受，不是 draft 自己的最大 softmax 概率。在同一已知前缀下，候选从 q 抽样，接受概率的期望为：

ck*=∑vmin(pk(v),qk(v))=1−12‖pk−qk‖1

(7)

由 min(a,b)=(a+b−|a−b|)/2 和概率归一化直接得到。在线尚无 p，故论文以 hk 和上一 token 的 Markov embedding 拼接（d+r 维）经线性映射和 sigmoid 估计 ck。注意它没有读取本位置实际抽样值。[E05]

aj=∏i=1jci

(8)

链式法则并不要求各位置接受事件独立。实际分数沿当前草稿路径估计，不等于在未观察任何草稿前对所有路径积分的精确概率。教学 c=(.9,.8,.6,.4)，验证四个位置预计输出 1+.9+.72+.432+.1728=3.2248；只验前两个则为 2.62。

Sequential Temperature Scaling (STS)

神经网络原始分数可能过度自信。在独立验证集上从左至右选择各位置的温度 T>0，将原始 logit z 映射为 sigmoid(z/T)。固定已校准的前缀温度，最小化累计接受概率的 ECE（分箱的预测均值与经验频率之差）。同位置变换单调，但不保证跨位置乘积的全局排名不变。校准改善预算估计，不能取代 rejection sampling。

Hardware-Aware Prefix Scheduler

R 个活跃请求，每个最多 γ 个候选。令 ℓr 为请求 r 验证的草稿长度，ar,j 为第 j 个位置累计生存率。每条请求还需要一个基础目标位置。总验证行数 B 和预计输出 τ 如下：

B=∑r=1R(1+ℓr)

(9)

τ=∑r=1R(1+∑j=1ℓrar,j)

(10)

Θ=τ·SPS(B)

(11)

SPS(B) 指给定验证行数时每秒执行步数，不是 token/s。由尾和公式 E[N]=ΣPr(N≥j)，增加一行的收益恰为 ar,j。固定 B 时，因为同请求的生存率单调不增，跨请求降序取前 K=B−R 个就是最优的固定预算分配（同分优先浅位置）。预算本身变化时则沿该排序路径计算 Θ。论文 Algorithm 1 首次不改善就停止。[E06]

为什么调度策略也会破坏无损性？

接纳决策必须 non-anticipating：不能观察当前待接纳候选的实际值，再决定它是否进入验证，否则实际入选候选不再按 q 分布。尤其 ck+1 使用实际 xk；回看未来置信度后撤销 xk 的 admission 可能引入选择偏差。

Appendix A 的反例：p(A)=.7，q(A)=.5。抽到 A 时才允许验证，A 总被接受；抽到 B 时不验证而重新从 p 抽样。最终输出 A 的概率变成：

P(Y=A)=0.5+0.5×0.7=0.85≠0.7

(12)

即使验证规则本身正确，调度仍能改变输出分布。同步 Algorithm 1 在收益首次不再增加时停止；仅当扫描路径目标单峰时才保证找到全局最大值。现实 SPS 有阶梯与局部极值。[E07]

生产方案使用两步前的置信度预测确定额外容量 K，当前分数仅负责前缀排序的 top-K；因历史预算不依赖当前待验证候选，论文据此在历史曲线上全局搜索，同时兼容 CUDA Graph 与 zero-overhead scheduling。实现应按可见前缀前沿决定入选，不能用当前未来 token 倒推入选事件。[E08]

训练：三个损失为何缺一不可？

冻结目标模型、共享 embedding 与 LM head；随机采样多个 anchor 构造局部草稿块，训练 backbone、顺序头和 confidence head。位置权重 wk=exp(−(k−1)/γ) 让早期位置更重要。训练使用已知序列 token 构造局部条件，而在线需要实际顺序抽样。

(13)

Ltv=∑kwk‖qk−pk‖1

(14)

Lconf=−∑kwk[ck*logck+(1−ck*)log(1−ck)]

(15)

L=0.1Lce+0.9Ltv+1.0Lconf

(16)

论文 Eq.10 使用原始 L1 距离，不包含 1/2；Eq.8 解析接受率中的 1/2 才是 TV 的定义。CE 学数据 token，L1 学整个目标分布，BCE 学接受概率软标签，不可互换。[E09]

实验：如何区分接受长度与实际加速？

统一训练框架和数据下比较 Qwen3-4B/8B/14B 与 Gemma4-12B；Eagle3 TTT horizon 与 DFlash、DSpark block size 对齐为 7，draft 深度分别为 1、5、5。Open-PerfectBlend 提示由各 target 重新生成响应；非 thinking、采样温度 1、chain draft，关闭 scheduler 隔离草稿质量。指标包含 bonus token。[E10]

原论文报告 Qwen3 三个尺度的宏平均接受长度相对 DFlash 增长 16.3%、18.4%、18.3%；相对 Eagle3 增长 30.9%、26.7%、30.0%。这是作者结果，不是本地复现。Figure 2 以已通过前缀为分母统计单步条件接受率，而非累计生存率：位置 1 失败会使所有后续草稿无用，更深的并行主干改善首位预测，顺序头则减少后缀衰减。不同任务和模型的接受率不可直接外推。

生产系统：算法如何落到 GPU？

生产 DeepSeek-V4-Flash/Pro preview 使用三层 MoE 主干、mHC、滑窗 128、Markov 头及最大 γ=5，不是上述离线 Qwen 设置。训练仅跨 worker 传输 target LM head 前的隐藏状态，在草稿 worker 对采样位置恢复 logits；通信尺度由 V 变为 d。anchor-bounded packing 将独立的预测块密集打包，通过 token 级索引维持合法可见范围。[E11]

每条请求验证长度不同，朴素 padding 浪费计算。论文将各请求 token 展平，再由 marker tensor 在稀疏注意力中恢复逻辑依赖，适配 index-attention 与 compress kernel。工程上还应核对 KV commit/rollback、EOS 与请求取消边界，并按实际硬件 profile SPS，而非照搬玩具公式。

限制与监控

调度减少目标验证浪费，但已经执行的全块 draft 成本无法回收。真实 SPS 还受上下文长度、KV cache、通信和 kernel 形状影响。部署应同时测 TTFT、TPOT、有效吞吐、各位置条件接受率、校准误差、草稿耗时、验证行数和 SLA 达成率，而不是只看接受长度。

最小可执行实验

同目录 demo.py 仅依赖 Python 3.11+ 标准库，包含概率质量守恒、累积生存率、前缀排序和选择偏差的确定性断言。它不训练真实模型、不复现 GPU benchmark。

from demo import schedule
lengths, tps = schedule([[.9,.8,.6],[.8,.5,.3]], .2)
assert lengths == [2,1]
assert abs(tps - 2762.5) < 1e-8

运行 python demo.py。训练与模型实现参考 DeepSpec。核心结论：草稿生成、依赖修正、置信度估计、资源分配与目标分布保持是不同职责，不可只优化其中一个指标。
