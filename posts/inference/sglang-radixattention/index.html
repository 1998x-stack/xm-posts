SGLang / RadixAttention：一棵树如何复用成千上万次 Prompt？

结构化语言模型程序反复共享提示前缀，SGLang 用 Radix Tree 保存可复用 KV，并把前端控制流与运行时调度连接起来。

Prefix Caching / LM Programs · 研究生技术精读 · 阅读约 27 分钟 · 2026-11-21

01 · 从一次请求变成一棵共享前缀树

一个 Agent 可能在同一份系统提示下尝试三种路线；一个评测任务可能对每个问题重复使用几十条 few-shot 示例。它们的 prompt 不是三个完全独立的字符串，而是共享大片前缀的计算图。

如果在每次生成调用结束后都丢弃 KV，即使前缀完全相同，下一次仍要重新执行它的 Prefill。SGLang 论文把这个问题和结构化语言模型程序的控制流一起考虑：在多次调用之间共享缓存，同时让用户用更自然的语言原语表达流水线。[SGLang §1–§3]

注意这里的「前缀」是 token、position 和模型上下文语义上的一致，不是相似句子的语义相似度。如果共享的是中间片段而非因果前缀，通常不能直接使用原有 KV。

02 · Radix Tree：边可以是一整串 token

普通 trie 的每条边通常容纳一个符号；Radix Tree 把只有一条路径的连续链压缩成一个可变长边标签。因此已有序列 (SYS, A, X) 与新序列 (SYS, A, Y) 可以在前两个 token 后分叉。插入时若新请求在某条压缩边中途产生分歧，就先拆分该边，然后挂上两个后缀。

m(x,𝒯)=maxp∈𝒯LCP(x,p)
x 是新请求的完整 token 序列，𝒯 是当前可用的缓存序列集合；LCP 返回最长公共前缀 token 数。这是解释性形式化。

匹配得到的前缀 KV 可作为推理状态复用，新请求仅计算剩余 prompt token。对具有重复 few-shot 示例、树搜索或多轮对话的程序，命中机制最直观。对于没有共用前缀的输入，算法仍能运行，但不会凭空创造命中。

hprefix=m|x|
单请求的教学统计；论文全工作负载缓存命中率统计口径需要按真实 token 总量汇总，不等于计算加速比。

这不是向量检索：它比较精确 token 序列，而非计算 embedding cosine similarity。实现时必须保证影响 KV 的上下文配置也一致；多模态内容不能仅凭字符串表面相同就认定缓存等价。

KVl,1:m=Cache(model,x1:m,config)
教学依赖表示；model 包括权重，config 可涉及位置编码、模态、adapter 等。不能只比较人类可见的提示文本。

03 · 为什么要引用计数与叶子淘汰？

论文的 RadixAttention 不是静态字典，而是以 KV Cache 为资源的在线缓存。缓存树由 CPU 管理结构信息，KV tensor 占用实际的 GPU 内存池；已完成的请求并不一定立刻导致其缓存消失，而正在运行请求引用的节点不能被释放。

为什么从叶子开始？父节点可能同时被多个分支共享；先移除无引用叶节点，才能尽可能保留后续请求可能再次命中的共同祖先。论文采用 LRU 加引用计数，但在真实工程中，缓存预算、eviction、并发修改和异构内存层次都会影响性能。

论文 §3 与附录 A 还讨论缓存感知调度：优先处理匹配前缀更长的请求，提高重用机会。不过只按命中率贪心排序可能让不热门请求饥饿，因此不能把该策略解释为在线 SLO 的普适最优解。

04 · SGLang 的另一半：语言程序前端

将 SGLang 等同于 RadixAttention 容易漏掉论文重点。它的前端通过 extend / gen / select / fork / join 等原语表达「生成、选择、分叉、合并」；运行时则可以利用程序结构优化执行。

论文还提出 compressed FSM：在满足特定格式约束且后续若干 token 只有唯一合法路径时，压缩状态机可让已知片段通过更少的模型迭代处理。另一项 API speculative execution 针对只开放黑盒接口的服务，尝试提前生成后续模板片段；这不同于典型的 draft-model speculative decoding，不能把两者混为同一个算法。

06 · 证据和性能必须按原论文口径阅读

SGLang NeurIPS 2024 论文在其评测任务和当时的基线版本下，报告最高 6.4 倍的 throughput 提升。这是跨任务的最佳结果，不是所有模型稳定达到的乘数；其吞吐口径主要是每秒完成的 LM program 数，不应直接当作 tokens/s 或线上 QPS。[§6.1–§6.3]

对多轮聊天和共享 few-shot 的任务，RadixAttention 节约 Prefill；对于长输出占比更高、跨会话共享更少的工作负载，整体加速可能很小。做文章或 Benchmark 时必须固定模型、硬件、输出长度、缓存热度、基线版本和指标单位。

课件里的前缀命中率与真实显存占用/吞吐不是线性关系。长前缀重算代价、decode 主导程度与缓存内存竞争决定系统净收益。

08 · 与前后两篇怎样连接？

  • KV Cache：解释为何历史 KV 可以重用，是数学前置。
  • PagedAttention：管理不连续 KV 块，关注存储布局；不等于自动完成跨请求 Radix 前缀匹配。
  • Continuous Batching：动态组批解决当前活跃集合；RadixAttention 进一步关心谁共享前缀、按什么次序接纳。
  • Sarathi-Serve：侧重长 Prefill 如何避免阻塞 Decode，与前缀缓存是可组合但不同的机制。

从 KV 可缓存 → KV 可分页 → KV 可跨请求复用 → 调度命中友好的请求，是这条知识路线的逻辑顺序。
