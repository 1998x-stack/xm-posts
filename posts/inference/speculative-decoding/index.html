PAPER STUDY · INFERENCE / SERVING

Understanding Speculative Decoding

小模型先猜，大模型批改：为什么一次前向可以确认多个 token，而且最终采样分布仍与大模型一致？从概率质量守恒，走到真实推理延迟。

Leviathan, Kalman & Matias · ICML 2023约 25 分钟Speculative Sampling / Latency

01 · 一次只生成一个 token，慢在哪里？

普通自回归解码是这样工作的：大模型根据当前前缀预测下一个 token，把它追加进前缀，再预测下一个。第 5 步必须等待前 4 步的结果，因而目标模型调用在时间上形成串行链。

在大模型推理中，单步 Decode 可能受权重读取、内存带宽和通信所限。此时 GPU 并不总是把所有算术单元都用满：能否让一次较贵的计算，同时验证多个“可能出现的下一个 token”？

先区分两个概念。 批量验证利用 Transformer 的因果掩码同时算出多个位置各自的下一 token 分布；这不等于大模型已经一次“确定”了未来所有 token。每个草稿能否留下，仍需概率检验。

02 · 小模型是草稿员，大模型是裁判

设目标模型产生分布 p，草稿模型产生分布 q。两者使用相同的词表和相同的已接受前缀。草稿模型较便宜，但允许犯错；目标模型较贵，决定最终输出概率。

  1. 小模型顺序提出 γ 个 token，例如 A、B、C。这里 γ（gamma）是草稿长度。
  2. 大模型用一次支持多位置并行的前向计算，得到每个草稿位置以及额外一个位置的目标分布。
  3. 从左往右检查草稿：遇到第一次拒绝，就在该位置修正；后续猜测全部作废。
  4. 若所有 γ 个草稿都被接受，额外从目标模型的第 γ+1 个位置采一个 bonus token。

这样，每轮至少输出 1 个 token，最多输出 γ+1 个。关键并非“草稿猜中比例很高所以凑合使用”，而是下面的精确采样修正。

03 · 为什么接受 + 纠正之后，分布仍是 p？

先只看一个位置。小模型随机提出 x，概率为 q(x)。若它在目标模型下也足够合理，就保留。接受概率是：

a(x)=min(1,p(x)q(x))

如果 q(x)=0，草稿根本不会提出 x，因此只在 q(x)>0 的候选上使用比值。对于被拒绝的位置，不能简单地重新按 p 采样：这样会重复计算已经通过接受路径输出的概率质量。必须只补齐“目标模型比草稿更需要的那部分”。

r(x)=max(0,p(x)−q(x))∑vmax(0,p(v)−q(v))

这里分母把每个 token 的正差值归一化为概率。假如 p=q，则所有草稿都被接受，根本不会进入修正支路，分母为 0 的情形无需执行修正。

对任意 token x，接受路径贡献的概率恰为 min(p(x),q(x))。总拒绝质量为 ∑max(0,p−q)，因此拒绝后残差路径恰好贡献 max(0,p(x)−q(x))。两者相加：

min(p(x),q(x)) + max(0,p(x)−q(x)) = p(x)。这就是精确分布不变性的核心证明；它不是“性能差不多”的近似论证。

α=∑xmin(p(x),q(x))=1−12∑x|p(x)−q(x)|

单步平均接受率 α 等于两个分布的重叠面积，也等于 1 减去总变差距离。草稿越接近目标，通常越容易一次保留多个 token；但更大、更慢的草稿模型不一定让整体推理更快。

04 · 亲手算一遍三个 token 的例子

这是专门构造的教学例子，并非论文实验数据。词表只有 A、B、C：

token草稿 q目标 p接受质量 min(p,q)正残差 (p−q)₊
A0.60.30.30
B0.30.40.30.1
C0.10.30.10.2
合计1.01.00.70.3

小模型提出 A 时，接受概率为 0.3/0.6=0.5；提出 B 或 C 时，因为 p≥q，接受概率为 1。整体接受概率是 0.7，而拒绝概率是 0.3。

拒绝后，修正分布把 0.1 与 0.2 归一化：B 的概率为 1/3，C 为 2/3。最终 A 的概率为 0.3；B 的概率为 0.3+0.3×(1/3)=0.4；C 的概率为 0.1+0.3×(2/3)=0.3。刚好回到 p=(0.3,0.4,0.3)。

你可以在随文章提供的 最小 Python 算例中运行同样的计算；它精确枚举单个位置的概率质量，并不声称复现真实大模型或 GPU 延迟。

05 · 多个草稿一起验证，为何必须“首次拒绝即停”？

假设草稿是 A→B→C。目标模型评估 B 的分布时，条件前缀包含 A；评估 C 的分布时，前缀包含 A、B。若 B 已被否定，那么 C 对应的那条前缀就不再存在：继续接受 C 会把错误条件下计算的概率当成正确条件。

有拒绝

保留前 n 个被接受的草稿，再从位置 n+1 的残差分布采 1 个修正 token。共输出 n+1 个。

全接受

保留全部 γ 个草稿，再从第 γ+1 个位置的原始目标分布 p 采 bonus token。共输出 γ+1 个。

这里的“并行”主要指大模型对给定完整草稿序列的多个位置同时求条件概率；小草稿模型按原始方法通常仍需自回归生成 γ 步。也存在并行草稿等其他变体，但不是本文主论文的必要前提。

06 · 为什么一次多出几个 token，不等于自动提速？

如果每个草稿在各位置被接受的概率都可近似看成独立同分布，平均值为 α，那么一轮生成 token 数 N 的期望是一个截断几何和：

E[N]=∑k=0γαk=1−αγ+11−α

式中 γ 是每轮草稿数；α 是位置平均接受率。α=1 时该式按极限取 γ+1。原论文用这个简化假设分析趋势；真实解码中接受率会随上下文、位置与任务变化。

再设小模型单步耗时与大模型单步耗时之比为 c，并假设一次目标批量验证能在近似一个目标单步的时间内完成，则理想化加速比：

S≈E[N]1+γc

举例 α=0.75、γ=3、c=0.05：每轮平均 2.734375 个 token；按简化成本模型，加速比约为 2.38×。这只是参数化教学计算，不是任何设备上的 benchmark。

显存、KV cache、张量并行、批量大小、预填充比重与目标验证的实际耗时都会改变结论。推测解码常用来降低单请求 decode 延迟，但也可能增加总计算量，甚至压低高并发 Serving 的吞吐。

09 · 真正落地时，要分清四个误解

误解 A：“输出完全相同”意味着同随机种子每次文字都一样

数学保证是输出的概率分布与目标模型相同，不是不同随机数消费顺序下一定逐 token 相同。有限精度浮点数、近似算子或实现错误可能破坏严格等价；必须用分布测试确认。

误解 B：“草稿越准越好”，所以草稿越大越好

更好的 q 通常提升 α，但模型成本 c 也可能增加。应该优化实际端到端延迟和资源效率，不能只优化 token 接受率。

误解 C：“有一个草稿模型就能直接接到任意采样器”

要让目标和草稿在同一输出词表及相容的采样规则上定义 p、q。温度、top-k/top-p 等变换应在用于接受检验的分布中一致且明确；不能用未调整的 logits 代替实际采样分布。

误解 D：“一次多 token”意味着总计算必然更少

目标模型会计算多个位置，还会做无用的被拒绝路径；草稿本身也有计算和 KV cache 代价。方法利用的是某些硬件条件下的并发余量，而不是普适的 FLOPs 节省。优化场景请分别测首 token 延迟、单请求生成延迟与并发吞吐。
