Understanding A3C

为什么多个各玩各的 Actor，反而能学出更稳定的深度策略？沿着相关性、n-step Return、Advantage 和异步梯度更新，走进 ICML 2016 的 A3C。

Mnih et al. · ICML 2016约 36 分钟Policy Gradient / Actor–Critic / Asynchronous & Parallel RL

01 · 经验为什么会“粘在一起”？

设想一名 Atari 玩家连续看到十帧画面：球、挡板和敌人的位置只移动一点。连续采样并不等于十次独立观测；如果我们直接在这些连续样本上训练深度网络，梯度方向可能高度相关。

DQN 的经验回放通过随机抽取旧样本降低相关性，但它需要额外存储，并更适合可以使用旧策略数据的 off-policy 学习。Mnih 等人的问题是：能否不存 replay memory，也让基于当前策略的 Actor–Critic 学得稳定？原论文 §1、§4 的答案是并行采样，而非更复杂的单个损失函数。[1]

核心直觉：用许多相互独立的环境实例，替代一条连续、局部相关的样本流。A3C 不是“DQN + 更多线程”，而是“在线 Actor–Critic + 异步并行更新”。

02 · 三个 A，分别代表什么？

Asynchronous：每个工作线程都能在自己准备好时更新共享参数，无需等其它线程到达同一 barrier；Advantage：用「这次实际多步回报相对状态均值好多少」校准动作的更新；Actor–Critic：策略概率和状态价值分别承担选择动作与评估状态的职责。

原论文的工作线程共享一个全局参数集合，但在 rollout 开始时把全局参数复制到本地，使用本地网络生成采样、累积梯度，随后异步提交更新，再拉取新参数。不同线程可能正在使用不同版本的权重，因而真实实现存在梯度陈旧性与写入竞争。[1, §4 和补充材料 Algorithm S2]

原论文研究的是单台多核 CPU 上的并行 actor-learners，借鉴 Hogwild! 式异步更新；这与多机参数服务器、同步梯度 AllReduce 都不是同一机制。

03 · Actor 和 Critic 为什么需要共用一段网络？

Actor 输出 π(a|s)，从中抽样动作。Critic 输出状态价值 V(s)，估计按当前策略继续行动能得到多少折扣回报。两者可共享卷积/循环编码层，但头部分别输出动作概率与一个实数。

在 Atari 的前馈版本中，策略头与价值头共享 CNN 隐层；作者也实验了在最后隐层后加入 256 个 LSTM 单元的递归版本。对于连续动作，策略可以建模动作分布，而不是枚举离散 Q 值。[1, §4–§5]

Actor：学习“做什么”

若动作回报高于该状态的平均期望，就提高它的 log probability；反之降低。

Critic：学习“值多少”

把预测 V(s) 拉向多步 bootstrap 回报，以降低策略梯度的方差。

04 · n-step return：奖赏如何跨越多个时间步？

单步 TD 只能直接把当前奖励传播一格；纯 Monte Carlo 则要等到整条轨迹结束。A3C 在一次短 rollout 中使用尽可能长的多步回报，以 Critic 对最后一个非终止状态的价值估计收尾。

Gt(k)=∑i=0k−1γirt+i+γkV(st+k;θv)

Eq. 01 k 是从 t 出发剩余的有效 rollout 步数，γ 为折扣因子，r 为即时奖励；真正终止时令末端的 V 为 0。

实际计算最方便的是从片段结尾逆序递推：先设 R 为 0（真终止）或 V(s_end)（未终止），然后重复 R ← rᵢ + γR。这样同一段轨迹末尾的状态是一步回报，越靠前的状态是更长的回报。[1, §4、Supplementary Algorithm S2]

05 · Advantage：把“好”变成相对判断

假设某个状态的典型回报是 5 分，这次动作带来了 7 分。Actor 应该关心的是比基线多出的 2 分，而非奖励总量 7；用 V(s) 做基线不会直接改变一个与动作无关的基线项的期望策略梯度方向，却能帮助降低方差。

A^t=Gt(k)−V(st;θv)

Eq. 02 Â_t 为训练中的 advantage 估计，不是真实且完全已知的 Q−V；当 V 有误差或参数陈旧时也会带来估计误差。

这是 A3C 里的第二个 A。不要把它直接写成后续 PPO 常见的 GAE(λ)：原论文使用的是前向 n-step 回报的混合长度，GAE 被论文讨论为可能的未来改进。[1, §6]

06 · 策略梯度为什么往优势的方向推？

策略梯度给出一个简洁更新方向：如果优势为正，提高这个动作的对数概率；如果优势为负，压低该动作概率。原论文同时在目标中加入熵奖励，以减缓策略过早塌缩为确定性选择。

∇θlogπ(at|st;θ)A^t+β∇θH(π(·|st))

Eq. 03 这里展示对一个采样时间步的梯度上升方向；在一段 rollout 上累加，熵权重 β 为非负超参数。优势作为该项的采样权重，不对它反向传播到 Actor。

H(π(·|s))=−∑aπ(a|s)logπ(a|s)

Eq. 04 熵越大意味着分布越平坦，并不保证探索质量始终提高；β 过大可能损害最终奖励。

对于负对数似然训练框架，可取损失为策略项的负号、再减去熵奖励。真实梯度应注意 actor/value 共享编码层可能同时接收两头的梯度，避免误用冻结或错把 bootstrap 目标当成可反传的在线标签。

07 · Critic 不选择动作，它学习回归目标

Critic 的任务是用当前值函数逼近多步目标 R。最简单的平方误差是：

LV=12(Gt(k)−V(st))2

Eq. 05 1/2 是方便求导的常见系数。论文给出 Actor 与 Critic 的梯度更新形式；该平方损失为等价的教学表示。

需要注意 bootstrap value 是训练目标，计算 Actor–Critic 损失时通常应当停止其梯度。这不是 DQN 的 target Q network；原版 A3C 不需要把 DQN 的经验回放和周期目标网络照搬进来。

09 · 从 rollout 到共享权重：一个线程在做什么？

  1. 同步本地参数：从共享 θ、θv 拷贝当前权重到 θ′、θ′v。
  2. 收集短轨迹：在独立环境按 π(·|s;θ′) 采样动作，至多运行 t_max 步或提前到达 terminal。
  3. 设置 bootstrap：真终止则 R=0，否则 R=V(s_end;θ′v)。
  4. 反向计算多步回报：对每个时间步求 R 和 R−V(s)，累积策略、价值和熵相关梯度。
  5. 异步更新共享参数：把累积梯度用于全局权重，再循环下一段采样。

这些步骤是对论文 Supplementary Algorithm S2 的原创教学性转述。优化器与线程调度会影响实际复现；严格复现须参照补充材料中的参数和初始化细节，而不是把以下小代码当成完整实现。

# 伪代码：一个 worker，不是可运行训练器
while global_steps < T_max:
    local.load_from(global_model)
    rollout = interact(env, local.policy, at_most=t_max)
    R = 0 if rollout.terminated else local.value(rollout.last_state)
    for transition in reversed(rollout):
        R = transition.reward + gamma * R
        advantage = stop_gradient(R - local.value(transition.state))
        accumulate_actor_gradient(transition, advantage, entropy_beta)
        accumulate_critic_gradient(transition, R)
    async_apply_shared_gradients(global_model)  # 调度可能导致 stale gradients

10 · 为什么要共享 RMSProp 的统计量？

异步更新中，若每个 worker 用不同的预条件统计量，步长会依赖线程各自的历史。作者比较了带动量 SGD、独立统计 RMSProp 和共享统计 RMSProp，发现后者在所测试的 Atari 子集上更稳健，但这不是所有任务的普适最优结论。

g←αg+(1−α)(Δθ)2;θ←θ−ηΔθg+ε

Eq. 06 α 控制历史平方梯度移动平均，Δθ 是本轮累积梯度，η 为学习率；共享版本会跨线程共享 g。此处 g、θ 的乘除按坐标逐元素进行。

共享统计不是“所有 worker 共享同一个 Adam 状态”的历史声明。原论文 §4 使用非中心化 RMSProp，原始实现与现代 PyTorch optimizer API 的细节也需要分开核对。[1, Eq. 1；补充材料 §1]

python posts/reinforcement-learning/a3c/mini_a3c.py
python -m pytest -q tests/test_a3c.py

它仅检验公式与确定性数值，不是 A3C 训练复现或 57 游戏 Benchmark。正式复现还需要多进程环境调度、网络结构、RMSProp 共享统计、随机种子、游戏环境版本与评估协议。

13 · 边界：A3C 何时会失效？

异步与 on-policy 的张力

worker 本地权重可能滞后共享模型，使样本与被更新策略不完全一致；并行减相关性不是消除所有偏差的证明。

样本效率与调试成本

不用 replay 省去了缓冲区，却失去旧轨迹的直接重复利用；非确定性的线程时序也让精确复现更难。

A2C 不是本文原版

同步 Advantage Actor–Critic 汇合 batch 后统一梯度更新，通常更易向量化和调试，但同步屏障是另一种工程选择。

与 PPO / GAE 的关系

PPO 的概率比裁剪与 GAE 的 λ 混合估计不属于 A3C 2016 原算法；它们是相关、可比较而非可混淆的后续技术。

最终因果链：相关的在线数据 → 多独立环境拓宽采样 → n-step 回报加速信用传播 → Critic 降低策略梯度方差 → 熵项维持探索 → 异步共享更新提高多核利用率，同时引入陈旧梯度和系统非确定性。
