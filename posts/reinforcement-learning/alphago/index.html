Understanding AlphaGo

围棋的选择太多，无法一条条推算到底。AlphaGo 如何用神经网络判断「该看哪里、局面有多好」，再让搜索做出最后决定？

Silver et al. · Nature 529 · 2016约 35 分钟Policy / Value / Rollout / APV-MCTS

01 · 为什么靠枚举下不赢棋

把下一步想成一棵不断分叉的树。每多看一层，就要评估更多候选变化。围棋的搜索不只是「算得够不够快」；真正的问题是：能否在有限计算里，把算力分给值得推演的分支？

原论文用围棋约 b≈250 的平均候选宽度与 d≈150 的平均长度，说明粗略的 bd 量级不可能暴力展开。AlphaGo 同时引入两个学习到的偏置：策略网络负责缩窄有效宽度，价值网络负责缩短需要模拟到终局的深度。再用蒙特卡洛树搜索（MCTS）根据反复试探更新优先级。[A01]

理解 AlphaGo 的钥匙：神经网络负责提出可用判断，搜索负责检验和重新分配注意力。不是把「深度学习」和「暴力穷举」简单相加。

02 · 两种网络，两个不同的问题

策略：下一步有多像好棋？

输入含落子方等状态特征的 19×19 棋盘表示，监督策略 pσ(a|s) 输出合法候选动作上的概率分布。在搜索树扩展时，它为边提供先验 P(s,a)，不是最终落子的直接命令。

价值：谁更可能赢？

价值网络 vθ(s) 从当前行动方视角预测最终胜负，输出标量。它可以替代一部分完整终局模拟，但并不等于游戏最优解 v*(s)。

2016 系统还需要 快速 rollout 策略 pπ：它用轻量局部模式快速模拟到棋局结束。不要把它与深层监督策略 pσ、经自对弈得到的 RL 策略 pρ 混为一谈。四者服务于不同阶段。[A02]

03 · 从人类棋谱到自我对弈

第一阶段——模仿专家：论文将 13 层监督策略网络在 KGS 的 3000 万局面上训练，held-out 棋步预测准确率为 57.0%（全部输入特征）；该准确率衡量专家下一手预测，并非对战胜率。[A03]

第二阶段——优化输赢：以 pσ 初始化 pρ，让当前版本与随机抽取的过去版本对弈，按终局输赢进行策略梯度更新；不再把模仿专家等同于最大化获胜概率。论文报告在直接采样落子、无树搜索的对局里，pρ 对 pσ 胜率超过 80%。[A04]

第三阶段——学习看局势：从 pρ 自我对弈中为价值网络生成 3000 万个局面，每局只取一个位置，以缓解相邻状态高度相关导致的过拟合。原论文给出的训练/测试 MSE 为 0.226 / 0.234；这是对应评测集上的模型误差，不是 AlphaGo 整体的胜率。[A05]

第四阶段——加入搜索：运行时把 pσ、vθ、快速 rollout pπ 和 APV-MCTS 组合起来。论文明确指出 pσ 在搜索先验中表现优于较强的 pρ：能找出多样的可选分支，与只优化赢棋概率并非同一目标。[A06]

04 · 三个训练目标，三个问题

以 s 表示当前棋盘及行动方，a 表示合法着法，z 表示该行动方视角的终局标签（赢 +1、输 −1）。

ℒSL=−logpσ(a*|s)
(1)s 是局面；a* 是棋谱中的专家落点，pσ 为监督策略。

这对应论文中的监督最大似然梯度方向。最小化负对数概率，就会提高专家落点的概率；但模仿专家并不能保证自对弈最强。

Δρ∝zt∇ρlogpρ(at|st)
(2)zₜ 由该步轮到的棋手视角决定，赢为 +1、输为 −1；无中途奖励。

这是基于完整对弈结果的 REINFORCE 型更新方向。这里把梯度写成向量记号，等价于论文的参数偏导式；训练时需一致处理双方交替行动所带来的回报符号。

ℒv=(z−vθ(s))2
(3)vθ 预测从局面 s 当前行动方视角的期望赛果，z∈{−1,+1}。

价值网络预测的是用指定自对弈策略继续行棋的结果，而不是训练数据中「有没有类似棋型」的频率。完整算法使用对应的均方误差回归更新。[A04–A05]

05 · 把一次搜索模拟拆成四步

Selection：从当前根节点往下走，选择行动价值 Q 加探索奖励 u 最大的边。Expansion：达到扩展阈值时，为新局面建立边，以策略先验初始化，真实实现中会排队等 GPU 计算。Evaluation：价值网络给局面评分，快速策略则继续玩到终局得到 z。Backup：把返回的结果按玩家视角向上传递，更新访问次数和累计价值。[A07]

准确的 2016 APV-MCTS 比简化教材版复杂：方法部分为 value 与 rollout 分别维护 Nᵥ/Wᵥ 和 Nᵣ/Wᵣ，并用 virtual loss 协调并行搜索。这里的四步是理解路径，不是线程调度或完整 Go 引擎实现。

06 · 从先验到探索：为什么不永远选最高概率

如果只按策略网络 pσ 选择最可能的一步，就没有理由花算力调查次优候选。树搜索改为同时使用 过去模拟的平均质量 Q、策略先验 P 和 探索奖励 u。论文主文用正比式描述，Methods 给出 2016 版本的具体形式：[A08]

u(s,a)=cpuctP(s,a)∑bNr(s,b)1+Nr(s,a)
(4)来自论文 Methods: Search algorithm；Nᵣ 是 rollout 访问统计，不应直接替换成 AlphaGo Zero 的搜索公式。

其中 cpuct 是探索系数，Nᵣ(s,a) 是边 (s,a) 的 rollout 统计，分子是该父节点所有候选的访问次数总和开方。已频繁访问的边探索补偿会降低；高先验但少访问的候选仍能得到机会。注意这个具体式子不能无标注地替换为 AlphaGo Zero 常见的 PUCT 实现。

07 · 价值估计与终局 rollout 如何合成

价值网络能快速估计好坏，却不直接算最终比分；rollout 能真的模拟到结束，却会受快速策略本身的质量影响。论文在正文用一个凸组合解释这种互补：

V(sL)=(1−λ)vθ(sL)+λzL
(5)λ∈[0,1]；原论文正文给出此直觉式，完整异步实现分开维护两类累计量。

实际异步实现需要保存两套累计值及其样本量，再按方法公式合成边的均值：[A09]

Q(s,a)=(1−λ)WvNv+λWrNr
(6)各统计量都以同一 (s,a) 为条件；只有对应次数为正时计算相应均值。

公式 (5) 是一次叶节点估计的直观解释；公式 (6) 是分别统计两类异步返回信号的实现概括。两者不应被误写成「每个叶子总会同步返回两个结果，直接用同一个 N 平均」。最后选棋时，论文采用根节点访问最多的动作：[A07]

a*=argmaxa∈A(s)N(s,a)
(7)不是直接选 pσ 最高、也不是必选瞬时 Q 最大；论文正文给出按访问次数落子。

08 · 两个微型试验：改变权重，搜索如何转向？

实验 A · 谁决定一个局面的分数？

固定教学样本 vθ=+0.60、rollout z=−1.00，改变 λ。λ=0 完全相信价值网络，λ=1 完全相信 rollout。

V = (1 − 0.50) × 0.60 + 0.50 × (−1.00) = −0.20。当前混合后的局面判断偏负。

实验 B · 哪一个分支应该继续计算？

演示树根有三条边，各自 Q、P、Nᵣ 不同。让探索系数 c 从 0.2 变化到 3.0，观察 Q+u 中谁得分最高。它是 只含根节点一次选择 的教学算例，不是围棋模拟。

候选 A：P=0.52，N=16，Q=0.28；B：P=0.23，N=3，Q=0.43；C：P=0.25，N=1，Q=0.14。改变滑块查看完整 Q+u 和被选择的分支。

为匹配论文形式，父节点总 rollout 访问数设为 20；分支数据为教学设定。真正搜索的 Q 会随着回传更新。

10 · AlphaGo Fan、Lee 和 Zero 不是同一个方法

本文的训练数据、双网络与 rollout 公式以 Silver 等，Nature 2016 为核心。随后 AlphaGo Lee 在 2016 年 3 月以 4–1 战胜李世石；2017 的 AlphaGo Zero 则不再使用专家棋谱监督，并改变了模型和搜索过程。AlphaGo Zero 的训练目标、单网络结构和搜索中不使用传统快速 rollout，不能倒灌成 2016 AlphaGo 的设计。[A13]

同一条技术线索串联的是：学习好的先验 → 用树搜索得到更强决策 → 用更好的决策反馈更新学习系统；但每一代的算法细节应单独核验。

11 · 一段可以手算、也可以运行的最小代码

下方代码只检验公式与「轮到谁行动」的符号约定，不实现围棋规则、神经网络训练、并行虚损或完整 APV-MCTS。仓库包含可直接执行的 mini_alphago.py 及单元测试。

"""Illustrative AlphaGo 2016 search arithmetic, NOT a complete Go engine."""
from math import sqrt
from typing import Sequence

def mixed_value(network_value: float, rollout_outcome: float, lam: float) -> float:
    """Convex mix in [-1, 1], viewed by the player to move at the leaf."""
    if not 0 <= lam <= 1:
        raise ValueError("lambda must be in [0, 1]")
    return (1.0 - lam) * network_value + lam * rollout_outcome

def puct_score(q: float, prior: float, edge_rollout_visits: int,
               parent_rollout_visits: int, c_puct: float) -> float:
    """Eq. in Silver et al. (2016) Methods; counts are rollout counts N_r."""
    if edge_rollout_visits < 0 or parent_rollout_visits < 0:
        raise ValueError("visits must be nonnegative")
    return q + c_puct * prior * sqrt(parent_rollout_visits) / (1 + edge_rollout_visits)

def select_most_visited(visits: dict[str, int]) -> str:
    """2016 paper: play root move with most visits (lexical tie break for demo)."""
    if not visits:
        raise ValueError("at least one legal action required")
    return max(sorted(visits), key=lambda action: visits[action])

def backup_alternating_players(path: Sequence[str], value_at_leaf: float) -> dict[str, float]:
    """Return parent-perspective action values for one simulation on a single path."""
    result = {}
    value = value_at_leaf
    for edge in reversed(path):
        value = -value  # each parent is the opponent of its child
        result[edge] = value
    return result

def _self_test() -> None:
    assert mixed_value(0.6, -1.0, 0.5) == -0.2 or abs(mixed_value(0.6, -1.0, 0.5) + 0.2) < 1e-12
    assert mixed_value(0.6, -1.0, 0.0) == 0.6
    assert mixed_value(0.6, -1.0, 1.0) == -1.0
    assert abs(puct_score(0.2, 0.5, 3, 16, 2) - 0.7) < 1e-12
    assert select_most_visited({"A": 13, "B": 24, "C": 2}) == "B"
    assert backup_alternating_players(["root-A", "A-B"], 0.75) == {"A-B": -0.75, "root-A": 0.75}
    print("AlphaGo teaching arithmetic checks passed")

if __name__ == "__main__":
    _self_test()

本地执行 python posts/reinforcement-learning/alphago/mini_alphago.py；关键断言包含 λ 的端点、PUCT 对访问次数的响应，以及树边向上回传时玩家视角交替翻转。它们用于算术核查，不是原论文胜率复现。

12 · 哪些事情不能从 AlphaGo 推出来

模型好 ≠ 不需要搜索。单独的策略网络、价值网络和完整系统应分开评估；反过来，搜索也需要精确先验、估值和足够算力才能工作。论文中的 99.8% ≠ 对人类专业棋手 99.8% 胜率。这是对特定程序集合、指定对局设置的胜率。

在两方零和游戏里，价值符号必须遵循行动方视角。叶节点对当前玩家有利，未必对其父节点玩家有利；实现 backup 时忽略轮换符号，会把有利分支错误回传成敌方的收益。

推理预算是系统变量。搜索线程、CPU rollout、GPU 网络评估以及延迟预算共同决定落子质量。2016 原论文单机使用 40 搜索线程、48 CPUs、8 GPUs；更大分布式版本的资源不应误写为「单机配置」。[A14]

读完应能解释：为何需要 P、Q、N 三类边统计；为什么训练时的 RL 策略不直接替代搜索先验；为何同一次搜索要融合 vθ 和 rollout；以及为什么 Root 选择看访问次数。
