Understanding DDPG

机器人每个关节都能施加连续力矩，为什么不能继续用 DQN 逐个比较动作？从一条可微的动作通路，理解 Actor–Critic 如何学习连续控制。

Lillicrap et al. · arXiv 2015 / ICLR 2016约 32 分钟Continuous Control / Off-policy / Actor–Critic

01 · 不是所有动作都能列成清单

想象给七关节机械臂施加力矩。我们可以粗暴地把每个关节只分成「负、零、正」三档；但仅仅这三档，组合数就已经是 3⁷ = 2,187。如果每个关节都能取连续实数，枚举更无法进行。

在 《Continuous control with deep reinforcement learning》 的引言中，作者正是用七自由度、每维三种离散动作的例子揭示问题。DQN 适用于较小的离散动作集合；一旦动作是连续向量，求 Q 的最大动作通常意味着每一步都要在连续空间做额外优化。而把连续动作粗糙离散化，又丢失了动作空间的邻近关系。

核心问题从「如何选择最大的离散 Q 值？」变成「能不能学一个函数，直接把状态映射到有用的连续动作？」DDPG 的答案是：Actor 产生动作，Critic 告诉 Actor 怎样改动作更有利。

02 · DDPG：让 Actor 替代动作上的 argmax

DDPG 的思想连接了两条研究线索：Silver 等人在 ICML 2014 提出的 Deterministic Policy Gradient（DPG），以及 DQN 里稳定学习 Q 值的经验回放、目标网络。DDPG 并非把 DQN 的离散动作头直接改成实数头，而是把控制任务分成两种可微的职责。

Actor μθ(s)

接受状态 s ∈ ℝdₛ，产生动作 a ∈ ℝdₐ。它不输出动作概率分布，评估时同一状态给出同一动作（除非环境或网络本身含随机机制）。

Critic Qφ(s,a)

同时接收状态和动作，估计遵循当前策略时的折扣累计回报。输出是一个标量，允许对动作 a 求导。

在线 Actor 与在线 Critic 都要学习，另有各自的目标副本负责生成相对平稳的 TD 监督信号。这是四套网络参数，并不是四个独立控制策略。其名称中的 deep 主要表示它使用深度网络逼近 Actor/Critic。

形状追踪：一个 batch 的状态是 [B, dₛ]，Actor 动作是 [B, dₐ]；Critic 拼接或融合状态与动作后给出 [B, 1]，训练代码有时展平成 [B]。不能把 Critic 误解成只给每个离散动作打分的 DQN 输出头。

03 · 一条可微的动作路径就是梯度

假设 Critic 对某状态判断：力矩稍微大一点，未来奖励会更高。那么不必在无限多动作中逐项搜索，Actor 只需要问 Critic 对动作的斜率，然后让自己的参数朝提高 Q 的方向移动。由于动作本身由 Actor 参数决定，链式法则正好把两段导数接起来。

∇θJ≈𝔼s∼𝒟[∇aQφ(s,a)|a=μθ(s)·∇θμθ(s)]
Eq 01 · 原论文 §3 Eq.(6)θ 为 Actor 参数，φ 为 Critic 参数，𝒟 表示重放样本的状态分布。导数是链式法则，Critic 参数在 Actor 更新中固定。
STEP 1

给定采样状态 s，Actor 计算 a = μθ(s)。

STEP 2

Critic 计算 Qφ(s,a)；对输入动作求偏导 ∂Q/∂a，而不是对环境动力学求导。

STEP 3

通过 ∂a/∂θ 把价值梯度传回 Actor。实际可用 actor_loss = −mean(Q(s, actor(s))) 做梯度下降。

这条导数成立的前提是 Actor 和 Critic 作为函数对动作可微，且 Q 的估计足够有用。梯度方向正确并不等于 Critic 数值一定可信；如果 Critic 制造了虚假的高值峰，Actor 会忠实地追逐这个错误。DDPG 也无法由此获得任意非凸深度网络的收敛保证。

严格性边界：原论文 §3 Eq.(6) 采用经验状态分布上的近似梯度；它引用 2014 年的 DPG 理论，但神经网络函数逼近、有限 replay 与优化误差会影响实际更新。别把示意箭头理解为策略总能单调改进。

04 · Critic 如何给动作打分？

只有 Actor 产生动作还不够。Critic 需要从真实交互中学会：在状态 s 做动作 a 得到即时奖励 r，之后沿当前策略继续，累计回报大约是多少。贝尔曼递推正好构成一次监督目标。

从经验缓存抽一组真实转移 (sᵢ, aᵢ, rᵢ, sᵢ′, dᵢ)。dᵢ=1 表示 MDP 的真实终止；如果只是由于训练器的时间上限截断，是否 bootstrap 取决于环境语义，不能一律当作结束。

yi=ri+γ(1−di)Qφ′(si′,μθ′(si′))
Eq 02 · 原论文 Algorithm 1 + 现代终止处理撇号表示缓慢更新的目标网络；d=1 表示真正的环境终止，目标值此时只剩即时奖励。d 项是现代实现的显式写法。
ℒ(φ)=1N∑i=1N(Qφ(si,ai)−yi)2
Eq 03 · 原论文 Algorithm 1Qφ 用回放中真实发生的 (s,a) 估值；y 用目标网络计算并停止反向传播。N 是 mini-batch 中的样本数。

请注意两个不对称的位置：在线 Critic 估计 Q(sᵢ,aᵢ)，这里的动作来自缓存里真实执行过的行为；目标 Actor 在下一状态产生 μ′(sᵢ′)，再由目标 Critic 评价它。把这两个动作混为一谈，会让训练目标不再对应原算法。

终止掩码不在原始 Algorithm 1 的简化四元组符号里出现，但现代环境 API 通常必须区分 terminal 与 time-limit truncation。目标值在真正终止后不应该再估算未来 Q；这属于严谨实现的补充，不要误认为是论文里的新模块。

05 · 为什么刚发生的经验要先放进缓存？

相邻时间步的机器人状态高度相关：刚向左偏一点，下一帧大概率仍在左侧。如果每产生一帧就只用最新一帧训练神经网络，梯度会被相似样本连续牵引。经验回放把顺序采集转为随机 mini-batch 更新，也让已经采集的交互得以多次使用。

行为策略 β

与环境实际交互。这里是确定性 Actor 加探索噪声；缓存里出现的动作不必等于当前 Actor 如今对相同状态的输出。

目标策略 μ

在 Critic 的 TD 目标及 Actor 更新中出现。DDPG 是 off-policy：可从旧经验训练，但仍受状态覆盖范围和估值偏差约束。

原论文 §3 指出缓存容量有限，满后丢弃较旧样本，每步从缓冲区均匀抽样。Off-policy 并不意味着任何分布外数据都可安全利用：如果 Actor 一直选回放中未出现过的动作，Critic 的外推误差会放大，出现典型的 bootstrapping + function approximation + off-policy 风险。

06 · 两套目标网络，让老师不要每秒换答案

如果 Critic 的预测 Q 既是学习者、又立刻被拿来给自己创建监督目标，优化器每更新一步，下一步的目标也会猛变。DDPG 复制 Actor 与 Critic 各一份，目标网络只慢慢追随在线参数，避免 TD 目标每次都瞬间跳到最新状态。

θ′←τθ+(1−τ)θ′,0<τ≪1
Eq 04 · 原论文 §3 / Algorithm 1同一式子分别用于 Actor θ 和 Critic φ。论文使用小 τ；Spinning Up 使用接近 1 的系数 ρ=1−τ，别把两个符号混为一谈。

一个数值例子：在线参数是 10、目标参数是 0、τ=0.01，则更新后目标只有 0.1。这不是「只训练目标网络的 1%」，而是每次把目标参数朝在线参数移动 1%。Critic 和 Actor 的目标副本都要更新，缺一者会让 bootstrap 目标的动作或评分漂移。

系数约定易混淆：原论文写 τ·online + (1−τ)·target（τ 很小）；Spinning Up 写 ρ·target + (1−ρ)·online（ρ 接近 1）。两者等价，但不能照搬数值而不检查定义。

07 · Actor 是确定的，它怎么探索？

如果当前 Actor 每次面对同一状态都给出同一动作，探索空间会很窄。DDPG 让行为策略在 Actor 的动作上额外叠加噪声，在环境中尝试不同力矩，再用回放数据学习；评价时通常关掉噪声，单独考察学会的策略。

at=clip(μθ(st)+𝒩t,amin,amax)
Eq 05 · 原论文 Eq.(7) 与动作边界论文 Eq.(7) 为 μ(s)+𝒩；这里额外写出常用环境动作边界裁剪。𝒩 是行为策略的探索噪声，不是 TD3 的 target smoothing。

Ornstein–Uhlenbeck（OU）过程有时间连续性：本次噪声与上一次有关，还受到向均值回归的趋势，适合表达有惯性系统中的平滑扰动。但这只是论文当时的探索设计，不是 DDPG 定义所必需的唯一噪声形式。Spinning Up 的现代教学实现使用高斯噪声，甚至先采一段随机动作以改善初始覆盖。

避免三种混淆：训练采集阶段的行为噪声、评估阶段去噪的动作、以及后续 TD3 为目标值构建加入的 target policy smoothing noise。最后一项不是原始 DDPG Algorithm 1 的操作。

08 · 你来计算 Critic 的监督信号

单步目标只依赖即时奖励、折扣系数、下一状态经目标网络给出的 Q，以及是否真正终止。调整数值，观察同一动作转移究竟给 Critic 一个怎样的学习目标。

Bellman target laboratory

默认是教学示例：r=1.00、γ=0.90、Q′=4.00、未终止，则 y=4.60。它不是论文中的仿真实验数据。

非终止转移 · y = 1.00 + 0.90 × 4.00 = 4.60。若在线参数=10、目标参数=0，本次 soft update 后目标为 0.10。

当切换为真正终止，bootstrap 被掩掉，y 会等于 r；这并不意味着 γ 或 Q′ 永远无用。调整 τ 时，目标网络更新的滞后程度变化，但 Bellman 目标不因此在当前一步立刻被重新定义——示例把两项刻意分开显示。

09 · 把所有小模块接成完整训练循环

现在可把 Algorithm 1 压缩成六个依赖顺序：先交互，再存储，然后算目标、更新两个在线网络，最后轻轻移动目标网络。注意：Critic 的动作样本和 Actor 的当前预测动作使用的是同一批状态、两条不同计算通路。

01 · 采集

在状态 s 执行 μ(s)+噪声；环境返回 r、s′ 及终止信号。

02 · 存储

将 (s,a,r,s′,d) 放入有限 Replay Buffer。

03 · 目标

从缓存随机采 N 条，计算每条的 y = r+γ(1−d)Q′(s′,μ′(s′))。

04 · Critic

最小化 Q(s,a) 与 y 的批均方误差；目标值不对目标网络反向传播。

05 · Actor

使用缓存的状态 s，但把 Actor 重新输出的 μ(s) 送入 Critic，最大化 Q(s,μ(s))。

06 · 更新副本

Actor 和 Critic 两套目标参数分别做 Polyak 平滑。下一时间步继续。

这套过程与典型 on-policy PPO 的反复 rollout→丢弃旧轨迹不同：DDPG 的 Replay Buffer 保留了早前的转移。但对比不应简单简化为「DDPG 一定更样本高效 / PPO 一定更稳定」；任务、网络、探索和评测协议都决定实际表现。

10 · 论文实际证明了什么？

原论文在 MuJoCo 等物理任务上测试了二十多个连续控制问题，既有低维状态输入，也有像素输入。视觉实验把连续三帧 RGB 的每帧缩放到 64×64，并使用重复动作来帮助推断运动。论文报告的是特定环境与当时实验设定，并非对所有连续控制任务的通用保证。

11 · 用可验算代码检查关键数学

真正重现论文需要神经网络、环境交互、Replay Buffer 和完整评估协议；下面的标准库算例只核验更基础且容易犯错的东西：终止掩码、Critic 的均方误差、软目标更新，以及 Actor 梯度是否等于数值差分。

def bellman_target(r, gamma, q_next, terminal):
    return r + gamma * (0.0 if terminal else q_next)

def soft_update(target, online, tau):
    return tau * online + (1.0 - tau) * target

# 玩具 Actor: a = theta * s
# 玩具 Critic: Q(s,a) = -(a-0.5*s)**2
def actor_grad(s, theta):
    a = theta * s
    return -2.0 * (a - 0.5 * s) * s

assert abs(bellman_target(1.0, .99, 4.0, False)-4.96) < 1e-12
assert bellman_target(1.0, .99, 4.0, True) == 1.0
assert abs(soft_update(0.0, 10.0, .01)-.10) < 1e-12
assert abs(actor_grad(2.0, .2)-2.4) < 1e-12

完整可执行脚本还包含有限差分校验、均匀抽样与 OU 一步离散化：mini_ddpg.py。它验证公式自洽，不会宣称重新训练得到论文 Table 1 的成绩。

12 · DDPG 为什么后来要演进？

DDPG 是连接 DQN 式稳定技巧与连续动作策略梯度的重要基线，但它把 Actor 完全交给单个 Critic 引导，估值偏差会被 Actor 利用；探索也依赖外加动作噪声，对随机种子和超参数敏感。它还有确定性策略本身覆盖不足的问题；用经验回放不能自动消除分布外动作的误估。

TD3 · 2018

在 DDPG 基础上引入双 Critic 取较小目标、延迟 Actor 更新和 target policy smoothing，专门缓解值函数高估及脆弱峰值问题。它们不是原始 DDPG 论文的组件。

SAC · 2018

改用随机策略与熵正则化，目标中显式奖励策略的探索性，形成另一条 off-policy Actor–Critic 连续控制路线；不要把它的熵项套回 DDPG 方程。

几个工程边界要单独检查：不同动作坐标的缩放和 tanh 裁剪、terminal 与 truncation、Critic 更新时 target 梯度隔离、Actor 更新时 Q 参数冻结但保留动作梯度、更新比率与 replay 初期分布、观测归一化，以及评估时关闭探索噪声。任何一个小错误都可能让数值看似正常、控制表现却很差。

记住一个因果链：连续动作不易枚举 → Actor 直接输出动作 → Critic 提供可微的学习方向 → Replay 降低序列相关且复用经验 → 双目标网络抑制 bootstrap 漂移 → 噪声补足行为探索。它解释了 DDPG 能运作的机制，也提示了不稳定性的来源。
