Understanding B+ Tree

为什么数据库能同时高效处理点查与范围查询？从一页装多少分隔键开始，推导有序叶链、分裂与合并，最后接到真实数据库的页管理和并发语义。

Bayer–McCreight · B-tree（1970 / 1972）预计阅读 32 分钟有序索引 · 页式存储

01 · 问题：索引为何不能只用二叉树？

把一亿条记录按键排序，既要尽快找到 user_id = 27，也要读出 created_at 落在一段时间内的所有记录。内存二叉搜索树最多只有两个孩子；当索引跨越许多磁盘页时，比较次数不是唯一成本，页访问次数更重要。

B+ Tree 的核心选择是：让每个节点恰好适配一个存储页，节点容纳许多分隔键和子页指针，降低树高；所有可检索条目都留在按序排列的叶页中，并通过叶子间的链接支持范围扫描。这是一种页组织与有序检索技术，不是机器学习的 Decision Tree。

历史边界必须先说清：Bayer 与 McCreight（1972）奠定了多路平衡 B-tree 索引的经典基础；本文讨论的是数据库里广泛使用的 B+ tree 变体，并不声称 1972 论文使用了本文所有叶链细节。

02 · 一页两种角色：路由与承载

内部页只需为路由提供 separator key + child page ID；典型二级索引的叶子条目则是 索引键 + 行定位信息，例如指向表记录的位置。对于聚簇索引，叶子也可能包含完整记录；不能把“叶子必定存完整行”当成普适规则。

内部节点（Internal）

存多个有序分隔键和子指针；我们的教学约定是 key < separator 走左侧，等于分隔键走右侧。

叶子节点（Leaf）

保存所有实际可查的键与关联值；通过 next 链接到下一片叶子，支持局部有序连续访问。

“内部有键、叶子也有键”不等于保存两份完整记录。分隔键可以是值的副本、前缀或边界表示，具体取决于实现；数据库的物理页布局比教学图复杂得多。

03 · 点查：每层一次定位

查找 k = 27：读根页 [20 | 40]；因为 20 ≤ 27 < 40，进入中间子页 [20,25,30]；对叶子做二分，发现没有 27。若要找 25，下降路径相同，但叶内可以命中记录。

内部节点的路由规则(1)
i=upper_bound(S,k)

S 为升序分隔键数组。等于分隔键时走右子树，这是本文“右子树最小键”约定；别的实现可采用不同边界语义。

04 · 范围查：沿叶链顺序推进

执行区间 25 ≤ k ≤ 45 时，先像点查一样下降到首个可能的叶子，再在叶内定位下界位置，依次输出 25、30；随后通过 next 前进到下一片叶子，输出 40、45，看到下一键 50 后终止。

注意两件事：第一，通常不是“每输出一条再从根查一次”；第二，叶子有序不意味着 SQL 查询必定只碰索引页——若需要回表取未包含在索引中的列，还可能产生额外随机 I/O。数据库优化器会结合选择率、覆盖列、缓存情况和执行计划决策。

反例：哈希索引很适合精确等值定位，但缺乏天然的全局排序来支持 ORDER BY 与区间扫描。B+ Tree 的价值并非总是比哈希更快，而是一个索引同时支持等值与有序访问。

05 · 阶数、容量与平衡不变量

“B+ Tree 的阶数是 m”这句话往往存在约定差异。为避免把阶数、键数、孩子数混为一谈，本文明确采用以下教学约定：内部节点最多 C 个孩子、C−1 个分隔键；叶子最多 L 个键值条目。对非根内部节点，孩子数至少为 ceil(C/2)；对非根叶子，条目至少为 ceil(L/2)。根节点有单独的例外规则。

非根内部节点的占用界(2)
⌈C2⌉≤nchild≤C

本篇演示使用 C = 4、L = 3。请勿套用到每一种数据库页：可变长键、页填充率及版本管理会改变物理占用条件。

三个关键不变量：有序路由保证每个查询落在唯一子区间；叶子按序保证扫描顺序；所有叶子深度一致保证高度平衡。每次分裂、借位、合并，都要维护这些约束。

06 · 插入：叶分裂为什么是复制键

考虑叶容量 L=3，原根分隔键是 20、40，中间叶子存 [20,25,30]。插入 35 得到临时四项 [20,25,30,35]：它超过容量，于是切成左叶 [20,25] 与右叶 [30,35]；将右叶最小键 30 复制到父节点当分隔键，父节点变成 [20,30,40]。

如果你把 30 从叶子直接移走，就违反了“所有数据条目均在叶子”的 B+ Tree 约定。这恰是教科书 B-tree 和 B+ tree 插入操作的关键区别之一。父页条目较大、键前缀压缩等因素在这幅图里被抽象掉了。

07 · 分裂传播与根升高

接着插入 37，右叶 [30,35] 变成 [30,35,37]；再插入 38，叶子分裂为 [30,35] 与 [37,38]，父节点需要插入新的 separator 37。此时根出现 [20,30,37,40] 共四个分隔键，超过 C−1 = 3 的上限。

根须再分裂：新根只有 [37]，左内部页有 [20,30]，右内部页有 [40]；这次 内部页分裂传播的是路由键，不是把叶子中的 37 移走。新根使所有叶子的深度同时增加一层。

08 · 删除：借位、合并、修正键

删除先定位到叶子并移除条目。如果叶子仍满足占用下界，就无需合并；但若删掉的是最小键，某些父级 separator 可能要刷新。若叶子下溢，有两条路：邻居有富余键，借位 / 重分配；邻居也在下界，合并，并删除父页对应的子指针与路由键。父页若下溢，则递归修复；根只剩一个孩子时可以降低树高。

例如 L=3，叶 [20,25] 删除 25 后只剩 [20]（低于最少 2 项）；右兄弟 [30,35] 也只有 2 项，不能借，于是合并为 [20,30,35]，撤销父页分隔两者的键 30。与此同时要接好叶链。

实现差异：MVCC 引擎中的逻辑删除、版本回收、页复用、在线并发操作与教科书“立即合并”的流程不同。本文代码只实现插入/点查/范围扫描，不会把未实现的删除重平衡标成可运行能力。

09 · 扇出与 I/O 复杂度

传统指针树的分支数低；B+ Tree 用页宽度换取高扇出。设平均有效扇出为 F、索引条目数为 N、每片叶子有效承载量为 L，则树高常可按下面的数量级近似估算（忽略根与页面填充差异）：

高度数量级(3)
h≈1+logF(NL)

高度按一次根到叶的页访问链计。F 与 L 是有效容量而非固定的数据库常量，公式是规模估计，不是所有树形状态下的精确页数。

理想化 I/O 代价(4)
Tpoint=O(logFN),Trange≈O(logFN+KL)

K 为实际返回条目数。区间扫描式子假设叶页较紧密、按逻辑顺序访问；不含回表、缓存未命中、叶页碎片、预取、锁等待等成本。

对磁盘或 SSD 来说，比较 O(log N) 的数学符号还不够；更重要的是访问哪些页、是否已在 buffer pool 中、是顺序还是随机访问。高扇出减少树高，不代表索引维护没有写放大。

10 · 真实存储引擎还要处理什么

页面与父子链接

实际页面容纳页头、slot array、keys、downlinks、记录定位、可变长属性以及管理元信息。压缩分隔键可提高扇出；页面分裂时还要处理邻居链接与原子性。PostgreSQL 文档说明其 B-tree 索引由多层页组成，每层页可形成双向链，分裂可以向上递归，根分裂会增加层数。

并发、恢复与版本

读写同时发生时，单靠 Python 对象指针无法保证一致性。真实数据库还需要 latch 协调、崩溃恢复日志、可见性检查与空间回收。PostgreSQL 的 MVCC 可能让一个逻辑行在索引中对应多个物理版本条目，且能将重复索引键压成 posting list；这些都是本文玩具模型没有实现的功能。参见官方 65.1.4 小节。

组合索引如何用

多列索引按比较规则形成词典序，因此 (user_id, created_at) 常有利于先约束 user_id 再筛选时间；并非所有只过滤第二列的查询都能同样高效。具体执行与数据库实现、统计信息有关，PostgreSQL 多列索引文档提供了正式约束。

11 · B-tree、B+ tree、哈希与 LSM

结构主要组织方式相对适合核心权衡
B-tree（教科书型）内部和叶均可存记录平衡有序查询范围访问路径依具体变体
B+ Tree内部路由，叶子承载条目并按序链接等值、区间、排序访问页分裂、维护与随机写
哈希索引散列桶定位等值匹配天然不维护键序
LSM Tree内存写入 + 多层有序文件合并写密集负载compaction、读/空间放大

这里比较的是设计取向而非普适性能排名。数据库产品常把其变体统称为“B-tree”，但物理组织可能与最简教科书 B-tree 不同。例如 SQLite 文件格式区分表 B-tree 与索引 B-tree 的叶/内部 cell 格式，不能机械套入“一切记录都只在叶子”的统一口号。

13 · 最小可验证插入与范围扫描

把“节点容量、路由、叶子分裂、内部页分裂、叶链”收进一个几十行的教学实现。mini_b_plus_tree.py 只实现唯一键的 insert、find、range_query；同一个键再次插入会覆盖值。它不包含删除、持久化、WAL、并发、变长页与重复键 posting list。

from mini_b_plus_tree import BPlusTree

t = BPlusTree(max_keys=3)
for key in [5, 10, 15, 20, 25, 30, 40, 45, 50, 35, 37, 38]:
    t.insert(key, str(key))
assert t.find(27) is None
assert [k for k, _ in t.range_query(25, 45)] == [
    25, 30, 35, 37, 38, 40, 45
]

用 python posts/storage-indexing/b-plus-tree/mini_b_plus_tree.py 可以运行内置断言；完整测试还覆盖从小到大插入、反向插入、随机顺序、更新已有键与跨多层叶子扫描。这证明的是该最小实现的不变量，不是对任何生产级数据库索引的性能复现。

15 · 一条完整的理解路径

结构：内部页用分隔键路由，叶子持有全部可检索条目。查询：点查下降到一个叶子，范围查询先下降再走叶链。更新：叶分裂复制右叶首键给父页，内部溢出递归，根分裂增加一层；删除则可能借位、合并与根收缩。工程：页布局、缓存、恢复、MVCC 与并发才决定现实运行成本。

继续阅读本站 Understanding FlashAttention 可对比 GPU SRAM/HBM 的数据移动优化；二者都关注存储层次，但 FlashAttention 是算子 IO 优化，B+ Tree 是有序数据库页索引，不属于同一个二级主题。
