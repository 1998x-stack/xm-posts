Understanding FlashAttention

Attention 的复杂度没变，为什么还能变快？从 GPU 内存墙出发，用五幅机制图、在线 Softmax 推导与可执行例子理解 IO-aware Attention。

主论文 · Dao et al., NeurIPS 2022演进 · FA2 / FA3 / FA4阅读约 32 分钟

01 ·更少的数据搬运，而不是更少的注意力

标准 Attention 的数学式只有一行，实际执行却会让 GPU 在一块巨大的 N × N 矩阵上来回读写。FlashAttention 的突破，不是丢弃一部分 token，也不是把 Softmax 改成近似函数，而是换一种执行顺序，让中间矩阵不落到昂贵的全局内存。

设一个 Attention head 有 N 个 token，每个 Query/Key 向量维度为 d，Value 维度为 dᵥ。普通实现先计算每对 token 的相关性，再逐行 Softmax，最后加权求和。数学上完全合理，但如果每一步都是一个独立 GPU kernel，分数矩阵 S 和概率矩阵 P 往往要被写入、读取显存。

一个可感知的量级：当 N = 4096、每个元素用 FP16 的 2 字节表示时，单独一张 4096 × 4096 分数矩阵就约为 32 MiB。多头、批量、反向中间张量又会增加工作集；具体峰值由框架和融合策略决定。

核心命题：一次 Attention 的 FLOPs 没有因为 FlashAttention 消失；优化的是 HBM ↔ SRAM 的 IO 以及由此带来的实际执行时间。原论文的算法仍计算完整的 dense Attention（稀疏扩展需单独看）。[FA1, Abstract / §3]

02 ·回到原式：到底在算什么？

S = QKᵀ / √d,  P = softmaxkey(S + M),  O = PV Q ∈ ℝNq×d，K ∈ ℝNk×d，V ∈ ℝNk×dᵥ，O ∈ ℝNq×dᵥ。Softmax 沿每个 Query 对应的 Key 维度进行。

M 是可选的加性 Mask：合法位置加 0；不合法位置在概念上加 −∞。在 causal self-attention 中，Query 位置 i 只能看到 j ≤ i 的 Key。分母是这一行所有可见 Key 的指数和，不是单个 tile 的局部和。

一个常见误解是：把序列拆成若干块，每块独立 Softmax，然后把结果相加就结束了。这样并不等价，因为每块使用不同归一化分母。FlashAttention 解决的正是「分块计算但仍共用整行 Softmax 分母」这个问题。

保持不变

Q、K、V 的含义、注意力权重定义、因果约束，以及输出的数学目标。

发生变化

tile 的读取顺序、局部归约的状态表示、Kernel 融合、反向缓存与重算策略。

03 ·把注意力矩阵切成小窗格

设 Query block 大小为 Bq，Key/Value block 大小为 Bk。内核依次把 Qᵢ 与 Kⱼ, Vⱼ 搬到片上内存，计算一个 Bq × Bk 的局部 score tile，并立即用于更新对应 Query 行的在线归约状态。整个 Nq × Nk 分数矩阵不需要被实体化。

这里不是「只算绿色块」的通用要求：非因果 Attention 所有 tile 都要参与。图中的三角形来自 causal Mask，而不是 FlashAttention 主动近似丢弃信息。每一个 Query tile 持有独立的 m、ℓ、acc 行状态。

tile 不应越大越好。更大的 block 能增加矩阵乘工作比例，但也会增加 shared memory、寄存器与线程块资源占用，从而影响 occupancy。最优配置依 GPU 架构、head dimension、序列长度、数据类型与 mask 而变化。

04 ·在线 Softmax：分母可以边走边算吗？

先只考虑某一个 Query 行。已经看过的 score 集合为 A，它的运行最大值为 m；指数和为 ℓ；未归一化的 Value 加权和为向量 acc。接下来读取新 tile B，其中每个位置有 score sⱼ 与向量 vⱼ。

m′ = max(m, maxj∈B sⱼ)把新旧两部分统一到一个数值稳定的指数参考点。
α = exp(m − m′),  wⱼ = exp(sⱼ − m′)
ℓ′ = αℓ + Σj∈Bwⱼ
acc′ = αacc + Σj∈Bwⱼvⱼ 初始化 m = −∞、ℓ = 0、acc = 0；对第一块应将 αℓ 视为 0。所有被 Mask 的 score 都不参与集合 B。

关键不是 ℓ′ 的更新本身，而是 旧的加权和也必须乘同一个 α。否则当后续 tile 出现更大的 score 时，历史项和新项不在同一个指数尺度，最终答案会错。

05 ·前向 Kernel：如何把这些状态串起来？

把一个 Query tile 的多行并排放入同一个线程块。每读取一个 K/V tile，就计算局部 QᵢKⱼᵀ，实施 Mask，进行按行更新。下面是便于推理的抽象伪代码，不是原论文 Algorithm 1 的逐行转录，也不是可直接编译的 CUDA Kernel。

for Q_tile in Q_tiles:
    m = -inf             # 每个 query 行一个最大值
    l = 0                # 每个 query 行一个指数和
    acc = zeros(Bq, dv) # 未归一化 value 加权和
    for K_tile, V_tile in KV_tiles:
        s = Q_tile @ K_tile.T / sqrt(d)
        s = apply_mask(s)        # 在本 tile 上
        new_m = max(m, rowmax(s))
        alpha = exp(m - new_m)  # 初始空状态按 0 处理
        w = exp(s - new_m[:, None])
        l = alpha * l + rowsum(w)
        acc = alpha[:, None] * acc + w @ V_tile
        m = new_m
    O_tile = acc / l[:, None]

关键的排列方式是：score tile 从生成到消费都不离开片上工作集。实际 CUDA 实现会细致区分 global memory、shared memory、寄存器、warp 与线程块；伪代码只表达数值不变量，不能推导真实的加速倍数。

为什么数值稳定？所有参与指数函数的 score 都减去目前已见数据的最大值，因此不需要直接计算巨大正数的指数。若一行所有位置都被 Mask，必须显式处理空集合；一般 causal self-attention 每行至少含自己，实际高性能内核也可能对边界 tile 做额外分支。

06 ·反向为什么值得重新计算？

常规自动求导会倾向保存较多前向中间结果，以换取反向少算一点。FlashAttention 反过来做：不在 HBM 保存 N×N 的概率矩阵，而是保存输出和每行可复用的归一化统计量。反向经过每个 tile 时再根据 Q、K、LSE 恢复局部概率。

对一行而言，dP = dO Vᵀ，Dᵢ = Σⱼ Pᵢⱼ dPᵢⱼ = Σₜ Oᵢₜ dOᵢₜ。Softmax 的 Jacobian 可简化为：

dSᵢⱼ = Pᵢⱼ (dPᵢⱼ − Dᵢ)
dQ = (dS K) / √d,  dK = (dSᵀ Q) / √d,  dV = PᵀdO S 已包含 1/√d；这些式子表达未加 dropout 等扩展的标准 Attention backward。

额外的 FLOPs 不一定是坏事：当被节省的是大量 HBM 读写时，「重算便宜的 tile、换掉昂贵的存储」可能让整体更快。具体收益仍依硬件与 shape 而定。[FA1, §3.2 / Appendix]

07 ·复杂度：线性内存，不等于线性时间

比较维度常规显式 AttentionFlashAttention v1
数学目标dense exact softmax attention相同的 dense attention
主计算量Θ(N²d)，令 dᵥ≈dΘ(N²d)，数量级不变
显式物化 S、P常见分阶段实现会做不需要整张 N×N 矩阵
额外工作存储通常 Θ(N²)，不含 Q/K/V/O论文 Theorem 1 给出 O(N) 额外存储
HBM accesses论文基线 Θ(Nd + N²)在论文假设下 Θ(N²d²/M)

M 表示可用片上 SRAM 容量（按标量元素计）。上表的理论 IO 结果针对原论文所述存储模型及 d ≤ M ≤ Nd 的参数区间；不能直接当成任意 GPU / Attention 变种的带宽预测。[FA1, Theorems 1–2]

两个经常被混淆的边界：FlashAttention 不会自动减少模型参数、KV Cache 所占空间，也不会把一次完整序列 Attention 的二次计算量变成线性。PagedAttention 管理的是 Serving 阶段 KV Cache 的分配与访问，它与这里的 Attention kernel IO 优化处于不同层级，可组合但不是同一算法。

09 ·最小可执行模型：用纯 Python 验证在线归约

为了验证数学机制，配套 mini_attention.py 只依赖 Python 标准库，包含朴素的按行 Softmax Attention 与 streaming/block 版本；对应 单元测试覆盖不同 block size、causal Mask 和极端 score 的数值稳定性。

# 对每个 query 行：更新 running max、分母、加权和
new_m = max(old_m, max(tile_scores))
alpha = exp(old_m - new_m) if has_prior_tile else 0.0
weights = [exp(s - new_m) for s in tile_scores]
new_l = alpha * old_l + sum(weights)
new_acc = [
    alpha * old_acc[t] + sum(w * value[t]
        for w, value in zip(weights, tile_values))
    for t in range(value_dim)
]
output = [x / new_l for x in new_acc]

从仓库根目录执行 python posts/systems/flashattention/mini_attention.py，或 python -m pytest -q tests/test_flashattention.py。这个示例只验证算法等价，不涉及 GPU、Tensor Core、内核融合或性能；CPU 小例子通过，不意味着复现论文的 GPU speedup。

把公式映射到真实系统

在 PyTorch 中，torch.nn.functional.scaled_dot_product_attention 可在满足条件时选择融合后端，但实际 dispatch 依设备、dtype、mask 与版本而定。要比较内核，应显式记录后端、GPU SKU、软件版本、B/H/N/d、causal、dtype、forward/backward、warmup 次数及统计口径，而不是只比较两行 Python 的耗时。

10 ·论文证据：哪些结果能支持什么结论？

原论文（NeurIPS 2022）在 Abstract 中报告：相对所述基线，GPT-2 训练（序列长度 1K）达到约 3× 加速；BERT-large（长度 512）相对 MLPerf 1.1 的特定训练记录有 15% wall-clock 改善。它们是作者在当时软件、硬件及实验配置下的比较，不是新系统的普遍承诺。[FA1, Abstract]

FA2（ICLR 2024）报告在 A100 上训练 GPT 风格模型达到 225 TFLOPs/s / GPU、72% model FLOPs utilization 的实验情形；这属于整模型训练配置的观察，不能与纯 attention kernel 的峰值 FLOPs 指标混用。[FA2, Abstract]

FA4（MLSys 2026）报告在 B200、BF16 的给定比较中最高达到相对 cuDNN 9.13 1.3×、相对 Triton 2.7× 的加速，并达到 1613 TFLOPs/s（71% utilization） 的峰值情形。它们并非所有输入长度或所有 Attention 模式上的普遍倍数。[FA4, Abstract]

怎么解读这些数字？先核对测试对象是单 kernel 还是 end-to-end 训练，再核对 GPU、dtype、batch/head 数、序列长度、前向/反向、比较基线与实现版本。没有统一测试口径，就不要把不同论文的“× 倍”直接排成一张排行榜。

11 ·工程边界：何时不会更快？

  • 短序列或很小的 batch：launch、调度和资源利用率可能主导，减少 N² 存储并不自动带来大幅耗时下降。
  • 长上下文 decode：单 token Query 与长 KV 的访存模式不同于 prefill；还需要结合 GQA/MQA、KV Cache、分页存储等 Serving 决策。
  • 数值精度：FP16/BF16/FP8 以及不同累加方式会产生误差差异；“exact”主要指不采用稀疏/低秩近似来改变目标，而非无限精度或 bitwise 相等。
  • Mask 与变长：causal、padding、sliding window、不同 Q/K 长度会改变有效 tiles 和边界处理；必须依据具体实现确认支持组合。
  • 反向的代价：重算会增加局部 FLOPs，是否划算取决于硬件的 compute/memory 平衡以及 block 配置。

最有价值的性能判断不是“是否安装了 flash-attn”，而是：对你的工作负载，这个形状的 kernel 是计算受限还是 IO/调度受限？瓶颈被移走后，下一个瓶颈会在哪里出现？

12 ·把 FlashAttention 记成三个不变量

1. 数学不变

仍然计算逐行 Softmax 的完整 attention；切块不意味着独立归一化。

2. 存储路径变

中间 S/P 不写整张 HBM 矩阵，借助在线归约与反向重算交换 IO 和 FLOPs。

3. 硬件目标持续变

FA2 优化并行划分，FA3 利用 Hopper 异步，FA4 面对 Blackwell 的扩展失衡。
