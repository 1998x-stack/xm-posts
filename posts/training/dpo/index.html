Understanding DPO

为什么偏好对可以直接训练语言模型，而无需显式奖励模型与 PPO？从一个被忽略的归一化常数开始，推导 DPO 的每一步。

Rafailov et al. · NeurIPS 2023预计阅读 34 分钟Preference Optimization · RLHF

01 · 为什么有了 SFT，还需要「偏好」？

假设同一个问题有两个都能读懂的回答：一个准确、完整且不误导；另一个流畅，却遗漏了关键条件。SFT 学的是「示范文本长什么样」，偏好数据告诉我们「两种合理输出，哪一种更好」。若直接模仿获选答案，模型是否真正学会了比较？

传统 RLHF 先训练一个给回答打分的奖励模型，再通过 PPO 更新语言模型。DPO（Direct Preference Optimization）提出更短的路径：不单独拟合奖励网络，而是直接从成对偏好中学习策略。这不意味着奖励概念消失了；它转成了策略相对参考模型的隐式奖励。[1]

先记住最重要的边界：DPO 并不是证明 PPO 处处不如它，也不是证明离线偏好学习可替代所有在线探索。它是在明确的 KL 正则化与偏好模型假设下，推导出一种更直接的优化方法。

02 · 从一次选择开始：偏好对到底是什么？

训练样本写作 (x, yw, yl)：x 是共同的提示，yw 是更受偏好的回答（winner / chosen），yl 是较不受偏好的回答（loser / rejected）。没有必要为每个回答标定一个绝对的“质量分数”。

论文采用 Bradley–Terry（BT）偏好模型，假设潜在奖励 r(x,y) 的差值决定谁更可能被选中：

p(yw≻yl|x)=σ(r(x,yw)−r(x,yl))
σ(z) = 1/(1+e−z)；原论文 §3，式 (1)。

因此，为成对偏好拟合显式奖励模型，原本也是一项二分类任务：−log σ(rw − rl)。DPO 的巧妙之处是找到一种无需独立奖励网络的奖励表达。[1]

03 · 传统 RLHF 的目标：奖励与偏离之间的平衡

对于一个提示 x，让策略 πθ 产生回答 y。经典 RLHF 不只是最大化奖励 r(x,y)，还希望策略不要相对 SFT 的参考策略 πref 漂移过远。

maxπEy~π(·|x)[r(x,y)]−βKL(π(·|x)||πref(·|x))
对 x 的数据分布再取期望；β > 0 是 KL 正则系数；原论文 §3，式 (3)。

β 不是学习率。在相同奖励尺度的理论问题里，较大的 β 对偏离参考分布惩罚更重；较小的 β 容许策略朝高奖励区域倾斜得更明显。奖励尺度、数据及优化过程变化时，不应机械解释 β。

为了理解为何过去常需要强化学习：目标中的期望取自当前策略生成的离散文本；用一个学得的奖励模型进行采样反馈时，通常需要策略采样、估计优势与反复训练。PPO 是常见实现，而不是“RLHF”的唯一算法。[1]

04 · 从 KL 正则化到最优策略的闭式形式

先暂时抛开神经网络参数化，固定一个提示 x，允许在所有输出序列上选择任意概率分布 π。在 πref(y|x)>0 的支持集上，把上一节目标写成对概率的优化，并加上归一化约束 Σyπ(y|x)=1。

① 展开 KL

F(π)=Σy π(y|x)·[r(x,y)−β log(π(y|x)/πref(y|x))]。

② 拉格朗日条件

对每个 π(y|x) 求驻点，得到 log(π/πref) = r/β + 仅依赖 x 的常数。

③ 归一化

把共同常数写成 −log Z(x)，使对所有 y 的概率和为 1。

π*(y|x)=πref(y|x)·exp(r(x,y)β)Z(x)
Z(x)=Σyπref(y|x)exp(r(x,y)/β)；原论文 §4，式 (4)，Appendix A.1。

直接按此式生成回答仍然困难：对于语言模型，所有可能序列组成巨大的集合，归一化项 Z(x) 通常无法显式计算。下一步关键是：偏好比较只关心两个奖励的差，不关心它们共同的基线。

05 · 最关键一步：为什么 Z(x) 可以消失？

将上式取对数并移项：

r(x,y)=βlog[π*(y|x)πref(y|x)]+βlogZ(x)
原论文 §4，式 (5)。

在相同提示 x 下，BT 模型使用 r(x,yw)−r(x,yl)。共同的 β log Z(x) 正好相减抵消，于是可以只用概率比刻画偏好。注意两个回答必须共享同一个条件提示。

r̂θ(x,y)=βlog[πθ(y|x)πref(y|x)]
隐式奖励代表同一个偏好等价类中的一个成员；不等于人类真实奖励的绝对标尺。

奖励函数加上只与 x 有关的任意偏置 f(x)，既不会改变 BT 偏好概率，也不会改变 KL 正则目标的最优策略。原论文 §5.1 以奖励等价类解释这一点。[1]

06 · DPO 损失：四个 log-prob 就够了

现在将潜在最优策略替换成可训练的 πθ，对每个偏好对做最大似然。定义 ℓθ(y)=log πθ(y|x)、ℓref(y)=log πref(y|x)，以及相对优势 a(y)=ℓθ(y)−ℓref(y)。

Δ=[ℓθ(yw)−ℓref(yw)]−[ℓθ(yl)−ℓref(yl)]
即 chosen 的 log-ratio 减去 rejected 的 log-ratio。
LDPO(θ)=−EDlogσ(β·Δ)
原论文 §4，式 (7)。在代码中可用 log-sigmoid / softplus 的数值稳定写法。

这解释了两个常见误解。第一，不是只比较 πθ(yw) 与 πθ(yl) 谁大，而是与参考策略的相对变化。第二，损失没有一个“把答案奖励分数直接回归到 1/0”的头；分类是建在隐式奖励差上的。

在初始时 πθ = πref，两者 log-ratio 为零，所以任意样本初始的 Δ=0，偏好模型预测 0.5，损失为 log 2 ≈ 0.6931。这只是初始数学状态，不是实验成绩。

07 · 亲手观察 β：同一个 margin，会怎样影响 loss？

设一条手工构造的偏好样本：chosen 的相对 log-prob 变化为 +0.6，rejected 为 −0.2，所以 Δ = +0.8。固定这四个 log-prob，不训练模型，只改变 β 看损失公式怎样响应。

固定 Δ = 0.8 · 改变 β
偏好 logit：βΔ0.4000
预测 chosen 获选概率59.87%
单样本 loss0.5130

当前预测仅来自数学公式；β 增大会把固定的 Δ 变成更大的 logit。

重要：此控件是固定 log-ratio 的局部函数演示，不是完整训练模拟。若重新训练模型，πθ 会随 β 改变，不能用这里的单调关系推断“较大 β 训练后必然偏好更强”。在 KL 正则化目标中，β 越大反而意味着对偏离参考策略惩罚越强。

08 · 梯度：为什么错误排序会被更强地修正？

对单个偏好对，令 z=βΔ。因为 ∂[−log σ(z)]/∂z = −σ(−z)，冻结参考模型后得到：

∇θL=−βσ(−βΔ)·[∇logπθ(yw|x)−∇logπθ(yl|x)]
原论文 Appendix A.4；两种 response 的更新项方向相反。

由于参数共享、softmax 耦合、生成长度和其他样本的影响，不能把这个梯度直接读成“每一步 chosen 的绝对概率必升、rejected 必降”。合理做法是监控 rewards/margins、rewards/accuracies、两个答案的 log-prob、长度和外部质量评估。[2]

09 · 工程实现：序列 log-prob、mask 与参考策略

对自回归模型，训练时计算的是给定 prompt 下，完整 completion 的条件对数概率之和；不是将 token 概率相加，也不是无条件给整段 prompt + response 打分：

logπθ(y|x)=∑t=1..Tlogpθ(yt|x,y<t)
通常使用 token-level log-softmax + gather；标签移位与 completion mask 必须对应。
数据侧

同一个 prompt 的 chosen/rejected，统一 chat template、EOS、截断策略，保证被比较的是同一条件分布。

模型侧

πθ 可训练；πref 通常冻结，且与初始 SFT policy 一致。参考 log-prob 可离线预计算以节约前向开销。

数值侧

先对有效 completion token 求 log-prob 之和，再求两个 log-ratio 的差；使用 softplus(−βΔ) 避免直接算 log(sigmoid)。

监控侧

只看 DPO train loss 不足以判断对齐质量；关注训练/验证偏好指标、长度偏差、真实任务及人工评估。

仓库提供 最小、无第三方依赖的公式实现与断言（该链接指向源代码仓库，而非公开站点；在线正文参考下方展示）。它仅复现损失和 mask 算术，不训练语言模型，也不复现实验胜率。

def dpo_loss(chosen_policy, rejected_policy,
             chosen_ref, rejected_ref, beta=0.1):
    if beta <= 0:
        raise ValueError("beta must be positive")
    margin = (chosen_policy - chosen_ref) - (
              rejected_policy - rejected_ref)
    return math.log1p(math.exp(-beta * margin))  # toy range only

# production: use stable softplus(-beta * margin)
# and completion-token log-probs from causal LM.

若要训练真实模型，可参考 Hugging Face TRL 的 DPOTrainer 文档；其实现与当前扩展的损失变体不等同于 2023 原论文全部设置。[2]

11 · 为什么 DPO 不是终点：假设与失败模式

偏好标签噪声

模糊或错误的 chosen/rejected 会把模型推向错误方向；BT 假设不是对任意人类偏好的完整刻画。2024 年 rDPO 专门研究随机偏好翻转与稳健损失。[3]

长度与形式偏好

序列 log-prob 是逐 token 累加；数据或评审中对冗长回答的偏好可能干扰“质量”。长度偏差问题有后续研究，但不是 2023 原论文已解决的性质。[4]

离线覆盖问题

若好答案从未出现在偏好数据里，静态成对比较难以提供在线探索所需的新信号。DPO 不自动发现偏好数据之外的最优回答。

参考策略与 β

参考模型决定了相对尺度；不同 SFT checkpoint、截断长度、β 与偏好数据分布会改变优化行为。不能只移植一个 β 数值。

代理目标与评测

更高偏好正确率并不保证真实用户满意度、安全性或事实性同步提高。需要独立、盲测和分布外评估。

理论到网络的落差

非参数最优策略的解析式不等于有限参数网络一定求得全局最优；真实训练有容量、优化和数据质量限制。

原论文 §7 也明确将分布外泛化、自标注数据、过优化及更大模型扩展留作后续问题。[1]

12 · 把整篇文章压缩成一条推理链

  1. 同一 prompt 的两个回答得到一条偏好标签，BT 模型把标签理解为潜在奖励的相对差。
  2. KL 正则化 RLHF 把“高奖励”与“保持接近参考模型”合在一个目标里。
  3. 在概率分布空间中，最优策略是参考策略按奖励指数重新加权。
  4. 把奖励写成策略/参考策略的 log-ratio 加上共同的 log Z(x)。
  5. 偏好只用同一 x 下的奖励差，因此 log Z(x) 抵消；最后是 βΔ 上的二分类 log-sigmoid 损失。
  6. 工程实现是精确的 completion token log-prob、冻结参考、稳定的损失函数，以及独立任务评估。
判断自己真正理解 DPO 的测试：能否解释为什么 “chosen 比 rejected 的当前概率高” 仍可能对应负的 Δ？答案是：如果参考模型原本更强烈偏好 chosen，新的策略反而缩小了这种差距，Δ 就可能为负。
