Understanding LoRA

为什么冻结几乎全部预训练权重，只学两个小矩阵，模型仍能适应新任务？从低秩假设走到梯度、实验与真实部署。

Hu et al. · ICLR 2022预计阅读 31 分钟PEFT / Low-Rank Adaptation

01 · 同一个基础模型，为什么微调成本会随任务数增长？

设想你已经拥有一个非常大的语言模型：现在要它分别处理客服问答、摘要和代码检查。完全微调当然可行，但每个任务都要更新并保存一份接近原模型规模的权重。难道每次学一个新任务，都必须搬动全部参数吗？

Hu 等人的 LoRA: Low-Rank Adaptation of Large Language Models（2021 年 arXiv 预印本，ICLR 2022）给出一种不同的视角：保留预训练权重 W₀，只拟合「任务需要的变化」ΔW。 这是参数高效微调（PEFT）的典型路线，而不是另起一套 Transformer 结构。

02 · 要学习的不是整张矩阵，而是变化的方向

一个形状为 d × k 的线性投影有 dk 个参数。完全微调允许每个元素独立改变；LoRA 则假设任务适配往往可以由更低维的方向组合表达，用一对细长矩阵替代全尺寸的更新矩阵。

W = W₀ + ΔW，　ΔW = BAW₀ 是已学会通用能力的基底；BA 是任务增量。低秩约束作用于 ΔW，而不是要求 W₀ 本身低秩。

注意「低秩有效」是论文通过实验支持的归纳偏置与假说，并非「任意数据集的最优权重变化都严格低秩」的数学定理。更大的领域迁移、不同语言或复杂任务可能需要不同的 rank 和适配位置。

03 · 沿着一次前向传播，推导每个张量形状

采用列向量约定：输入 x ∈ ℝᵏ，输出 h ∈ ℝᵈ。冻结矩阵 W₀ ∈ ℝᵈˣᵏ；可训练 A ∈ ℝʳˣᵏ、B ∈ ℝᵈˣʳ，其中 r ≪ min(d,k)。

h = W₀x + (α/r)B(Ax)先降维 k→r，再升维 r→d；缩放 α/r 是原始 LoRA 的常用约定。现代变体可以改变缩放规则。
全参数微调

在这一层更新 W₀：dk 个可训练权重，并保存相应梯度、优化器状态。

LoRA

只更新 A 和 B：r(k+d) 个可训练权重；W₀ 仍参与前向和梯度传递，但自身不被更新。

04 · 为什么一插入 LoRA，模型输出不应突然改变？

原论文第 4.1 节使用 A 的随机高斯初始化、B 的零初始化。当 B=0 时，BA=0，因此初始输出严格等于冻结主干输出。LoRA 起步不是给模型强行加一个随机扰动。

在这个初始化下，若损失对 ΔW 的梯度为 G，则 ∂L/∂B ∝ G Aᵀ，而 ∂L/∂A ∝ BᵀG=0。因此第一次参数更新通常先改变 B，后续 A 才可能获得非零梯度。这是两矩阵乘积的链式法则，不意味着 A 永远不学习。

05 · rank=8 到底省了多少参数？

对一个 4096×4096 的线性层，原权重包含 16,777,216 个元素；rank=8 的两个矩阵共有 8×(4096+4096)=65,536 个可训练元素，约为原层权重数量的 0.3906%。这个比例只针对该投影，不是整模型的总训练显存比例。

交互计算只变更单层参数量。实际 GPU 峰值显存还有冻结权重、激活、梯度、Adam 状态、精度和序列长度等成本。论文所述的 10,000× 可训练参数缩减与约 3× 显存降低，来自特定 GPT-3 175B 对照，不应对所有模型套用。见原论文摘要及第 4 节。

06 · 在 Transformer 的哪里放 LoRA？

Transformer 的自注意力包含 Query、Key、Value 和输出投影 Wq、Wk、Wv、Wo。LoRA 可以作用于一个或多个线性投影；原论文实验多以注意力投影为研究对象，并不要求所有层所有权重都低秩化。

Table 5 固定约 18M 可训练参数比较不同投影位置：只改 Wq 时 WikiSQL 验证准确率为 70.4%，只改 Wv 为 73.0%，同时改 Wq 与 Wv 为 73.7%，四个投影均改时也为 73.7%。这支持「分配到哪些模块」与「rank 多大」同样重要，但不是跨模型通用排名。

常见误区：参数量相同，不代表训练质量必然相同。训练目标、目标模块、初始化、学习率与数据集都会改变效果。论文 Table 6 中，Wq+Wv 在 rank=1 和 rank=8 时的 WikiSQL 验证准确率分别为 73.4% 与 73.8%，但不能据此声称 r=1 对所有任务都足够。

07 · 两行逻辑看懂合并：一个可手算的最小实验

取 W₀=I₂、A=[1,0]、B=[0,2]ᵀ、x=[3,4]ᵀ，且 r=α=1。主干输出是 [3,4]ᵀ，低秩增量是 [0,6]ᵀ，相加得到 [3,10]ᵀ。由此可直接验证：(W₀+BA)x=W₀x+BAx。

"""Minimal LoRA linear algebra, standard-library only; not a training reproduction."""
def matvec(matrix, vector):
    return [sum(a * x for a, x in zip(row, vector)) for row in matrix]

def low_rank_forward(W0, A, B, x, alpha=1.0):
    r = len(A)
    base = matvec(W0, x)
    delta = matvec(B, matvec(A, x))
    return [v + alpha / r * d for v, d in zip(base, delta)]

def merged_weight(W0, A, B, alpha=1.0):
    r = len(A)
    return [[W0[i][j] + alpha / r * sum(B[i][t] * A[t][j]
            for t in range(r)) for j in range(len(W0[0]))]
            for i in range(len(W0))]

W0 = [[1.0, 0.0], [0.0, 1.0]]
A = [[1.0, 0.0]]            # r=1, k=2
B = [[0.0], [2.0]]          # d=2, r=1
x = [3.0, 4.0]
assert low_rank_forward(W0, A, B, x) == [3.0, 10.0]
assert matvec(merged_weight(W0, A, B), x) == [3.0, 10.0]
assert low_rank_forward(W0, A, [[0.0], [0.0]], x) == [3.0, 4.0]
assert 8 * (4096 + 4096) == 65_536

这是标准库可运行的矩阵算例，不包含真实梯度下降或原论文训练。仓库内保存了 完整最小示例；训练级用法参阅 Microsoft loralib 与 Hugging Face PEFT API。

09 · 训练节省参数，推理为什么还能没有新增层？

一旦任务固定，可将权重代数合并成 Wmerged = W₀ + (α/r)BA。原来「主干矩阵乘法 + 低秩分支」变为一次线性层乘法：这是 LoRA 相比额外串行 Adapter 层非常关键的部署性质。

但「没有额外推理时延」有明确前提：Adapter 已成功合并到等价的权重表示。如果服务同时托管很多 Adapter、频繁热切换或主干使用量化与分片策略，未合并的算子、权重转换、内存拷贝仍可能产生开销。训练时节约的是可训练参数与优化器状态，不能把它直接等同于生成时 KV Cache 或激活显存的减少。

10 · 从 LoRA 到 QLoRA、rsLoRA 与 DoRA：哪些是后续方法？

这些技术经常一起出现，但不是 2022 年原始 LoRA 论文的一部分：

QLoRA · 2023

在冻结的量化基础模型上训练 LoRA，引入 NF4、double quantization 与 paged optimizer 等技术，主要缓解微调权重显存。Dettmers et al.

rsLoRA · 2023/24

调整按 rank 缩放的规则，例如 α/√r，以改善较大 rank 配置的稳定性。Kalajdzievski

AdaLoRA · 2023

根据重要性向不同矩阵动态分配秩预算，不把每个模块的 r 设为常数。Zhang et al.

DoRA · 2024

把权重更新拆分为幅值与方向，方向部分沿用 LoRA 思路。Liu et al.

这些名称中的「量化」「缩放」「秩分配」「幅向分解」指向不同机制，不能互换使用。实际配置应核对所用库的版本、量化合并条件与模块类型。

11 · 还需要警惕哪些边界？

  • 低秩不是免费午餐：当任务偏离预训练分布很多、rank 或目标模块选择不当时，容量限制可能明显影响结果。
  • 部署存储和训练显存是两个量：多个任务可共享 W₀，但训练仍需完整的冻结主干参与前向；优化器节省不等于完全消除激活与计算开销。
  • 合并的数值等价需要限定精度：在有限精度或量化表示中，合并先后顺序可能影响误差；不能保证所有运行环境比特级一致。
  • 不能替代实验协议：比较 PEFT 与 Full FT 时应对齐数据分割、token budget、训练步数、学习率搜索、种子与计算预算。

实际选择 LoRA 时，可从注意力投影或明确的目标模块开始，用多组 rank 与 alpha 做验证；先记录训练质量、显存和部署模式，再考虑增加全层覆盖或 QLoRA。以上是工程研究路线，不是论文证明的唯一最优配方。
