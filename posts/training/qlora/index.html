PAPER STUDY · QUANTIZATION × LOW-RANK ADAPTATION

Understanding QLoRA

65B 模型为什么可以在 48GB GPU 上微调？从一块冻结权重的存储账本开始，逐步拆解 NormalFloat、双重量化、分页优化器和真实论文证据。

Dettmers et al. · NeurIPS 2023预计阅读 33 分钟Training / PEFT / Quantization

01 · 为什么 LoRA 之后，65B 模型仍会爆显存？

LoRA 节约的是可训练参数与优化器状态，但预训练主干仍必须驻留用于前向和反向传播：如果 65B 权重按 BF16 保存，仅主干权重就约 130 GB（十进制），没有包括激活与 CUDA 临时内存。

QLoRA 论文不是发明一种新推理架构，而是把这份冻结主干量化成 NF4，并让 LoRA 适配器承担参数更新。作者报告在其 GPU、batch、序列长度与训练协议下，在单张 48 GB GPU 上微调 65B 模型；论文还将 16-bit 全量微调的显存需求估计为超过 780 GB。两数字都有实验条件，不能直接推广为所有模型的硬件门槛。[1] Abstract, §1

02 · 冻结 W，训练两个低秩矩阵

令输入 X 形状为 (b,h)，主干矩阵 W 为 (h,o)，输出 Y 为 (b,o)。LoRA 引入 L₁:(h,r)、L₂:(r,o)、标量缩放 s（常取 α/r），其中 r 小于输入输出维度。QLoRA 完整继承这个低秩分支，差别是冻结主干如何储存和计算。

NLoRA=r(h+o)

例如 4096×4096 的投影层，rank=8 的 Adapter 参数数为 8×(4096+4096)=65,536，而原层有 16,777,216 个参数，仅占 0.391%。但更新更少的参数并不消除计算冻结主干所需的前向和输入梯度。

03 · 4-bit 存储不等于 4-bit 算矩阵乘法

论文 §3 对 storage dtype 和 compute dtype 做了严格区分。量化码存储在 NF4 中，调用时反量化到通常为 BF16 的计算表示，然后执行浮点矩阵乘法。可训练的 LoRA 权重同样使用较高精度计算；不对量化主干应用优化器更新。

Y=XD(WNF4,c)+sXL1L2

D(W_NF4,c) 表示用量化码和尺度还原用于计算的权重近似，c 是分块尺度。这里采用行向量记法。冻结并非“反向时完全略过主干”：计算 Adapter 的梯度仍需要穿过网络；只是不存主干的可更新梯度和优化器状态。

04 · 为什么 NF4 的 16 个码位不是等间距？

均匀 4-bit 量化把有限的码点铺在数值区间。若预训练权重接近零均值正态，大多数值集中在零附近，等距分配会浪费一些远端码位。论文构造的 NormalFloat 4 从标准正态的分位数出发，使码位匹配概率密度，并通过不对称处理保留精确的零值。

论文称其在给定正态数据假设下信息论最优，并用 Pile 的 perplexity、zero-shot 任务和 MMLU 对比 FP4/Int4。不要误读为任意权重、任意硬件都保证零量化误差。NF4 仍是有损表示。[1] §3, Eq. (4), Appendix H

05 · Double Quantization：量化“量化尺度”

每 64 个权重共用一个 FP32 的 block scale 时，仅 scale 就增加 32/64=0.5 bit/weight。论文进一步把第一层尺度按 256 个一组变成 FP8，并为这组尺度保留第二层的 FP32 scale，得到如下严格限定的账本：

3264−(864+3264×256)=0.373 bit/weight

对 65B 参数，额外节省约 65×10⁹×0.373/8 = 3.03 GB。这是压缩元数据的节省，不是“整个 4-bit 主干降为 2-bit”。实际内存还有打包方式、异构权重、embedding 与动态缓冲等影响。

06 · Paged Optimizer 为什么与 PagedAttention 无关？

即使常驻权重足够小，长样本和梯度检查点重计算也可能产生瞬时内存峰值。QLoRA 的 Paged Optimizer 使用 NVIDIA Unified Memory，在 GPU 内存紧张时允许优化器状态的页面迁到 CPU RAM，需要时再迁回。

论文只在指定的 65B / 48GB / batch=16 设置下报告 Paged Optimizer 与普通优化器训练速度相同，未证明各种工作负载上都无额外开销。数据迁移可能消耗带宽；它也不会神奇地降低所有激活内存。[1] §3–4

07 · 反向传播：如何“经过”冻结权重而不更新它？

在 Y = X D(W) + s X L₁ L₂ 中，主干仅用于乘法计算与链式求导，requires_grad=False 意味着不对 W 分配可更新参数梯度。Adapter 的两个因子才是训练目标。冻结的是参数更新，不是整条计算图中所有中间节点的梯度。

这也解释“4-bit 不可导就不能微调”的误解：实际乘法在较高精度执行，梯度可流入 Adapter，而不需要对离散索引本身做梯度下降。把真实的 GPU 量化内核当作纯 Python 中逐个做整数转换的操作，会错误地丢失这条路径。[1] Eq. (5)–(6)

09 · 论文 Table 3：性能“接近”有哪些限定？

原论文在 LLaMA 7B、13B、33B、65B 四个尺寸 × Alpaca、FLAN v2 两个微调数据集上，报告了5-shot MMLU test accuracy。Table 3 的八组均值分别为 BF16 LoRA 53.0%、FP4 LoRA 52.2%、NF4+DQ 53.1%。这不是“所有四种规模都对比了 16-bit 全参数微调”。

NeurIPS 2023 · Table 3，八组配置的平均 MMLU 5-shot test accuracy
Adapter 微调类型平均值相对 BF16
BF16 LoRA53.0%基准
FP4 LoRA52.2%-0.8 pp
NF4 + DQ53.1%+0.1 pp

Table 2 另报告 Pile Common Crawl mean perplexity：Int4 34.34、FP4 E2M1 31.07、FP4 E3M0 29.48、NF4+DQ 27.41（越低越好）。这个语言建模指标与 MMLU 准确率既不是同一指标，也不能合并成一个“模型质量分”。

Guanaco 在当时 Vicuna benchmark 约达 ChatGPT 的 99.3%，属于论文特定的聊天评价协议。原论文也指出自动评审、偏好与榜单的可靠性限制，并列出 Guanaco 的失败例。[1] §4–6, Table 2–3, Appendix F

10 · 用什么代码实现，怎样避免伪复现？

作者项目 artidoro/qlora 使用 bitsandbytes、Transformers 和 PEFT。现代 Transformers 中的核心配置是 load_in_4bit=True、bnb_4bit_quant_type="nf4"、bnb_4bit_use_double_quant=True、bnb_4bit_compute_dtype=torch.bfloat16。先核对实际软件版本、硬件设备、模型许可及目标线性层，再连接 LoRA；不能只凭一个配置字典宣称已复现原论文。

from transformers import BitsAndBytesConfig
import torch
quant = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16,
)
# 另需加载兼容模型并挂载 PEFT LoRA。
# 这不是完整训练脚本，也不执行模型训练。

论文 Appendix D 的 Guanaco 实验采用 rank=64、α=16，并把 LoRA 加到所有线性层；这只是历史实验选择。配套 mini_qlora.py 仅用标准库演示量化码点、冻结权重与 Adapter 贡献，不代表 CUDA 内核或完整结果复现。

11 · 误区与系统边界

4-bit 不等于零损

NF4 的优势需要适当权重分布和任务协议，不同模型/层可能有额外量化误差。

低显存不等于更快

反量化、显存带宽、重计算、统一内存迁移会影响训练速度。

权重占用不是峰值 VRAM

激活和序列长度、batch、optimizer、缓存以及运行时分配仍可能主导开销。

QLoRA 不等于训练 4-bit 主干

冻结的量化 W 没有被 Adam 更新；适配器学习变化方向。

部署适配器需验证

对量化权重合并 Adapter 可能引入再次量化误差，不能承诺数学上位级相同。

数据比“参数多”更重要吗？

论文仅在给定基准观察某些更小高质量数据优于更大数据，不能推为所有任务定律。
