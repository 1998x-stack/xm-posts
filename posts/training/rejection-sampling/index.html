Understanding Rejection Sampling

拒绝采样不是“生成很多答案，然后挑一个”这么简单。从概率论中的接受—拒绝算法出发，推导它为什么能得到目标分布；再看奖励模型如何把这套思想带进 LLM 对齐、Best-of-N 和拒绝采样微调。

核心案例 · RAFT / Llama 2 / WebGPT约 30 分钟训练与对齐概率采样 · 奖励筛选

01 · 拒绝的究竟是什么？

想象我们想从一个复杂分布里抽样，但它太难直接采样。我们手里却有一个容易采样的分布。拒绝采样的想法是：先从容易的分布提出候选，再按一个经过推导的概率接受或拒绝它。只要条件满足，最后留下来的样本就服从我们真正想要的目标分布。

这和普通的“筛掉不喜欢的答案”有一点像，但两者不能直接画等号。统计学中的精确拒绝采样有严格的密度比和包络上界；LLM 后训练中的 reward filtering 通常使用奖励模型排序、阈值或每个 prompt 的 Top-1 / Top-K，是一种工程化的筛选流程。它继承了“多生成、再筛选”的思想，但不一定严格实现了概率论里的接受—拒绝算法。

01 / TARGET目标分布 p

我们真正想得到的样本分布，可能难以直接采样。

02 / PROPOSAL提议分布 q

一个容易生成候选、并覆盖目标支持集的分布。

03 / TEST接受概率 a(x)

候选不是一律保留，而是按密度比随机接受。

04 / RESULT目标样本

被接受的候选，在理想条件下恰好服从 p。

在语言模型中，可以把“候选”理解为完整回答序列。模型先给出多个可能的回答，再由奖励模型或验证器判断哪些回答更符合偏好、规则或任务目标。接下来要弄清楚：这个类比在什么地方是严格的，在什么地方只是近似。

02 · 精确拒绝采样的数学保证

先把符号固定下来。目标密度记为 p(x)，提议密度记为 q(x)。我们要求提议分布覆盖目标分布的支持集：如果某处 q(x)=0，那么目标也必须在该处为零。否则，提议过程永远不可能产生目标分布需要的样本。

条件一：构造一个处处覆盖目标的包络

p(x)≤Mq(x),M≥suppq

M 是一个常数上界。图中的 Mq(x) 必须在每个 x 处都不低于 p(x)，而不是只在峰值附近覆盖。

算法每轮做两件事：先抽一个候选 X∼q，再独立抽一个 U∼Uniform(0,1)。只有当 U 落在接受区域内，才保留 X。

条件二：按密度比接受

a(x)=p(x)Mq(x),U≤a(X)

当 U ≤ a(X) 时接受，否则拒绝并重新采样。因为 p(x) ≤ Mq(x)，所以 0 ≤ a(x) ≤ 1。

为什么接受后的分布恰好是 p？

这是整套算法最重要的一步。候选落在某个很小区间 dx 的概率约为 q(x)dx；它同时被接受的概率是 p(x)/(Mq(x))。两者相乘，q(x) 会被约掉：

被接受样本的未归一化概率质量

q(x)·p(x)Mq(x)=p(x)M

因此，所有位置上的接受质量都是目标密度 p 的同一个常数倍。

把所有 x 的接受质量加起来，得到单次提议的总接受概率：

P(accept)=∫pMdx=1M

于是对任意集合 A，接受样本落在 A 中的条件概率为：

P(X∈A|accept)=∫Ap(x)dx1/M·1M=∫Ap(x)dx

接受事件发生后，样本在任意集合 A 上的概率与目标分布完全一致。这就是“拒绝后仍然无偏”的核心原因。

效率结论：若 p 已归一化，单次提议接受率为 1/M，因此平均需要 M 次提议才能得到一个接受样本。M 越松，算法越慢；包络越紧，接受率越高。

更一般地，目标可能只知道未归一化密度 p̃(x)，归一化常数 Z=∫p̃(x)dx 不可得。只要 Mq(x)≥p̃(x)，接受概率仍可写为 p̃(x)/(Mq(x))，接受后的样本服从 p̃/Z；单次接受率为 Z/M，平均提议次数为 M/Z。这正是拒绝采样有用的地方：不必先算出 Z。

03 · 一个可以手算的离散例子

用三个离散状态 A、B、C 代替连续变量。我们希望目标分布为 p=(0.1, 0.3, 0.6)，但只会从提议分布 q=(0.4, 0.4, 0.2) 抽样。计算每个状态的密度比：

pq=(0.1/0.4,0.3/0.4,0.6/0.2)=(0.25,0.75,3)

最大密度比是 3，所以 M=3。A 的接受概率是 0.25/3=1/12；B 是 0.75/3=1/4；C 是 3/3=1。注意，提议分布中 A 很常见，但目标分布中 A 很少，因此大多数 A 会被拒绝。C 在提议分布中相对稀少，但目标分布中更常见，因此只要抽到 C 就接受。

04 · LLM 如何把候选变成训练数据？

现在把样本 x 换成一条用户提示，把候选样本换成完整回答 y。模型不是只生成一个答案，而是对同一个 prompt 生成 K 个候选；奖励模型再估计每个回答的偏好分数，最后把高分候选保留下来。

INPUT选择提示集合

从指令数据或目标任务中选取 prompt，控制覆盖范围与难度。

GENERATE采样多个回答

从当前策略采样 K 个回答，温度、top-p 和长度上限会改变候选多样性。

SCORE奖励模型打分

用 reward model 或可验证规则对回答评分，必要时先去重。

LEARN对保留样本做 SFT

把高分回答作为伪标签，更新原模型或下一轮策略。

对第 i 个 prompt，记 K 个回答为 yᵢ₁,…,yᵢK，奖励模型分数为 rφ(xᵢ,yᵢⱼ)。最简单的“每个 prompt 留一个”策略是：

每个 prompt 独立选出奖励最高的回答

yi*=yi,j*,j*=argmaxrφ(xi,yij)

最后对保留的数据集合 Dkeep 做普通的监督微调：

LRSFT(θ)=−E(x,y)∼Dkeep[∑t=1Tlogπθ(yt|x,y<t)]

这一步仍然是最大似然 / 交叉熵训练，不是 PPO 式的策略梯度更新。不同实现会采用 token mask、样本权重和长度归一化等细节。

关键变化是：训练标签不再只来自人工示范，也可以来自当前模型自己生成、再经奖励模型挑选的候选。这是一种带有模型筛选器的自训练过程。

05 · 三种常被混称的机制

论文与工程实践中，“rejection sampling”有时被用来泛指生成多个候选后筛选的过程。阅读论文时，必须先确认它具体指哪一种机制。

机制候选如何保留是否更新模型主要用途关键成本
精确接受—拒绝采样按目标 / 提议密度比随机接受否，采样算法本身不训练模型从难采样的目标分布取样包络常数 M 决定接受率
Best-of-N生成 N 个候选，返回奖励最高者否推理时用更多计算换取更高评分输出每个请求多次生成和打分
RSFT / RAFT每个 prompt 留 Top-1、阈值通过或 Top-K是，用保留样本做 SFT将筛选结果蒸馏回生成模型候选生成、奖励推理和反复训练
术语边界：Best-of-N 在一些 LLM 论文里也被称为 rejection sampling，但它更准确地说是“奖励重排序 / 推理时选择”。如果它没有按 p/(Mq) 进行随机接受，就不要把它说成严格的概率论拒绝采样实现。

对于固定 prompt x，若每个回答的奖励分数互不相同，Best-of-N 选择某个回答 y 的概率可以写成：

πN(y)=F(r(y))N−F−(r(y))N

F 是单次采样奖励分数的累积分布函数，F⁻ 表示严格低于该分数的概率。若存在并列分数，需要另外指定 tie-breaking 规则。

直觉上，N 越大，样本奖励排名靠前的概率越高。但这并不意味着它会在所有维度上变得更好：奖励模型只看它被训练来识别的偏好，模型可能越来越擅长“讨好评分器”，而不是真正完成任务。

06 · 奖励模型与目标分布：一个更深的连接

上面我们用 Top-1 做了排序筛选。现在换一种更有理论解释力的视角：如果我们希望在参考策略 πref 的基础上偏好高奖励回答，同时不希望策略偏离参考模型太远，可以考虑一个 KL 正则化目标：

maxπEy∼π(·|x)[r(x,y)]−βDKL(π∥πref)

β 越大，越不愿偏离参考策略；β 越小，越愿意为了奖励改变输出分布。

对每个 prompt 固定 x，在所有可能回答上做归一化，可以得到最优分布的形式：

π*(y|x)=πref(y|x)exp(r(x,y)β)Zβ(x)

Zβ(x) 是归一化常数，对所有回答 y 求和或积分。这个表达式说明奖励并不是简单替换掉参考策略，而是对参考策略的概率质量进行重新加权。

这个形式把拒绝采样和偏好对齐连在了一起。若以 πref 作为提议分布，并且奖励有已知上界 rmax，那么对从 πref 抽出的回答 y，可以按下式接受：

a(y|x)=exp(r(x,y)−rmaxβ)

因为 r(x,y) ≤ rmax，所以接受概率不超过 1。被接受的分布正比于 πref(y|x) exp(r/β)，恰好对应上面的 KL 正则化最优策略。

但这里有三个理想化前提：奖励上界必须真实有效；候选生成分布必须与推导中的参考策略一致；奖励模型必须足够可信。真实 LLM 的输出空间巨大，奖励上界与概率比往往难以精确获得，因此工程实现通常采用 Best-of-N、Top-K、阈值过滤或偏好对构造，而不是逐 token 精确执行这个接受概率。

07 · 从 WebGPT 到 Llama 2 与 RAFT

拒绝采样不是近几年才出现的 LLM 技巧。它在偏好对齐中有一条清晰的实践脉络，但不同论文把它放在了不同位置：有的把它当推理时基线，有的把筛选结果重新用于训练，还有的进一步研究如何从目标策略分布中构造偏好数据。

WebGPT（2021）：推理时的 Best-of-N

WebGPT 在行为克隆模型或 RL 模型上采样多个答案，再用奖励模型挑出最高分答案。论文将其描述为一种不需要额外训练、但需要更多推理计算的替代方案；实验设置比较了 Best-of-4、Best-of-16 和 Best-of-64。这个例子很重要，因为它清楚展示了“采样更多候选”本身就能成为一个推理时计算策略。

Llama 2（2023）：把最佳候选变成新的监督信号

Llama 2 的 §3.2.3 描述了 Rejection Sampling fine-tuning：对每个 prompt 采样 K 个回答，用当时可用的最佳奖励模型打分，并把最高分回答当作新的 gold response，再对筛选后的数据做微调。论文还指出，他们只在最大的 70B Chat 模型上执行这一步，较小模型使用来自大模型的拒绝采样数据进行蒸馏。到后续迭代阶段，拒绝采样与 PPO 也被组合使用。

RAFT（2023）：把筛选—微调变成迭代框架

RAFT（Reward rAnked FineTuning） 把流程组织成循环：当前模型对每个 prompt 采样 K 个候选；奖励模型排序，保留高质量回答；对保留样本做 SFT；更新后的模型进入下一轮。论文在语言模型和扩散模型上研究了这种 reward-ranked fine-tuning。它的价值在于把生成、排序和参数更新解耦，工程上更接近数据筛选加监督学习，而不是每一步都做策略梯度更新。

RSO 与 RS-DPO（2024）：让拒绝采样参与偏好数据构造

RSO 研究如何用统计拒绝采样从目标最优策略中获取偏好样本；RS-DPO 则从 SFT 策略为每个 prompt 采样多个回答，根据奖励分布构造对比样本，再使用 DPO 优化。这些工作说明拒绝采样不只是“选出一个好答案”，也能成为偏好数据生成与离线优化之间的桥梁。

BoNBoN Alignment（NeurIPS 2024）进一步从理论上分析 Best-of-N 与 RLHF 策略之间的关系，并研究如何训练一个模型去模仿 Best-of-N 的输出分布，减少每次推理都采样 N 次的开销。

08 · 与 PPO、DPO、GRPO 的边界

拒绝采样经常被拿来与 PPO、DPO、GRPO 比较，但它们解决问题的方式并不相同。最简单的辨别方法是问：模型参数到底通过什么信号更新？

方法主要数据 / 信号参数更新方式计算重心典型优势与风险
Best-of-N同一 prompt 的 N 个候选及奖励分数不更新参数，只返回最高分输出推理阶段重复生成与评分简单直接；延迟和成本随 N 增长
RSFT / RAFT奖励筛选后的 prompt–completion 样本对保留样本做 SFT / 最大似然训练离线生成、评分、筛选与微调训练流程简单；依赖奖励模型和覆盖度
PPO-RLHF在线 rollout、奖励、价值估计与优势策略梯度更新，通常带 KL 约束采样、奖励、价值网络和反向传播可持续优化策略；系统复杂且超参敏感
DPO偏好对 (chosen, rejected)直接优化偏好分类式目标离线偏好数据与策略 / 参考模型前向计算不必在优化环节单独训练 RM；依赖偏好对质量
GRPO同一问题的一组 rollout 与组内相对奖励基于组相对优势做策略优化组采样、奖励计算与策略更新减少对独立 critic 的依赖；仍是 RL 更新而非简单筛选

因此，拒绝采样不应该被描述成“比 PPO 更先进”或“DPO 的另一种名字”。更准确的说法是：它提供了一种从当前策略的候选分布中构造高质量监督样本的方法；PPO、DPO、GRPO 则分别定义了不同的优化目标和参数更新机制。它们可以互相作为基线，也可以组合使用。

10 · 什么时候拒绝采样会失效？

1. 奖励模型并不等于真实质量

奖励模型是对人类偏好或任务结果的代理。候选数量 K 增加时，模型有更多机会找到高分回答，也有更多机会找到“奖励模型认为高分、但人类并不喜欢”的漏洞。不能把 reward score 上升直接解释为真实能力或安全性同步上升。

2. 候选空间覆盖不足

如果当前策略几乎不会生成某类正确答案，单纯增加筛选力度也无法创造这些答案。拒绝采样只会从已有候选中挑选，不会保证找到全局最优解。温度、top-p、提示多样性、候选数量和模型能力共同决定了探索范围。

3. 采样预算与收益不是线性关系

增大 K 往往提高 Best-of-K 的最大分数，但生成和奖励推理成本也近似随候选数增加。收益通常会出现边际递减；工程上要在质量、延迟、显存、吞吐和预算之间做权衡。

4. 全局筛选可能改变 prompt 分布

若某些 prompt 天生更容易获得高奖励，全局 Top-K 可能过度保留这些 prompt 的候选，导致困难问题或少数领域被挤出训练集。每个 prompt 独立筛选、分桶配额、去重和覆盖率监控可以缓解这种偏差，但也会改变最终目标。

5. 迭代训练会放大分布漂移与遗忘

每轮都从更新后的策略重新采样，会形成“策略 → 候选 → 奖励筛选 → SFT → 新策略”的反馈闭环。若奖励模型不够稳健，错误偏好可能被一轮轮强化；如果只训练最近一轮的高分数据，也可能遗忘原本具备的能力。需要保留多样化数据、独立评测集和定期人工审查。

实践建议：至少同时监控奖励分数、独立验证器 / 人类偏好、任务正确率、回答多样性、prompt 覆盖率、重复率和原始能力回归。奖励模型分数只能作为一项诊断信号。

11 · 可运行的最小实现

下面的 Python 代码实现有限离散空间上的精确拒绝采样。它先检查分布是否归一化、目标支持集是否被提议分布覆盖，再计算最小包络常数 M=maxᵢ pᵢ/qᵢ。为了让逻辑透明，示例只使用 Python 标准库；它不是 LLM 训练代码。

from collections import Counter
import random


def rejection_sample(target, proposal, n, seed=0):
    """Sample from a normalized discrete target using rejection sampling."""
    if len(target) == 0 or len(target) != len(proposal):
        raise ValueError("target and proposal must have equal nonzero length")
    if any(p < 0 for p in target) or any(q < 0 for q in proposal):
        raise ValueError("probabilities must be non-negative")
    if abs(sum(target) - 1.0) > 1e-9:
        raise ValueError("target must sum to one")
    if abs(sum(proposal) - 1.0) > 1e-9:
        raise ValueError("proposal must sum to one")
    if any(p > 0 and q == 0 for p, q in zip(target, proposal)):
        raise ValueError("proposal does not cover target support")
    if n <= 0:
        raise ValueError("n must be positive")

    ratios = [p / q if q > 0 else 0.0
              for p, q in zip(target, proposal)]
    envelope = max(ratios)
    rng = random.Random(seed)
    states = list(range(len(target)))
    accepted = []

    while len(accepted) < n:
        candidate = rng.choices(states, weights=proposal, k=1)[0]
        q = proposal[candidate]
        accept_prob = target[candidate] / (envelope * q)
        if rng.random() < accept_prob:
            accepted.append(candidate)

    return accepted


def best_of_n(candidates, rewards):
    """A separate LLM-style ranking heuristic; not exact accept-reject."""
    if len(candidates) != len(rewards) or not candidates:
        raise ValueError("candidates and rewards must have equal nonzero length")
    return candidates[max(range(len(rewards)), key=rewards.__getitem__)]


if __name__ == "__main__":
    target = [0.1, 0.3, 0.6]
    proposal = [0.4, 0.4, 0.2]
    samples = rejection_sample(target, proposal, n=50000, seed=7)
    counts = Counter(samples)
    print([round(counts[i] / len(samples), 3) for i in range(3)])
    # Expected to be close to [0.1, 0.3, 0.6].

单元测试不仅检查输出比例接近目标分布，也检查支持集缺失时必须报错。大样本频率测试有随机误差，因此使用合理容差，而不是要求小数点后完全相同。

import pytest
from rejection_sampling import rejection_sample, best_of_n


def test_rejection_sampling_recovers_target_distribution():
    target = [0.1, 0.3, 0.6]
    proposal = [0.4, 0.4, 0.2]
    samples = rejection_sample(target, proposal, n=50000, seed=7)
    frequencies = [samples.count(i) / len(samples) for i in range(3)]
    assert abs(frequencies[0] - 0.1) < 0.012
    assert abs(frequencies[1] - 0.3) < 0.012
    assert abs(frequencies[2] - 0.6) < 0.012


def test_proposal_must_cover_target_support():
    with pytest.raises(ValueError):
        rejection_sample([0.5, 0.5], [1.0, 0.0], n=10)


def test_best_of_n_is_a_separate_ranking_step():
    assert best_of_n(["low", "high", "middle"], [0.1, 0.9, 0.4]) == "high"

12 · 建立正确的心智模型

第一层：统计学。 拒绝采样用容易采样的提议分布，加上严格的密度比接受规则，构造出目标分布的无偏样本。包络条件决定正确性，接受率决定效率。

第二层：LLM 推理。 Best-of-N 让模型生成多个回答，再用奖励模型选择一个输出；它不改变模型参数，只把额外计算花在当前请求上。

第三层：LLM 训练。 RSFT / RAFT 把筛选出的高分回答变成新的监督数据，通过 SFT 更新策略。RSO、RS-DPO 等工作则进一步研究如何把拒绝采样融入偏好数据构造。

最重要的边界：奖励筛选是对精确拒绝采样思想的工程化借用，不应在没有密度比、包络和接受概率的情况下，把 Top-K 排序说成严格的概率采样算法。

读论文时，可以按顺序问四个问题：候选从哪个分布生成？用什么信号判断候选好坏？筛选规则是精确接受概率还是排序启发式？保留结果只用于当前推理，还是会进一步更新模型？回答这四个问题，通常就能看清一篇工作中的“拒绝采样”究竟承担了什么角色。

下一步阅读建议：先看 Importance Sampling 理解采样分布与目标分布的差异，再看 Rejection Sampling，然后沿着 RLHF、DPO 和 GRPO 理解筛选样本如何进入不同的对齐目标。
