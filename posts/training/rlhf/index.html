Understanding RLHF

为什么“预测下一个词”还不等于“回答得让人满意”？从人类偏好到奖励模型，再到 PPO 与 KL 正则化，用一条可计算的因果链理解经典 RLHF。

核心案例 · Ouyang et al., 2022约 32 分钟训练与对齐

01 · 为什么 SFT 仍不够？

预训练优化的是“下一个 token 有多像训练语料”；SFT 优化的是“能否模仿标注员写出的一个示范答案”。但真实问题经常有多个都说得通的回答：哪个更准确、更直接、更符合用户意图？

假设用户希望“一句话解释 KL 散度”。长篇回答和简洁回答都可能符合语言分布，SFT 只把指定示范写成高似然样本；人类比较则能表达“在这个上下文里更偏好 A 而不是 B”。这也是 Stiennon et al. (2020) 用人类偏好改进摘要质量的动机。

SFT 目标（序列级记号）
LSFT(θ)=−E(x,y*)∼Ddemo[∑t=1Tlogπθ(y*t|x,y*<t)]
x 是提示，y* 为示范答案，T 是答案 token 数。实现时可按 token 或样本做归一化；公式省略这些工程细节。

常见误区：RLHF 不是“让模型随机试错直到对了”。在语言模型的经典方案中，SFT 先给出可用初始策略，后续优化针对人类排序学得的奖励代理。

02 · 一张图看懂经典 RLHF

经典 InstructGPT 由三个独立但串联的优化过程组成：示范学习 → 偏好建模 → 策略优化。每一步使用的数据、可训练参数和损失函数都不同。Ouyang et al. (2022), Figure 2 / §3.5。

阶段 1 · SFT

输入：(prompt, demonstration)。输出：会基本听指令的策略模型。

阶段 2 · RM

输入：同一 prompt 下候选答案的排序。输出：给完整回答打一个标量分数的模型。

阶段 3 · PPO

输入：prompt、策略采样回答、RM 分数和 KL 惩罚。输出：更新后的策略。

不是所有“偏好对齐”都要 PPO。RLHF 是方法范畴；PPO 是某一类在线策略优化器。DPO 等后续算法可以直接从偏好对学习，而不显式运行这个三阶段循环。

03 · 人类偏好如何变成训练信号？

标注员在相同 prompt x 下比较多个候选完成；记偏好的回答为 yw，另一个为 yl。我们不要求标注员为每篇回答给出绝对的“质量分”，而是学习它们的相对次序。

偏好概率与对数损失
Pφ(yw≻yl|x)=σ(rφ(x,yw)−rφ(x,yl))
LRM(φ)=−E(x,yw,yl)[logσ(rφ(x,yw)−rφ(x,yl))]
σ(z)=1/(1+e−z)。InstructGPT Equation (1) 还按同一排序内的组合对数进行归一化，并把同一 prompt 的相关比较分组训练。

因此，奖励分数存在平移不确定性：若每个输出都加同一个常数 c，胜负概率完全不变。InstructGPT 在进入 RL 前，对 RM 评分的偏置做了归一化，使示范数据的平均得分为 0（§3.5）。

论文中每个提示的排序候选数 K 在 4 到 9 之间，一个完整排序可导出 K(K−1)/2 个两两比较。这些比较并不统计独立；不应该简单地当作完全独立样本重复梯度更新。

04 · 交互实验：偏好概率如何变化？

固定 loser 分数为 0，点击不同的 winner–loser 分差。你会看到 sigmoid 将任意实数差值变成 (0,1) 之间的预测概率。

偏好概率 · TOY LABΔ = r(w) − r(l)
P(winner ≻ loser) ≈ 88.1%

这里的分数是可控玩具输入；没有训练 RM，也没有从真实标注数据估计置信度。试着对比 Δ=0 和 Δ=4。

当 Δ=0，模型给出的偏好概率是 50%；当 Δ 变大，概率趋近 100%。这解释了模型为何只关心分数差，也提示了重要风险：一个代理评分器可以非常确信，却仍然不反映真正的人类判断。

05 · PPO 阶段到底优化什么？

现在我们有了会生成答案的策略 πθ，以及一个评分器 rφ(x,y)。对每个提示 x，从当前策略抽样完整回答 y，RM 给出终止时的分数，然后让策略倾向产生更高分的回答。语言模型的一次 response 可看作 bandit episode；实现中通常仍将生成拆成 token 级 action 以估计优势和更新参数。

经典 RLHF 的 KL 正则化目标（不含 pretraining mix）
maxθEx∼D,y∼πθ(·|x)[rφ(x,y)−βlog(πθ(y|x)πref(y|x))]
这里 πref 是冻结的 SFT 策略；对 y∼πθ 取期望后，log 比值项对应 DKL(πθ || πref)。β≥0 控制偏离参考策略的代价。

由于自回归概率可分解，序列的 log 比值也可按时间相加：log π(y|x) / πref(y|x) = Σt[log π(yt|st) − log πref(yt|st)]。这使 KL 惩罚能分配到每个 token。注意：单次采样的 log-ratio 可能为负；其在当前策略分布下的期望才是非负的 KL 散度。

InstructGPT 的完整 Equation (2) 对 PPO-ptx 还包含 γ Ex∼Dpretrain[log πθ(x)]，以混合预训练梯度缓解部分公开 NLP 任务上的性能回退；论文中将 γ=0 的版本称为 PPO，默认提及的 InstructGPT 通常指 PPO-ptx。不能把该项当作所有 RLHF 系统的必选模块。

06 · 为什么会有两种不同的“约束”？

读 RLHF 训练代码时经常看到两个都像“让策略别走太远”的量，实际却不是同一个约束。

PPO 的 clipped surrogate（单个 token 的简化写法）
Lclip(θ)=Et[min(ρt(θ)At,clip(ρt(θ),1−ε,1+ε)At)]
ρt(θ)=πθ(at|st)πold(at|st)
πold 是生成当前 batch 时的策略；At 是估计的优势函数。这是 Schulman et al. (2017) 的 PPO-Clip 核心思想，不是完整语言模型 PPO 训练损失。

Reference KL 对齐“初始化时的 SFT 行为”，而 PPO clip 对齐“当前更新前的行为”。某个训练步对 πold 改动很小，不代表经过许多步后仍靠近 πref；反过来，Reference KL 也不代替 PPO 的重要性采样与裁剪。

07 · 交互实验：KL 系数改变会怎样？

有两个候选策略输出，A 的奖励更高，但相对参考模型的 log-ratio 也更高；B 的奖励稍低，却更接近参考模型。通过改变 β 看“高奖励 / 小偏移”的权衡。

REFERENCE PENALTY · TOY LAB
候选 A

RM = 1.6

采样 log-ratio = 1.4

目标贡献 ≈ 1.60
候选 B

RM = 1.0

采样 log-ratio = 0.1

目标贡献 ≈ 1.00

当前 A 的单样本贡献较高。

计算的是单个采样序列的 r−β·log(π/πref)，不是实际策略分布的完整期望 KL，也不构成 RLHF 性能实验。

β 过小可能诱导评分器过优化；β 过大会妨碍策略改善偏好。真实训练需结合 reward、KL、任务质量和偏好评测共同选择系数。InstructGPT 的附录 E.7 专门讨论了 KL 系数敏感性。

08 · 用张量形状读懂训练系统

如果已经熟悉 Transformer，下列形状可以把抽象的 RLHF 对应到模型和显存。假设批量 B、回答长度 T、词表大小 V：

量示意形状在更新中做什么
prompt + response token IDs[B,T]（此处仅表示生成的 response 部分）作为策略和参考模型的条件输入
策略 logits[B,T,V]逐 token 取出已采样 token 的 log-prob
策略 / 参考 log-probs[B,T]计算 token 级 reference log-ratio
奖励模型分数[B]对完整 prompt-response 生成标量奖励
Value 预测 / advantage[B,T]构造 token 级 actor–critic 更新

上表只展示概念维度。实际系统通常以完整的 prompt+response 串行输入，需使用 attention mask 和 response mask，避免将 padding 与 prompt token 错算进策略损失。不同 PPO 实现可能将最后一步奖励放到 EOS 位置，并用 GAE 估计 advantage；这些是工程策略，不是 InstructGPT 论文中所有实现细节的逐行复刻。

LLM Infra 视角：在线 RLHF 往往同时涉及策略、冻结参考策略、奖励模型和价值函数，包含批量生成、模型前向评分以及多轮更新。哪些模型共享 backbone、如何分片、如何缓存旧策略 log-probs，决定了实际内存与吞吐；不能把“4 个角色”直接等同于必须部署 4 份独立 GPU 模型。

09 · 可运行的最小数学检查

先验证三件事：偏好分数差产生 sigmoid 概率；KL 在分布相同时为零；PPO clipped surrogate 的正负优势符号不同。以下独立 Python 脚本不用深度学习框架，只验证核心表达式，并没有训练语言模型或真正运行 PPO。

"""Minimal deterministic illustrations for RLHF math; not a PPO trainer."""
from __future__ import annotations
import math

def preference_probability(winner_score: float, loser_score: float) -> float:
    difference = winner_score - loser_score
    if difference >= 0:
        return 1.0 / (1.0 + math.exp(-difference))
    value = math.exp(difference)
    return value / (1.0 + value)

def pairwise_loss(winner_score: float, loser_score: float) -> float:
    difference = winner_score - loser_score
    return max(-difference, 0.0) + math.log1p(math.exp(-abs(difference)))

def discrete_kl(policy: list[float], reference: list[float]) -> float:
    assert len(policy) == len(reference) and policy
    assert all(p > 0 and q > 0 for p, q in zip(policy, reference))
    assert abs(sum(policy) - 1.0) < 1e-10
    assert abs(sum(reference) - 1.0) < 1e-10
    return sum(p * math.log(p / q) for p, q in zip(policy, reference))

def ppo_clipped_objective(ratio: float, advantage: float, epsilon: float = 0.2) -> float:
    """The single-token clipped surrogate (maximize this), not full PPO."""
    assert ratio > 0 and 0 < epsilon < 1
    limited = min(1 + epsilon, max(1 - epsilon, ratio))
    return min(ratio * advantage, limited * advantage)

def run_checks() -> None:
    assert math.isclose(preference_probability(2, 0), 0.8807970779778823)
    assert preference_probability(2, 0) > preference_probability(0, 2)
    assert math.isclose(pairwise_loss(0, 0), math.log(2))
    assert math.isclose(pairwise_loss(2, 0), pairwise_loss(12, 10))
    assert math.isclose(discrete_kl([0.5, 0.5], [0.5, 0.5]), 0.0)
    assert discrete_kl([0.9, 0.1], [0.5, 0.5]) > 0
    assert math.isclose(ppo_clipped_objective(1.5, 1.0), 1.2)
    assert math.isclose(ppo_clipped_objective(0.5, -1.0), -0.8)

if __name__ == "__main__":
    run_checks()
    print("RLHF toy math checks passed")

源码：mini_rlhf.py。运行 python posts/training/rlhf/mini_rlhf.py 以执行内置断言。

如果要把它扩展到可复现实验，至少还需：固定基座模型与 tokenizer、记录数据许可证与 prompt split、实现可训练 RM 与 value head、保留 πold / πref log-prob、GAE、梯度裁剪、KL 控制、人工偏好评测，以及多随机种子的结果记录。

10 · 原论文究竟证明了什么？

Ouyang et al. (2022) 在其 API prompt 分布的人类偏好评测中，报告 1.3B InstructGPT 的输出被偏好于 175B GPT-3（Abstract / Figure 1）。这比较的是特定提示分布上的指令遵循与偏好，并非声称小模型在所有知识、推理或任务上都超过大模型。

85 ± 3%175B InstructGPT 对 175B GPT-3 的直接人类偏好胜率
71 ± 4%175B InstructGPT 对 few-shot GPT-3 的直接人类偏好胜率

来源：InstructGPT §4.1，PDF p. 11。模型大小、baseline 和评测提示分布固定；这里不是本网站重跑实验的测量值。

论文还观察到对明确约束的遵守改善、部分闭卷任务的编造减少，但也报告偏见指标未必同步改善，以及某些公开 NLP 任务的性能回退；混合预训练梯度的 PPO-ptx 可以缓解但并不消除全部回退（§4.2、Appendix E）。

数据边界同样重要：原文 §3.3 写明训练任务提示超过 96% 是英语，§3.4 报告约 40 名经过筛选的合同标注员。标注员判断是实际用户意图的代理，不能自动代表所有语言、文化与使用情境。

11 · 奖励不是价值本身

Reward hacking / 过优化。策略能学会提升 RM 分数，却不一定提升真正的人类满意度。KL 正则和独立的人类评估能提供缓冲，但都不是原则上的完美解决方案。

偏好聚合有局限。成对比较受标注指南、群体差异、问题歧义、数据覆盖和回答长度偏好影响。RM 拟合的是这些观测偏好，不是无条件真实的“善 / 恶”或“正确 / 错误”。

离线与在线的区别。经典 PPO-RLHF 要从不断变化的当前策略采样；如果用一份固定偏好数据直接优化参数，就属于另一类离线偏好优化路线。DPO（Rafailov et al., 2023） 把常见 KL 正则化 RLHF 目标重新参数化为偏好分类损失，省去显式 RM + PPO 训练环节，但这不意味着它的所有假设和行为与 PPO 完全等价。

Bai et al. (2022) 则探讨 helpfulness / harmlessness 双目标、红队偏好数据和迭代在线更新；这些是值得对照的演进，而不是应该倒写进 InstructGPT 的原始设计。

12 · 记住这一条因果链

为什么有 RLHF？语言建模学“像文本”，示范微调学“像样例”，人类比较进一步表达“在两个可行输出中更倾向哪个”。奖励模型把比较压缩为标量代理，RL 优化策略，参考 KL 与 PPO 裁剪各自在不同层面阻止训练偏移过大。

因此，真正理解 RLHF 需要同时问四件事：谁提供偏好？RM 学到了什么？策略如何被更新？怎样证明对用户而非评分器真的更好？
