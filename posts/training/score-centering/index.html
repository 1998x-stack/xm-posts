LLM POST-TRAINING · POLICY OPTIMIZATION

Score Centering

从 Training–Inference Mismatch 出发，推导 Off-policy Policy Gradient 中的 Drift / Signal 分解，以及一种不依赖概率比裁剪的加性修正。

原论文：2026-09-17研究脉络更新：2026-11-24预计阅读：38 分钟关键词：TIM · Policy Staleness · Top-k
01 / THE MISMATCH

同一份模型权重，为什么训练与推理会得到不同的策略？

LLM 强化学习的一条典型链路是：Inference Engine 负责生成 rollout，Training Engine 负责计算 log-probability 与梯度。理论上它们表示同一个参数化策略；工程上，它们未必实现同一个数值分布。

把训练器在历史前缀 h 上的 next-token 分布记作 pθ(v | h)，把真正生成 rollout 的 sampler / behavior policy 记作 q(v | h)。本文固定采用这个记号：p 是 learner / trainer，q 是 sampler / behavior policy。

这种差异并不一定来自模型权重更新。原论文归纳了几类来源：

数值与实现差异

训练与推理使用不同精度、不同 kernel、不同 reduction 顺序或不同执行框架。即使参数相同，浮点运算的非结合性也可能造成 logits 偏差。

策略陈旧性

异步 rollout、分离式训练与推理、长时间运行的 Agent episode，使得一条轨迹可能来自较旧 checkpoint，甚至不同 token 位置来自不同版本。

还要区分两个概念：TIM 是相同或相近参数在训练 / 推理实现上的分布差异；policy staleness 是 rollout 生成时的行为策略与当前 learner 参数版本不同。两者都会让 q 与 p 不一致，但工程成因不同。原论文 §2.1 对此作了区分。

核心问题：如果我们拿 q 生成的 token，却用 p 的 log-probability 计算 policy gradient，梯度里除了“哪些动作带来更高 reward”的信号之外，会不会多出一个与 reward 具体落在哪个 token 无关的系统性分量？

因此，不宜把 Score Centering 称为替代 PPO / GRPO 的“终极 RL 算法”。从公开论文的定义看，它是一种针对 training–inference mismatch 的 policy-gradient correction，可叠加在不同训练目标之上；原论文还明确展示了它与 TIS / MIS 的组合。

02 / IMPORTANCE SAMPLING

Importance Sampling：用概率比修正分布，但要付出方差代价

先回到基本 policy gradient。对完整 response y，目标策略 pθ 的期望回报梯度为：

∇θJ(θ)=Ey∼p[R(y)∇θlogp(y)]

rollout 实际来自 q。若 q 对 p 的目标分布具有支持覆盖（p 可能生成的 response 在 q 下也有非零概率），可以用完整轨迹 importance ratio 改写期望：

Eq[pqR∇θlogp]=Ep[R∇θlogp]

对自回归 response，完整序列概率是 token 条件概率的乘积：

r(y)=p(y|x)q(y|x)=∏t=1Tp(yt|ht)q(yt|ht)

序列 ratio 是逐 token ratio 的乘积，长 response 下容易出现极端权重。工程上常见 token-level IS、truncated IS、masking、PPO-style clipping 等控制手段，但它们对应不同 surrogate objective；不能把所有算法简单等同于同一种 clip。

这里必须区分：完整序列 IS 在支持条件满足时可重写完整 response 的目标期望；token-level IS 通常对应以 behavior-policy occupancy / sampled history 为基础的 surrogate。它并不会自动修正整条轨迹的分布偏移。

本节结论：IS 数学上并没有错；完整 ratio 的方差可能很高。裁剪、截断和 mask 是为稳定性付出的偏差代价。Score Centering 提供的是另一种加性修正，不是新的 ratio clip。
03 / THE SCORE

Score 不是概率：它是 log-probability 对参数的梯度向量

固定历史前缀 h，训练器 pθ 对候选 token v 的 score 定义为：

sv(h):=∇θlogpθ(v|h)∈Rd

其中 d 是模型参数维度。log p(v | h) 是标量；对 θ 求梯度之后的 score 是 d 维向量。Score Centering 做的是向量中心化，不是对 token log-probability 做减均值，也不是对 reward 做减均值。

在 on-policy 情况下，token 从 pθ 自身采样。score 的期望满足 score-function identity：

Ep[sv]=∑v∈Vpv∇θlogpv=∇θ∑v∈Vpv=0

这个恒等式是整篇文章的支点：策略用自己的分布采样时，所有 token 的期望 score 必然抵消。一旦样本由 q 产生，梯度却按 p 计算，这个抵消关系就不再自动成立。

04 / DRIFT VS SIGNAL

核心推导：把 Off-policy Gradient 拆成 Drift 与 Learning Signal

在固定 prefix h 下，令 A 表示该 token / rollout 对应的 advantage 或 reward 权重。先把 A 视为随机标量，s 是参数空间向量。协方差恒等式给出：

Eq[As]=Eq[A]Eq[s]+Covq(A,s)

为什么 drift 会表现得像对 sampler 的蒸馏？

在固定 q（对 θ 求导时 stop-gradient）时：

s̄q=∑v∈Vq(v)∇θlogp(v)=−∇θDKL(q∥p)

这里写清楚 KL 的方向很重要：是 q → p，即固定 sampler 分布 q，把 trainer p 往 q 拟合。不同文献对 forward / reverse KL 的口头命名可能相对于 teacher/student 角色变化，因此文章直接写明 D_KL(q || p)，避免只写“reverse KL”。

如果 sampler 是量化版本、旧 checkpoint，或者存在系统性数值偏差，vanilla policy gradient 会在每个 prefix 上额外把 trainer 拉向 sampler。若 sampler 随训练不断从 trainer 同步，这个方向可能形成正反馈。

05 / GROUP BASELINE

为什么 GRPO 的组内 Advantage 中心化并没有消除所有 Drift？

GRPO 对同一 prompt 的多条 rollout 做 group-relative normalization，组内优势均值接近零，为什么仍然会有 drift？关键在于两个期望的条件范围不同：

  • GRPO 的 group mean 在同一 prompt 的完整 rollout 集合上计算。
  • Drift 项中的 (E_q[Amid h]) 是在某个具体 token prefix h 下计算。

因此，group centering 可以缩小 drift，却不保证在每个 prefix 上将其消除。原论文 §4 对此有直接讨论。

不要混淆两种中心化：Group baseline 中心化 reward / advantage；Score centering 中心化参数梯度 score。两者对象不同，条件范围也不同。
06 / THE METHOD

Score Centering：减去 sampler 的期望 score

定义固定 prefix h 下的 sampler expected score：

s̄q(h):=Eq[s|h]

把原始 score 替换为 centered score：

s̃v(h)=sv(h)−s̄q(h)

由定义可得：

Eq[s−s̄q|h]=0

因此 score-centering 后的期望更新为：

Eq[A(s−s̄q)|h]=Covq(A,s|h)

这不是对 advantage 进行新的 baseline 估计，而是直接修正 score 的期望。原论文称之为 additive correction：不需要为 sampled token 乘一个随机 importance ratio，就能消除这部分 drift。

交互式：Bernoulli policy 的 Drift / Signal 分解

把 vocabulary 简化成两个动作。trainer 选择动作 1 的概率为 p，sampler 的概率为 q；A(1)=1.5、A(0)=−0.5。拖动滑块，观察原始更新如何拆成 drift 与 covariance signal。

07 / TOP-K ESTIMATION

Top-k：不保存完整词表分布，怎样近似期望 score？

直接计算 bar_s_q = Σ_v q(v | h) s_v(h) 需要每个 token 的 sampler 概率。以 Qwen3 词表约 152K 为例，单个 token 的 full-vocabulary FP32 log-probability 约 608 KB；batch 1024、每条 rollout 32K token 时，保存整份分布会达到约 20 TB 量级。

原论文只记录 sampler 的 Top-k head。令 H 为 sampler top-k token 集合，T 为其余尾部。只保存 token ID（int32）与 log-probability（float32）时，通信 / 存储量约为 8 × T × K bytes；32K token、K=128 约为 32 MiB，远小于 full-vocabulary 分布，但还未计入 padding、拷贝和 trainer 侧张量：

q^v=qvv ∈ Hρpvv ∈ T,ρ=1−∑qv1−∑pv

ρ 是 sampler 剩余尾部质量与 trainer 尾部质量的比值。我们用 trainer 的尾部形状近似 sampler 的尾部，再将概率质量重新缩放到 sampler 实际剩余质量。

利用 Σ_v p(v | h) s_v(h) = 0，期望 score 可以化简为：

Eq^[s]=∑v∈H(qv−ρpv)sv

原本需要遍历完整词表的期望 score，最终只需要计算 k 个 head token。原论文报告 k=128 是保守默认值，k=32 在其测试设置中也与 full score centering 表现相当。这是论文实验观察，不是对任意模型、采样过滤和分布失配的无条件误差保证。

实现注意：Top-k log-probability 不能先重新归一化到和为 1；需要保留 sampler 原始 head mass。被采样 token 即使不在 top-k head 中，也要单独保留它自己的 sampler log-probability，尤其是在组合 IS 时。
08 / AUTOGRAD IMPLEMENTATION

把向量中心化写成一个标量 loss

自动微分框架中不必手写每个参数维度上的 score 向量。把期望 score 写成 trainer log-probability 的加权和，并对系数 stop-gradient：

L=−Alogp(yt|h)−∑sgqv−ρpvlogp(v|h)

sg 表示 stop-gradient。第二项的系数只作为常量权重，不对 sampler 概率、尾部质量比或 residual 系数反向传播。对 θ 求导后，得到 sampled token score 减去 Top-k 近似的 sampler expected score。

import torch

def score_centering_loss(
    train_logp, sampler_topk_logp, topk_ids,
    sampled_token, advantage, eps=1e-6
):
    # train_logp: [B, T, V], normalized over full vocabulary
    # sampler_topk_logp / topk_ids: [B, T, K]
    # sampled_token / advantage: [B, T]

    head_logp = train_logp.gather(-1, topk_ids)
    token_logp = train_logp.gather(
        -1, sampled_token[..., None]
    ).squeeze(-1)

    p_head = head_logp.exp()
    q_head = sampler_topk_logp.exp()
    p_tail = (1.0 - p_head.sum(-1)).clamp_min(eps)
    q_tail = (1.0 - q_head.sum(-1)).clamp_min(eps)
    rho = q_tail / p_tail

    residual = q_head - rho[..., None] * p_head
    correction = (residual.detach() * head_logp).sum(-1)
    return -advantage.detach() * (token_logp - correction)

这是展示核心 loss 的教学片段，不是完整 RL trainer。实际系统还要处理 completion mask、token normalization、分布过滤、数值稳定性、采样概率捕获与分布式并行。

作者官方仓库提供完整 JAX / PyTorch 参考实现、测试与训练配置：martin-marek/score-centering。其中实现还保留 sampled token 自身的 sampler log-probability，并支持在 score centering 外组合 TIS / MIS。

09 / ESTIMATOR BOUNDARIES

Bias 与 Variance：消除了 Drift，不代表估计量变成无偏

假设在同一个 prefix h 上、A 的定义相同且期望可精确计算：

gSC(h)=Covq(A,s|h),gtarget(h)=Covp(A,s|h)

二者的差是：

gSC−gtarget=Covq(A,s)−Covp(A,s)

所以，SC 消除了 (E_q[A]E_q[s])，但保留下来的 covariance 仍然是在 q 下测量的，不必等于目标策略 p 下的 covariance。实际训练中 prefix 本身也由 q 的轨迹分布产生，整个状态 / 历史分布差异仍然存在。

为什么不能笼统说“SC 一定降低方差”？

SC 减去的是固定 prefix 下的确定性向量 bar_s_q(h)，而不是一个随机 IS ratio。它能避免乘上极端 importance ratio 的额外随机放大；但“避免 ratio variance”不等于“对所有 reward 与采样条件都降低梯度方差”。原论文把 SC 定位为 bias / drift correction，而不是一般性的 variance-reduction theorem。

当 A 是常数时，SC 后的期望更新为零；但对每个样本减去一个确定性 score 均值，并不会自动改变 score 随 token 变化的方差。若 A 本身随机并与 score 相关，最终估计量的方差变化还取决于二者联合分布。

因此不能推出：SC 一定比 IS bias 更小；一定比原始 off-policy gradient 更接近真实目标；或者一定降低任何训练设置下的 gradient variance。它保证的是特定 drift 项被抵消，bias / variance 的整体排序要由分布、advantage、截断策略和数据生成过程决定。
10 / SFT VS ONLINE RL

为什么离线 SFT 通常稳定，而在线 RL 对小小的 mismatch 也敏感？

原论文的解释不只是“RL 有负样本，SFT 没有负样本”，而是把两个因素分开考察：reward mode 与 sampler 是否随着 learner 一起移动。

在原论文受控实验里，离线训练下 +1/0 的非负奖励模式最稳定；在线训练且存在 TIM 时，+1/0 反而最不稳定，而 group-centered、包含正负 advantage 的模式相对更稳定。论文据此指出，正向样本的在线蒸馏会让 trainer 追随一个有偏、且会随 trainer 更新而刷新的 sampler。

这有助于理解 SFT / RFT 与在线 RL 的差别：经过筛选的正样本可以形成固定的离线监督目标；在线 RL 的采样分布却不断随模型变化，负 advantage、组内归一化和长程 rollout 会改变梯度动力学。但不能断言所有 RFT 都稳定，或所有负样本训练都会崩溃。负梯度对 softmax 其他 token 的影响也不是均匀分配，而由当前 logits 与梯度共同决定。

离线 SFT / 正样本蒸馏

教师分布固定；训练目标主要提高目标 token 的似然。teacher 不会因为 student 更新而同步改变。

在线 RL / 移动 sampler

奖励和 advantage 随 rollout 变化；sampler 周期性刷新；TIM 产生的 drift 可能通过反复同步累积。

值得做的独立实验是：在相同数据、初始化和训练预算下，比较正样本-only、正负 advantage、group-centered advantage，以及冻结 teacher / 每步刷新 teacher 的组合，并测量 entropy、policy KL、gradient norm 与 reward。

11 / PAPER EVIDENCE

原论文究竟验证了什么？

框架支持并不意味着实现语义完全相同。TRL AsyncGRPOTrainer 的 score-centering 目标默认结合 Masked Importance Sampling：权重在配置区间内保留，区间外置零；其默认 sampler logprob 候选数为 8。NeMo-RL 则明确说明，它把中心化项加到既有 clipped objective 上，并不声称精确中心化任意 PPO clipped gradient；若使用 top-k / top-p sampling filters，还需要 sampler replay，让 trainer 与 sampler 在相同 support 上计算概率。

真实训练中还要监控 sampler 与 trainer 的概率差异、Top-k tail mass、importance ratio 分布、有效样本量、entropy、gradient norm、policy KL 和 sampler refresh interval。尤其在异步长轨迹任务中，局部 token 修正不能替代 trajectory-level staleness 治理。

原论文的工程建议：当 trainer 在 sampler 同步之间可能移动较远时，优先评估 SC 与 TIS / MIS 的组合；在严重 staleness 实验中，组合方法优于单独 SC。对于数值量化 mismatch，单独 SC 在论文测试中也表现出较强稳定性。
13 / BEYOND SCORE CENTERING

从 SC 到 RSC：当 learner 离 behavior policy 太远怎么办？

2026 年 11 月 16 日公开的后续预印本 Regularized Score Centering 指出：即使 score centering 去掉 reward baseline 对期望更新的贡献，剩下的 token advantage 仍然依赖 behavior policy 生成的后续 continuation。

在固定历史 h 下，同一个 token 的后续回报可以因后续策略不同而变化。因此 behavior continuation 下的 advantage A^μ(h,a) 不一定等于 learner continuation 下的 A^{πθ}(h,a)。SC 也不会改变已经采样到的 prefix 分布。

RSC 在 SC 或 SC+TIS 的基础上，增加 learner 与 behavior policy 之间的 token-level reverse KL 正则化：

DKLπθ(·|h)∥μ(·|h)=∑πθ(a|h)logπθ(a|h)μ(a|h)

这不是原始 SC 的一部分，而是针对其适用边界的后续扩展。RSC 论文报告数学推理和多个 Agentic benchmark 实验，尤其关注长程任务与较大的 sampler refresh interval。它仍是 2026 年 11 月的研究预印本，结论要结合任务和实验设定理解。

14 / RESEARCH QUESTIONS

值得继续研究的六个问题

  1. Moving teacher 的因果作用：冻结 sampler、每 N 步刷新 sampler、每步刷新 sampler，是否呈现不同 drift 累积曲线？
  2. 奖励符号与离线稳定性：正样本-only、正负 advantage、group-centered reward 在固定 teacher 与 moving teacher 下是否产生不同 entropy / gradient dynamics？
  3. Top-k 近似误差：比较 K=8、16、32、64、128 与 full distribution，测量 expected-score error、通信、显存和训练结果。
  4. Advantage 来源：比较 outcome reward、group-centered sampled advantage、critic 估计和 Monte Carlo conditional advantage；确认误差来自 q 的动作分布，还是 q 的后续 continuation。
  5. 数据质量控制：在 reward verifier 不变时加入 rollout 质量筛选，区分低质量轨迹、负 advantage 与数值 mismatch 对崩溃的独立影响。
  6. 组合策略：比较 SC、SC+TIS、SC+MIS、RSC 与 RSC+TIS，特别关注长程 Agent、工具调用和高 staleness 场景。
