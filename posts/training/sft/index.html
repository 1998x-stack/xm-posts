01 · 为什么模型会续写，却不一定会回答？

一个预训练语言模型已经能写文章、补代码、续故事。可是，当用户说“请用三句话解释梯度下降，并给一个直观例子”时，它不一定会稳定地把这句话当成一条需要完成的指令。

这不是因为模型完全没有相关知识，而是因为训练目标与用户希望得到的行为并不完全相同。预训练通常让模型在大量文本上学习下一个 Token 的条件概率；用户则希望模型识别任务、理解约束、组织回答，并在合适的位置停止。

想象你学过大量教材和网页，已经很擅长接着一句话往下写。但老师第一次要求你“先给结论，再列三个步骤，最后解释一个反例”，你可能知道知识，却不知道这份作业期待的组织方式。SFT 提供的正是这种“任务输入—期望输出”的示范。

先记住核心句：SFT 不会凭空创造一个全新的语言模型；它使用带有目标输出的监督样本，继续调整已有模型参数，让模型在给定输入条件下更倾向生成示范中的回答。

02 · SFT、Instruction Tuning 与 Continued Pretraining 的边界

“Fine-tuning”是一个很宽的词。为了避免把所有训练都叫作 SFT，需要先区分三个层次：

  • Supervised Fine-Tuning（SFT，监督微调）：用输入—目标输出的监督样本继续训练模型。输入可以是指令、上下文、领域文本或任务条件；目标是让模型提高对目标输出分布的似然。
  • Instruction Tuning（指令微调）：SFT 的一个重要子类，训练样本的输入以自然语言指令为核心，通常还包含可选上下文，输出是希望模型给出的回答。
  • Domain / Task Fine-Tuning（领域 / 任务微调）：同样可能采用 SFT，但目标更具体，例如法律文本抽取、医学报告结构化或代码补全。它不一定训练通用助手式指令行为。
训练阶段 / 方法主要数据直接优化的信号主要回答的问题
预训练（Pretraining）大规模原始文本下一个 Token 的似然“文本接下来可能是什么？”
继续预训练（Continued PT）领域或更新后的原始语料仍然是下一个 Token 似然“怎样适应新的文本分布？”
SFT输入与示范输出配对目标 Token 的交叉熵 / 负对数似然“给定这个输入，怎样生成目标回答？”
偏好学习（RM / DPO）优选 / 非优选回答对偏好排序或隐式偏好目标“两个可行回答中，人更喜欢哪一个？”
强化学习后训练策略采样、奖励或验证器反馈奖励驱动的策略目标“怎样让策略获得更高的反馈？”

因此，SFT 与 LoRA 也不是同一维度：SFT 描述监督信号与优化目标，LoRA 描述参数更新的参数化方式。你可以做全参数 SFT，也可以用 LoRA / QLoRA 实现 SFT。相同地，SFT 常作为 RLHF 或 DPO 之前的初始模型，但它本身不等于 RLHF 或 DPO。

03 · SFT 的数学目标：让模型给示范回答更高概率

3.1 从一个输入—输出样本开始

把一条监督样本写成一对序列：输入 x 与目标回答 y = (y₁, y₂, …, yₜ)。输入可以包含 system 指令、用户问题、检索上下文或多轮历史。模型按自回归方式逐个预测回答 Token。

公式 1 · 目标回答的负对数似然

ℒSFT(θ)=−𝔼(x,y)∼D[∑t=1|y|logπθ(yt|x,y<t)]

θ 是模型参数；D 是监督数据分布；πθ 是模型给出的下一个 Token 条件分布；y<t 表示当前 Token 之前已经给定的回答前缀。

这条公式的直觉很简单：假设标准答案的下一个 Token 是“梯”，模型给“梯”的概率越高，负对数损失越小。每个目标 Token 都贡献一个训练信号，反向传播会调整参数，使示范序列整体变得更容易被模型生成。

3.2 Teacher Forcing：训练时使用正确前缀

训练第 t 个回答 Token 时，模型看到的是输入 x 与真实回答前缀 y<t，而不是模型刚刚采样出来的预测。这就是自回归监督训练中常见的 Teacher Forcing。它让训练目标稳定、并行化友好；推理时模型则必须使用自己已经生成的前缀。

公式 2 · 一步梯度更新（示意）

θnew=θold−η∇θℒSFT

η 是学习率。实际训练常用 AdamW 等优化器；这里用梯度下降表达“损失影响参数”的方向，不代表某篇论文唯一的优化器配置。

3.3 最容易被忽略的工程细节：Loss Mask

一条对话序列里，system 与 user 部分是模型回答时必须读取的上下文，但它们未必应该作为模型需要模仿的目标。常见的 response-only SFT 会让整条序列进入前向计算，只对 Assistant 回答 Token（以及需要学习的结束标记）计算损失。

ℒmask=−1∑j=2Tmj∑j=2Tmjlogpθ(zj|z<j)

两个 Mask 不要混为一谈：Attention Mask 约束模型能否读取某些位置（例如 padding 或未来 Token）；Loss Mask 约束某个目标 Token 是否计入损失。提示词通常应该被模型读取，却可以不计入 response-only loss。

3.4 从标签到交叉熵：实现时怎样对齐位置？

对 Decoder-only 模型，位置 t 的 logits 预测位置 t+1 的 Token。因此，手写损失时要做一次 shift：预测端去掉最后一位，标签端去掉第一位。被忽略的位置通常使用 -100 这样的 ignore index。

import torch.nn.functional as F

# input_ids: [batch, seq_len]
# assistant_mask: True only on assistant target tokens
labels = input_ids.clone()
labels[~assistant_mask] = -100

# 若自行计算 loss，需要手动 shift 一次
shift_logits = logits[:, :-1, :].contiguous()
shift_labels = labels[:, 1:].contiguous()

loss = F.cross_entropy(
    shift_logits.view(-1, shift_logits.size(-1)),
    shift_labels.view(-1),
    ignore_index=-100,
)
实现警告：如果使用 Hugging Face 等因果语言模型接口并把 labels 直接传给模型，很多模型会在内部完成 causal shift。此时不要再手动 shift 一次。具体行为要以所用模型类与训练器版本为准。

另一个重要选择是：多轮对话中，究竟监督所有 Assistant 回合，还是只监督最后一轮？前者让模型学习连续对话行为；后者有时用于避免把合成上下文中的模型生成内容再次当作高质量目标。两者都不是对所有任务都正确的固定规则。

04 · SFT 的核心设计空间：你究竟用什么数据教模型？

4.1 一条样本不只是 instruction 与 answer

一个更完整的指令样本通常包含：任务指令、可选输入、目标输出、来源与许可、质量标签、任务类别、语言、对话轮次、拒绝 / 安全标记等元数据。元数据不一定都送进模型，但它们决定了数据能否被过滤、分层采样与审计。

4.2 三种常见数据构建路线

人工编写与策展

专家或标注员写出任务与目标回答，适合控制正确性、风格和边界行为；成本高，覆盖面受人力限制。

任务集合与模板化

把分类、问答、摘要等现有任务包装成自然语言指令，覆盖广；模板质量、任务比例和指标偏好会影响模型行为。

教师模型合成

用更强模型生成指令与回答，再过滤无效和相似样本；扩展快，但会继承教师模型的错误、偏见与表达习惯。

2026 年的指令微调综述将数据构建归纳为人工策展、基于蒸馏的合成数据、基于自我改进的合成数据等路线。这个分类很适合作为文章内部的数据地图；它不意味着仓库需要为每种数据生成方式都新建一个一级领域。

4.3 为什么“数据越多越好”不是可靠原则？

看 InstructGPT 论文的 API prompt 分布：生成类任务占 45.6%，开放式问答 12.4%，头脑风暴 11.2%，对话 8.4%。这说明数据混合的比例会影响模型最熟悉的交互模式。若训练集被某一类任务占满，模型可能在该类任务上表现很自然，却对少数任务缺乏稳定行为。

数据混合可以理解为多个任务分布的加权组合：如果第 k 类任务的数据分布是 Pₖ，采样权重为 αₖ，那么训练时实际看到的是它们构成的混合分布。权重不只是一个工程参数，它定义了模型被要求模仿哪些行为、以多大频率模仿。

公式 4 · 多任务数据混合（概念表达）

Pmix=∑k=1KαkPk,∑k=1Kαk=1

αₖ 是采样权重。真实数据管线还要考虑样本长度、重复采样、packing、任务难度与损失归一化方式。

4.4 三个经典研究案例：FLAN、LIMA 与 Self-Instruct

FLAN（Wei et al., ICLR 2022）。研究者把 60 多个 NLP 任务改写成自然语言指令，在 137B 预训练模型上做 instruction tuning，并在未见任务类型上评估。论文报告 FLAN 相比未微调模型在 25 个评测任务中的 20 个超过 zero-shot 175B GPT-3。这个结果说明多任务指令数据可以帮助模型把已有能力迁移到新任务；它不是“只要把任务数量堆上去就必然泛化”的保证。

The Flan Collection（Longpre et al., ICML 2023）。作者通过消融研究分析任务平衡与提示丰富化，报告这些设计对结果有重要影响；将 zero-shot、few-shot 与 chain-of-thought 提示形式混合训练，在相关评估设置中带来约 2% 的提升。关键结论不是单纯追求数据规模，而是仔细设计任务覆盖、采样比例与模板变化。

LIMA（Zhou et al., NeurIPS 2023）。作者用 65B LLaMA 在 1,000 条精心策展的指令—回答样本上做标准监督微调，训练数据约 75 万 Token，其中包含社区问答与人工编写样本。论文提出 Superficial Alignment Hypothesis：强预训练模型已经拥有大量知识与能力，指令微调可能主要帮助模型学会以用户期望的格式表达这些能力。请注意，这是该研究提出并用特定模型与数据验证的假设，不是所有领域模型都只需要 1,000 条数据的普遍定律。

Self-Instruct（Wang et al., ACL 2023）。它让语言模型生成新的 instruction、input 与 output，再过滤无效或相似样本，最后用合成数据微调原始模型。论文在 Super-NaturalInstructions 上报告相对原始 GPT-3 绝对提升 33%。这里最重要的工程问题是：教师模型的错误和偏见也会随合成数据扩散，因此“自动生成”并不等于“自动正确”。

4.5 数据入库前的质量检查

  • 任务覆盖：数据是否覆盖真实用户的任务、语言、难度与输出格式？有没有被某个高频任务垄断？
  • 答案正确：事实、推理、代码和引用是否有独立核验？模型生成的答案不能因为流畅就被视为真值。
  • 指令明确：输入是否存在歧义、缺失条件或互相冲突的约束？
  • 格式一致：同类任务的回答结构是否稳定？需要列表、JSON、代码块或拒绝时，样本是否给出正确示范？
  • 去重与污染：近重复样本、模板泄漏和训练—测试交叉是否得到控制？
  • 安全与隐私：PII、授权、许可证、危险指令和拒绝样本是否经过治理？
  • 长度与轮次：长回答、短回答、多轮对话和结束标记的比例是否符合目标应用？

05 · InstructGPT：SFT 是 RLHF 的起点，而不是全部

理解 SFT 最经典的入口之一是 InstructGPT。Ouyang 等人把流程拆成三个阶段：先用人工示范训练一个监督策略（SFT）；再让标注员比较多个模型回答，训练奖励模型（RM）；最后用 PPO 根据奖励模型更新策略。

这三类数据并不相同：SFT 数据包含人类写出的示范回答；RM 数据包含对同一提示下多个回答的排序；PPO 阶段主要使用提示词让当前策略采样回答，再由奖励模型给出反馈。把它们都叫作“人工标注数据”会掩盖训练信号的差异。

阶段输入与监督信号模型学习什么
SFTPrompt + 标注员示范回答模仿示范回答的 Token 分布，建立可用的初始策略
Reward Model同一 Prompt 的多个回答及人类排序预测哪个回答更受标注员偏好
PPO策略采样回答 + 奖励模型分数 + KL 约束在控制策略偏移的同时，提高代理奖励

论文报告 SFT 数据集约有 13,000 个训练 prompts，来自 API prompt 与标注员编写的 prompts。作者报告 SFT 训练使用 16 个 epoch、cosine learning-rate decay 与 0.2 residual dropout；最终 SFT 模型根据验证集上的奖励模型分数选择。一个很有教学价值的细节是：SFT 模型的验证损失在 1 个 epoch 后就出现过拟合迹象，但继续训练仍提升了奖励模型分数和人类偏好评价。

不要把论文超参数当作通用配方。16 epochs 是 InstructGPT 特定数据、模型、优化与模型选择方案下的报告值。它恰恰提醒我们：训练损失、验证损失与最终行为指标可能并不完全一致。不同模型、数据规模和目标任务必须重新验证。

另一个容易混淆的细节：InstructGPT 在构造后续 RLHF 初始策略时，还报告了另一套配置——在示范数据上训练 2 个 epoch，并混入 10% 预训练数据。这是附录中的 RLHF 初始化配置，不应与前面 SFT 基线的 16 epoch 结果混为一谈。

06 · 工程上怎样构建一条可靠的 SFT 训练管线？

6.1 一条可审计的训练流程

  1. 选择起点模型：记录模型版本、Tokenizer、上下文长度、许可证与原始训练目标。
  2. 构建样本：统一 instruction、optional input、response 与多轮消息格式，记录来源和数据版本。
  3. 应用 Chat Template：使用与模型训练 / 推理接口一致的消息模板，确保角色边界、特殊 Token 与结束标记正确。
  4. 生成 labels 与 masks：明确哪些 Token 是目标、哪些是 padding、哪些是上下文；逐样本检查 shift 后的标签。
  5. 选择参数更新方式：全参数微调、LoRA 或 QLoRA；这影响显存、可训练参数量与部署方式，但不会改变 SFT 的监督定义。
  6. 训练与监控：记录有效目标 Token 数、训练 / 验证 loss、学习率、梯度范数、吞吐、显存、数据混合比例与 checkpoint。
  7. 独立评估：对照 base model 与 SFT model，在未见 prompt、未见任务和目标应用场景中测试行为。

6.2 全参数微调与 LoRA 是不同的工程选择

全参数 SFT 会更新模型中的大量或全部可训练参数；LoRA 则冻结原始权重，在若干线性层旁学习低秩更新。QLoRA 在量化基座上训练 LoRA adapter，以降低显存开销。它们都可以使用同一套监督数据和 masked causal-LM objective。

因此，不要把“我用了 LoRA”当成“我使用了另一种监督目标”。如果数据、标签和损失函数相同，LoRA 改变的是参数更新的自由度与资源成本，而不是 SFT 的基本学习信号。可继续阅读 LoRA 与 QLoRA。

6.3 训练配置没有脱离数据的万能答案

配置项它影响什么应该检查什么
Learning rate参数更新步幅；过大会破坏原能力，过小可能学不到目标行为训练稳定性、验证行为、不同模型规模下的敏感性
Epoch / token budget模型重复看到样本的次数重复样本、过拟合、长尾任务是否被充分学习
Batch / gradient accumulation每次更新的有效 Token 数与梯度噪声按 Token 统计而非只看样本条数；注意长度差异

特别注意 packing：把多条短样本拼成一个长序列可以提高 GPU 利用率，但必须清楚样本边界是否阻断了不应发生的跨样本注意力，以及 loss mask 是否与拼接后的 Token 位置对齐。否则，效率优化可能改变训练语义。

07 · SFT 的能力边界：它会模仿什么，也可能放大什么

SFT 的优化目标是让示范回答在模型分布下更容易出现。它并不直接告诉模型“这个回答比另一个回答更好”，也不自动验证目标回答是否真实。一个流畅但错误的示范，同样可能成为高权重的学习信号。

失败模式为什么发生可能的诊断 / 缓解
错误知识被模仿训练目标把错误答案当成正例事实核验、引用验证、专业领域审核、难例回归集
任务分布偏斜高频任务占据大多数梯度更新按任务分层统计、重采样、任务平衡与长尾评测
模板与风格过拟合数据只呈现单一格式或固定表达模板多样化、反事实格式测试、未见 prompt 评估
合成数据自我放大偏差教师模型输出中的错误、偏好与盲点进入训练集独立验证、来源追踪、抽样人工审阅、差异化教师
遗忘原有能力目标数据分布过窄，更新方向偏离预训练能力保留通用能力评测、混合数据、较小更新或 PEFT
格式或停止行为异常角色边界、EOT/EOS 或 assistant loss mask 配置错误检查 Chat Template、结束标记、shift 后 labels 与生成终止
训练 loss 下降但体验变差模仿似然只是代理指标，不能覆盖偏好、安全与真实任务成功多维评估、人工比较、独立测试集与上线监控

LIMA 的研究还提供了一个重要反例：没有合适的格式示范时，模型可能难以遵循结构化输出约束；论文展示了少量格式相关样本对这类行为的影响。这说明“模型见过大量知识”并不等于“模型会按指定结构表达知识”。

不要把 SFT 的能力夸大为价值对齐：示范数据只能代表被收集、筛选和标注出来的行为分布。对于多目标冲突、偏好分歧、安全边界和奖励权衡，通常还需要更专门的反馈、评测与后训练机制。

08 · 怎样判断一次 SFT 真正有效？

评估应该从训练目标之外再走一步：模型是否真的更好地完成用户任务？如果训练集和测试集共享模板、来源或近重复问题，离线指标就可能高估泛化能力。InstructGPT 通过用户 ID 划分数据，并对训练提示做去重和 PII 过滤，是一个值得注意的数据治理实例。

评估维度示例检查容易忽略的陷阱
指令遵循是否完成任务、遵守数量 / 长度 / 结构约束？只测训练模板，未测同义改写
事实与推理答案是否正确？中间推理是否支持结论？流畅性被误当成正确性
格式与工具接口JSON 是否可解析？代码是否可运行？结束标记是否正确？只做字符串相似度，不检查实际执行
安全与拒绝有害请求是否正确拒绝？正常请求是否过度拒绝？只测拒绝率，不看误拒绝与上下文
分布外泛化新领域、新语言、新格式、组合约束是否仍能完成？训练与测试在任务模板或来源上泄漏
人类偏好盲测比较 base 与 SFT 输出，按任务分层统计评审标准不一致、样本量不足、只报告总体平均

建议至少保留三组结果：原始 base model、SFT checkpoint、以及必要时的后续偏好优化模型。相同 prompt、相同 decoding 配置、相同评估协议，才能让比较更有解释力。

09 · SFT 与其他后训练方法如何组合？

SFT 不是整个后训练体系的终点。它通常提供一个“已经知道如何响应指令”的初始策略，后续方法再引入不同类型的监督信号。

方法训练信号与 SFT 的关系
SFT单条输入对应的示范回答建立初始行为分布
Rejection Sampling采样多个候选，再用规则 / 奖励 / 验证器筛选筛选出的高质量回答可以再次作为 SFT 目标
RLHF偏好排序训练奖励模型，再用 RL 优化策略经典流程通常从 SFT 策略初始化
DPO优选与非优选回答对通常从 SFT 模型出发，直接优化偏好目标，不需要显式在线 RM+PPO 循环
GRPO / RLVR组相对奖励、规则或可验证结果反馈可在 SFT 模型基础上进一步训练推理 / 任务策略
LoRA / QLoRA参数更新方式与显存优化策略可以用来执行 SFT，也可用于其他微调阶段

把这些方法放到一条学习路径中，会更容易理解它们的依赖关系：先理解 GPT-1 的预训练与微调，再理解 Teacher Forcing 和 SFT；随后学习 RLHF、DPO 与 GRPO。如果你关心如何降低 SFT 的显存成本，再阅读 LoRA 和 QLoRA。

最终的心智模型：预训练学习通用文本分布；SFT 用示范回答教模型“在这个输入下应该怎样答”；偏好学习进一步告诉模型“多个可行回答中哪一个更好”；强化学习则可以把奖励或可验证反馈转化为策略更新。它们解决的是相互关联、但并不相同的问题。
